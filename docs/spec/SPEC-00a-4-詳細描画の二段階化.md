# SPEC-00a-4: 試作（詳細描画の二段階化）

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: SPEC-00a-3 の続きで、同じスレッドで表示の中核ロジックを直すため

---

## 目的

SPEC-00a-3 で、A1 を 400% に拡大してから鮮明になるまでの時間は 4.7 秒から 1.3 秒に縮んだ。短い横スクロールも、ほぼ一瞬で鮮明になるようになった。

ただし、詳細領域の余白を広げたため、描く面積が画面の約4倍になり、詳細領域の描画だけで 1.18 秒かかっている。密な図面では、描画時間が面積にも比例して増える。

そこで、**見えている範囲をまず描き、余白は後から描く**二段階の方式にする。拡大直後の速さと、横スクロールへの備えを両立させる。

## 対象

- 変更してよいファイル: `src/viewer/PageView.tsx`、`src/viewer/detailRegion.ts`、`tests/detailRegion.test.ts`、`e2e/perf.spec.ts`
- 上記以外は変更しない。

## 変更内容

1. **第1段（見えている範囲）**
   - 見えている部分を 128 デバイス px 単位に外側へ丸め、ページの外を切り落とした領域を、**優先度 0** で要求する。余白は付けない。
   - `isSharp()` は、この第1段が見えている部分を覆った時点で true とする（今までの定義どおり）。
2. **第2段（余白付き）**
   - 第1段が描かれた後に、今の方式の領域（余白は表示領域の半分、上限 4096×4096）を**優先度 1** で要求する。
   - 届いたら第1段と差し替える。
   - 第2段がまだ処理待ちのうちに見えている部分が変わったら、第2段を release して取り消し、新しい第1段から始め直す。
3. **スクロールしたとき**
   - 見えている部分が、表示中の詳細（第1段か第2段）に収まっていれば、何もしない。
   - はみ出したら、60ms 後に第1段から始め直す。
   - 古い詳細は、新しい第1段が届くまで表示し続ける。
4. **長辺 2048px の下地**（SPEC-00a-3 で入れたもの）は、第2段が描かれた後に優先度 2 で要求する。
5. `detailRegion.ts` に、第1段の領域を求める関数 `computeVisibleRegion(visible, pageDeviceSize, grid=128)` を追加し、単体テストを書く。
6. **ベンチ**（Worker 3本・warm なしのまま）
   - 今の項目に加えて、拡大から第2段が描かれるまでの時間（`zoom-full`）を記録する。
   - 拡大直後の要求ログを、今回も抜粋して示す。
