# SPEC-01a: 第1版 画面の骨組み（タブ、ページ一覧、書式パネル、開始画面）

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: 画面全体の構成、Worker の文書管理（複数の文書）、状態管理を作り替える、複数のファイルにまたがる中核の改修のため

---

## 目的

第1版の最初の段階として、画面の骨組みを作る。作るのは次の4つ。

1. 複数のファイルを**タブ**で同時に開く。
2. 左に**ページ一覧**（縮小表示）を置く。
3. 右に**書式パネル**（色、線の太さ、文字の大きさ）を置く。
4. ファイルを開いていないときは、**開始画面**（開くボタンと、最近使ったファイル）を表示する。

最初に、次を読むこと。
- `docs/要件と設計方針.md`（特に第5章「画面」）
- `docs/第1版の計画.md`（特に「タブと Worker」）
- 今の `src/` 全体

## 画面の構成

```
┌─[ファイルA.pdf ●]─[ファイルB.pdf ×]─[＋]──────────────────────┐ タブ
│ 開く 上書き保存 別名で保存 │ 選択 文字 四角 │ 縮小 拡大 幅に合わせる 123% │ ツールバー
├────────┬───────────────────────────────┬─────────┤
│ ページ一覧 │                                        │ 書式         │
│ [1]       │            PDF 本体                       │ 色 ■■■■      │
│ [2]       │                                        │ 太さ ▼       │
│  …       │                                        │ 文字の大きさ ▼│
├────────┴───────────────────────────────┴─────────┤
│ 3 / 30 ページ　　　　　　　　　　　　　　　　保存しました（増分・0.4秒）    │ 状態バー
└──────────────────────────────────────────────────┘
```

- ページ一覧と書式パネルは、ツールバーの切り替えボタン（「ページ一覧」「書式」）で表示と非表示を切り替えられる。その状態は localStorage に保存する。
- 状態バーには、現在のページ、総ページ数、保存の結果のメッセージを表示する。今ツールバーにある表示は状態バーへ移す。

## 変更内容

### 1. 文書の管理（Worker と通信）

- すべての文書向けメッセージ（`open`、`render`、`listAnnotations`、`layoutText`、`applyAndSave`、`cancelJobs`、`reprioritize`）に `docId: string` を付ける。
  - `layoutText` は文書に依存しないので、docId は不要でよい。
- 新しいメッセージを追加する。
  - `close {docId}`: その文書を閉じ、DisplayList のキャッシュも捨てる。
  - `exportBytes {docId}`（Worker 0 だけ）: 現在の文書（反映済みの書き込みを含む）を増分保存の形でバイト列にして返す。
- **Worker 0** は、開いているすべての文書を持つ。書き込みの反映と保存を受け持つためである。
- **表示用の Worker（1 以降）** は、最大2つの文書（今のタブと、直前のタブ）を持つ（LRU）。
  - `PdfWorkerPool.activate(docId)` で今のタブを切り替える。
  - その文書を持っていない表示用の Worker には、Worker 0 から `exportBytes` で取ったバイト列を渡して開かせる。
  - **main thread に文書のバイト列を持ち続けない**（開いた直後に Worker へ渡したら手放す）。
- ページの担当（`pageIndex % workerCount`）は、今のタブの文書について適用する。
- 同時に開ける文書は 8 つまでとする。9 つ目は「同時に開けるのは8ファイルまでです」と表示して開かない。

### 2. タブ（`src/app/DocumentTabs.tsx`、`src/app/documentModel.ts`）

- 文書ごとに、次の状態を持つ。
  - docId、ファイル名、ファイルハンドル、ページサイズ
  - `AnnotationStore`（文書ごとに1つ）
  - 表示の状態（ページ、倍率、スクロール位置）
  - `fileOutdated`
- 状態は、React の外のクラス（`DocumentSession`）にまとめ、App が一覧を持つ。
- タブの見た目
  - ファイル名を表示する（長い名前は省略し、ツールチップで全部を出す）。
  - 未保存なら「●」、閉じるボタンは「×」。
  - 今のタブを目立たせる。
- タブを切り替えたら、そのタブの前回の表示位置（ページ、倍率、スクロール位置）に戻す。
- 閉じるときに未保存の変更があれば、`confirm` で確認する。
- すでに開いているファイルをもう一度開いた場合は、新しいタブを作らず、そのタブに切り替える。
  - 同じかどうかは、ハンドルがあれば `isSameEntry`、なければ「ファイル名 + バイト数」で判定する。
- 最後のタブを閉じたら、開始画面に戻る。
- キー操作
  - `Ctrl+O`: 開く
  - `Ctrl+W`: タブを閉じる（ブラウザ標準の動作は `preventDefault` で止める）
  - `Ctrl+Tab` と `Ctrl+Shift+Tab`: 次のタブ、前のタブ
- 「開く」でもドラッグ＆ドロップでも、新しいタブで開く。複数のファイルを一度にドロップしたら、それぞれのタブで開く。
- 前回の場所の記憶（SPEC-00c）は、タブごとに働かせる。

### 3. ページ一覧（`src/app/ThumbnailPanel.tsx`）

- 幅 160 CSS px の縦の一覧。各ページの縮小表示（幅 120 CSS px 程度）と、その下にページ番号を並べる。
- 見えている部分だけ DOM を作る（仮想化）。
- 縮小表示の画像は、`RenderScheduler` で本体の低解像度版と**同じ key**（長辺 512px 版）を優先度 2 で `want` し、縮小して描く。これで本体の先読みの下地にもなる。
- クリックしたら、本体をそのページへ移動する。今見ているページを目立たせ、一覧もそこへ追従させる（一覧が手で動かされている間は追従しない）。
- タブを切り替えたら、そのタブの一覧に切り替える。

### 4. 書式パネル（`src/app/FormatPanel.tsx`、`src/editor/formatDefaults.ts`）

- 色: 赤、青、黒、緑、橙、紫、黄、白の8色（ボタンに色見本を付け、ツールチップに色の名前を出す）。
- 線の太さ（四角）: 0.5、1、1.5、2、3、5 pt
- 文字の大きさ（文字）: 8、9、10.5、12、14、18、24、36 pt
- **何かを選んでいるとき**
  - その書き込みの値を表示する。
  - 変更したら、その書き込みに反映する（ストアの `update`。文字の大きさを変えたら、配置を計算し直して高さを直す）。
  - 既存の注釈なら、touch と同じ扱いにする。
- **何も選んでいないとき**
  - 今のツールの初期値を表示する。
  - 変更したら、次に作る書き込みに使う。
- 初期値は localStorage（キー `karu-pdf:format`）に保存する（「最後に使った設定を引き継ぐ」）。読み書きは try/catch で包む。
- 初期値の既定は、今と同じ（赤、1pt、10.5pt）。
- 書体（ゴシック／明朝）の欄は、SPEC-01b で追加するので、今回は作らない。

### 5. 開始画面（`src/app/StartScreen.tsx`）

- タブが1つもないときに表示する。
  - 中央に大きな「PDF を開く」ボタンと、「ここにファイルをドラッグ＆ドロップ」の案内を置く。
- **最近使ったファイル**
  - 最大10件。`recentStore.ts` を拡張し、IndexedDB の `handles` ストアに、キー `recent` で配列（ハンドル、名前、日時）を保存する。
  - 開くたびに先頭へ追加し、同じファイル（`isSameEntry`）は重複させない。
  - 一覧は、ファイル名と開いた日時を表示する。
    - クリックすると `requestPermission({mode: 'read'})` を求めてから開く。
    - 許可されなかったり、ファイルが無かったりしたら、理由を表示し、一覧から消すかを確認する。
  - 各行に「一覧から消す」ボタン（×）を置く。
  - **ファイルの中身は保存しない**（SPEC-00c と同じ）。
- 開始画面は、ページ下部に「使い方」の短い説明（主な操作5つ）も表示する。

### 6. ツールのショートカット

入力欄を開いていないときだけ、次のキーでツールを切り替える。
- `V`: 選択
- `T`: 文字
- `R`: 四角
- `Esc`: 選択を外す

### 7. テスト用の窓口

`window.__karu` は、今のタブを対象に動くようにする。次を追加する。
- `openBytes(bytes, name)`: 新しいタブで開く。
- `listTabs()`: タブの一覧（docId、名前、`dirty`）を返す。
- `activateTab(docId)`: タブを切り替える。
- `closeTab(docId)`: タブを閉じる（確認なしで閉じる）。

## 禁止事項

- `src/core/` の変更は、docId を扱うための最小限にとどめること（注釈の外観や保存の処理は変えない）。
- git の操作をしないこと。
- ファイルの中身を、IndexedDB と localStorage に保存しないこと。
- 試作の性能（開く、スクロール、拡大、書き込みの反応）を悪化させないこと（検証項目で確かめる）。
- 自分で起動したサーバーは必ず止めること。一時ファイルは削除すること。

## テスト

- 単体テスト
  - `DocumentSession` とタブの一覧: 追加、切り替え、閉じる、8つの上限、同じファイルを開いたときの判定
  - `formatDefaults`: 保存、読み出し、例外への耐性
  - 最近使ったファイルの一覧: 先頭への追加、重複の除去、10件の上限、削除
- 画面のテスト（e2e）
  1. `sample-small.pdf` と、別の試験用 PDF（テストの中で2ページの PDF を作ってよい）を開き、タブが2つになる。
     - それぞれに書き込みをし、`saveToBytes()` で保存して開き直す。
     - 書き込みが、それぞれの文書にだけ入っていることを確かめる。
  2. ページ一覧で3ページ目をクリックし、本体が3ページ目へ移動する。
  3. 四角を選び、書式パネルで青・3pt にする。保存して開き直し、色と太さが反映されていることを確かめる。
  4. 何も選ばずに文字の大きさを 14pt にして文字を作り、14pt であることを確かめる。
  5. タブを全部閉じると開始画面が出る。
  6. 同じファイルをもう一度開くと、新しいタブにならない。
- 既存のテスト（`npm test`、`npm run e2e`）がすべて通ること。
