# SPEC-01c: 第1版 ページ整理（並べ替え・回転・削除・白紙・結合・抽出・分割）

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: 文書の構造を変える処理（Worker 0）と、新しい画面（ページ整理）、表示用 Worker の読み込み直しにまたがる新機能で、判断の余地がある難所を含むため

---

## 目的

全ページを一覧で並べる「ページ整理」画面を作り、書類をまとめる作業に必要なページの操作を一通りできるようにする。

- 並べ替え、回転、削除、白紙の挿入
- 他の PDF のページを加える（結合）
- 選んだページを別のファイルにする（抽出）
- 1つのファイルを複数に分ける（分割）

最初に次を読むこと。
- `docs/要件と設計方針.md`（第3章、第5章）
- `docs/第1版の計画.md`（「ページ整理」）
- SPEC-01a、01a-2、01b
- 今の `src/` 全体

## 画面

```
┌─ ページ整理（ファイルA.pdf） ────────────────────────────────┐
│ 左に回転 右に回転 削除 白紙を挿入 他のPDFを追加 抽出 分割 │ 元に戻す やり直し │ 適用 やめる │
├──────────────────────────────────────────────┤
│ [1]  [2]  [3↻] [4]  [白紙] [B-1] [B-2] …                       │
│  ページのカードを格子状に並べる。ドラッグで並べ替える             │
└──────────────────────────────────────────────┘
```

- ツールバーの「ページ整理」ボタンで、今のタブの本体の表示を、ページ整理の画面に切り替える。
- 「適用」を押すまでは、元の文書を変えない（**下書き**として操作する）。
- 「やめる」と `Esc` で、下書きを捨てて本体の表示に戻る。下書きに変更があれば、`confirm` で確認する。

## 変更内容

### 1. 下書き（`src/organize/OrganizeDraft.ts`、React に依存しないクラス）

```ts
type CardSource =
  | { kind: 'page'; docId: string; pageIndex: number }      // 今の文書、または加えた PDF のページ
  | { kind: 'blank'; width: number; height: number }        // 白紙（pt）
interface PageCard { id: string; source: CardSource; rotation: 0 | 90 | 180 | 270 }  // rotation は元の /Rotate に足す角度
```

- 操作: 並べ替え（複数のカードをまとめて移す）、回転（±90°）、削除、白紙の挿入、他の PDF のカードの挿入
- 下書きの中での、元に戻す／やり直し（`Ctrl+Z`／`Ctrl+Y`）。100 手まで。
- `isChanged()`: 元の並び（全ページ、回転 0）と違うか。

### 2. 画面（`src/organize/OrganizeView.tsx`）

- 幅 160 CSS px 程度のカードを格子状に並べる。見えている行だけ DOM を作る（仮想化）。
  - 縮小表示は、SPEC-01a のページ一覧と同じ key と優先度の決まり（描画済みならすぐ使う。まだなら止まってから優先度 3 で頼む）を使う。
  - 回転は、カードの画像を CSS で回して表示する。
- **選択**
  - クリック: 1つ選ぶ
  - `Ctrl`＋クリック: 選択に加える／外す
  - `Shift`＋クリック: 範囲で選ぶ
  - `Ctrl+A`: すべて選ぶ
- **ドラッグで並べ替え**: 選んでいるカードをまとめて動かす。落とす位置を縦線で示す。
- **キー**: `Delete`（削除）、`Ctrl+Z`／`Ctrl+Y`、`Esc`（やめる）
- **白紙を挿入**
  - 選んだカードの後ろ（選んでいなければ末尾）に入れる。
  - 大きさは、直前のページと同じにする（無ければ A4 縦）。
- **他の PDF を追加**
  - ボタン（`showOpenFilePicker`、複数選択可）か、格子へのドラッグ＆ドロップで加える。
  - ボタンなら、選んだカードの後ろ（無ければ末尾）に入れる。ドロップなら、落とした位置に入れる。
  - 加えた PDF は、タブにはせず「材料の文書」として Worker で開く（docId は `src-…`）。ページ整理を終えたら閉じる。
  - カードには、元のファイル名の略称（例: `B-1`）を表示する。

### 3. 適用（Worker 0 の新しいメッセージ `applyPageLayout {docId, cards, sources}`）

処理の順番:
1. **未反映の書き込みを先に反映する。** 今の `AnnotationStore.toEdits()` を、文書に反映だけして保存はしない。そのために、Worker 0 に `applyEdits {docId, edits}` を追加する（`applyAndSave` から保存の部分を除いたもの）。反映した後は `markApplied` を呼ぶ。
2. **元に戻すための控えを取る。** 今の文書のバイト列（増分保存の形）を、**Worker 0 の中に** 1つだけ保持する（main thread には持たない）。
3. **ページを組み立てる。** 文書を作り直さず、元の文書をその場で変える。こうすると、しおりやフォームなど文書全体の構造が残りやすい。
   1. 加えた PDF のページを `graftPage` で末尾に足す。白紙は `addPage` と `insertPage` で末尾に足す。
   2. 最終的な並びを、ページ番号の配列として `rearrangePages(order)` に渡す（並びに無いページは削除される）。
   3. 各ページの `/Rotate` に、カードの回転を足す（360 の剰余）。
   4. `rearrangePages` が、しおり（アウトライン）とリンクをどう扱うかを、テストで確かめて報告する。
4. **表示用の Worker を読み込み直す。** 結果の文書を `exportBytes` して、表示用の Worker で開き直す。
5. **画面を更新する。**
   - main thread 側で、ページサイズを取り直す。
   - `AnnotationStore` を作り直す（注釈を読み直す）。
   - 本体の表示に戻り、ページ一覧を更新する。
   - タブを「ファイルが最新でない（●）」にする。
- 適用中は、操作を止めて「ページを組み立てています…」と表示する。
- 失敗したら、控えから元に戻し、理由を表示する。
- **直前のページ整理を元に戻す**: 本体の表示のツールバーに「ページ整理を元に戻す」を置く（控えがあるときだけ押せる）。Worker 0 は控えから文書を開き直し、表示用の Worker も読み込み直す。

### 4. 抽出と分割（元の文書は変えない）

- **抽出**
  - 選んだカードを、下書きの並びと回転のまま、新しい PDF にする。
  - Worker 0 で `new PDFDocument()` に `graftPage` し、`saveToBuffer`（全体を書き出す）でバイト列にする。
  - `showSaveFilePicker` で保存先を選ぶ。既定の名前は `<元の名前>_抜粋.pdf`。
- **分割**
  - 選び方は2つ。
    - 「選んだカードの前で区切る」
    - 「N ページごと」（N を入力する）
  - `showDirectoryPicker` でフォルダを選び、`<元の名前>_1.pdf`、`<元の名前>_2.pdf`… として書き出す。同名のファイルがあれば、上書きせずに `(2)` を付ける。
  - `showDirectoryPicker` が使えない場合は、順にダウンロードする。
- 抽出も分割も、下書きの書き込み（未反映）を含めるため、1の手順と同じく先に `applyEdits` をしてから行う。

### 5. テスト用の窓口

`window.__karu` に次を追加する。
- `openOrganize()`
- `organizeDraft()`: 下書きの操作 API をそのまま返す。
- `applyOrganize()`
- `undoLastOrganize()`
- `getPageInfo()`: 各ページの幅、高さ、/Rotate、先頭 30 文字のテキスト
- `extractToBytes(cardIds)`
- `splitToBytes(mode)`: バイト列の配列を返す。ファイルには書かない。

## テスト

- **Node の結合テスト**（`tests/pageLayout.integration.test.ts`。`src/core/pageOps.ts` に処理を置いて、Worker から呼ぶ）
  - 試験用 PDF（各ページに「Page N」の文字）で、次を行い、ページの順番（文字）、回転、ページ数を確かめる。
    - 並べ替え、削除、回転、白紙の挿入、他の PDF からの追加
  - 注釈のあるページを動かしても、注釈がそのページに付いたまま残ること。
  - しおりのある PDF（試験用に生成してよい）で、削除と並べ替えをした後のしおりの状態を確かめ、仕様として記録する。
  - 抽出と分割の結果（ページ数、順番、回転）
  - 控えから元に戻したら、元のページの並びに戻ること
- **単体テスト**: `OrganizeDraft` の操作、履歴、`isChanged`
- **画面のテスト（e2e）**
  1. `sample-small.pdf` でページ整理を開く。
  2. 3ページ目を先頭へドラッグし、2ページ目を右に回転し、4ページ目を削除し、白紙を末尾に挿入する。
  3. 適用して、`getPageInfo()` で結果を確かめる。
  4. 保存して開き直しても同じであることを確かめる。
  5. 「ページ整理を元に戻す」で元に戻ることを確かめる。
  - 別の試験用 PDF を追加して適用し、ページ数が増えることを確かめる。
  - 抽出と分割を `extractToBytes` と `splitToBytes` で確かめる。
- **性能**: `heavy-300p.pdf`（300 ページ）で、10 ページを並べ替えて適用するまでの時間を計測する（目標: 開発機で 5 秒以内）。計測は `e2e/perf-organize.spec.ts`（project: bench）に置き、1回だけ実行する。

## 禁止事項

- `src/core/annotations.ts`、`textLayout.ts`、`save.ts` の既存の動作を変えないこと（ページ操作は新しい `pageOps.ts` に置く）。
- main thread に、文書のバイト列を持ち続けないこと（控えは Worker 0 に置く）。
- 分割で、既存のファイルを上書きしないこと。
- git の操作をしないこと。自分で起動したサーバーは必ず止め、一時ファイルは削除すること。
