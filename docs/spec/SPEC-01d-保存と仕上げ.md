# SPEC-01d: 第1版 保存と仕上げ（確定保存・印刷・保存量の対策・オフライン・使い方）

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: 保存の処理、Service Worker（PWA）、ビルド設定にまたがる新機能で、配布物に関わる変更を含むため

---

## 目的

第1版の仕上げとして、次の機能を作る。

1. 提出用の「確定して別名で保存」（書き込みをページに焼き付ける）
2. 印刷
3. 保存を繰り返しても、ファイルが大きくなり続けないようにする
4. オフラインでも動く（PWA）。新しい版を公開したら知らせる
5. インストールした場合に、エクスプローラーの「プログラムから開く」から PDF を開けるようにする
6. 使い方の画面

最初に次を読むこと。
- `docs/要件と設計方針.md`（第2章、第4章、第5章）
- `docs/第1版の計画.md`
- SPEC-00b-1、01a、01b、01c
- 今の `src/` 全体と `vite.config.ts`

## 対象

- 変更してよいファイル: `src/`、`tests/`、`e2e/`、`vite.config.ts`、`index.html`、`package.json`（`vite-plugin-pwa` の追加だけ）、`public/`（アイコンの追加だけ。`public/fonts/` は変更しない）、`scripts/`（アイコン生成スクリプトの追加だけ）
- 変更しないファイル: `docs/`、`LICENSE`、`.github/`、`public/fonts/`

## 変更内容

### 1. 確定して別名で保存

- 「ファイル」のメニュー（または別名で保存の隣のボタン）に「確定して別名で保存」を置く。
- 処理:
  1. 未反映の書き込みを `applyEdits` で反映する。
  2. Worker 0 で、今の文書のバイト列から**別の文書として**開き直す。
  3. `bake(true, false)` で注釈をページに焼き付ける。フォームの入力欄（widget）は焼き付けない。
  4. 全体を書き出す形（不要なオブジェクトの除去つき）で保存する。
- 保存先は `showSaveFilePicker`（既定の名前は `<元の名前>_確定.pdf`）で選ぶ。
- **今開いている文書は変えない**（書き込みは引き続き編集できる）。
- 保存が終わったら、「確定版を保存しました。確定版の書き込みは編集できません。」と表示する。
- テスト: 焼き付けた PDF に注釈が無いこと。焼き付けた書き込みがページ内容として描かれること（文字は `toStructuredText` で取れること）。

### 2. 印刷

- ツールバーに「印刷」を置く（`Ctrl+P` も同じ動作にし、ブラウザ標準の印刷は止める）。
- 処理:
  1. 未反映の書き込みを反映する。
  2. 今の文書のバイト列を Blob URL にする。
  3. 新しいタブで開き、Edge・Chrome 標準の PDF 表示から印刷してもらう。
  4. 「新しいタブの印刷ボタンから印刷してください」と表示する。
- Blob URL は、1分後に `revokeObjectURL` する。
- 作った注釈には、印刷のフラグ（`/F 4`）を付ける。Line、Circle、Ink、Square も確かめ、無ければ付ける（`src/core/annotations.ts` の最小限の変更は可）。

### 3. 保存を繰り返しても大きくなり続けないようにする

- 文書ごとに「開いてからの増分保存の回数」と「増えたバイト数」を数える。
- 回数が 5 回を超えたか、増えた量が 2MB を超えたら、次の保存を全体の書き出し（不要なオブジェクトの除去つき）にする。数えた値はそこで 0 に戻す。
- 全体の書き出しにしたときは、「ファイルを整理して保存しました（全体保存・n秒）」と表示する。
- テスト: 同じ文字の書き込みを10回書き換えて保存したとき、最終的なファイルの大きさが、1回だけ保存した場合の 1.5 倍以内に収まること。

### 4. オフライン対応と新しい版の通知（PWA）

- `vite-plugin-pwa` を使う。
  - `registerType: 'prompt'`
  - すべてのビルド成果物（JS、CSS、WASM、フォント）を事前にキャッシュする。WASM とフォントは大きいので、`maximumFileSizeToCacheInBytes` を適切に設定する。
- manifest:
  - `name`: かるPDF
  - `short_name`: かるPDF
  - `lang`: ja
  - `start_url` と `scope`: `/karu-pdf/`
  - `display`: `standalone`
  - `theme_color`
  - アイコン: 192px と 512px
- アイコンは、`scripts/make-icons.mjs` で MuPDF を使って作る。BIZ UDゴシックで「かる」の文字を描いた、単純なもの。`public/icons/` に置く。
- 新しい版が待機状態になったら、画面の上部に「新しい版があります。［更新する］」の帯を出す。押したら更新して再読み込みする。
  - 未保存の変更があれば、`confirm` で確認してから更新する。
- テスト: ビルドした成果物に manifest と Service Worker があること。Playwright で一度開いた後、オフラインにして再読み込みしても、開始画面が出ること。

### 5. 「プログラムから開く」への対応（File Handling API）

- manifest に `file_handlers` を加える（`action: '/karu-pdf/'`、`accept: {'application/pdf': ['.pdf']}`）。
- `launchQueue.setConsumer` で渡されたファイルハンドルを、それぞれタブで開く。
- 対応していないブラウザや、インストールしていない場合は何もしない（エラーにしない）。
- 使い方の画面に、インストールの方法と、「プログラムから開く」で かるPDF を選べることを書く。

### 6. 使い方の画面

- ツールバーと開始画面に「使い方」ボタンを置き、ダイアログで表示する。
- 内容（日本語）:
  - 開く・保存・確定保存・印刷
  - 各ツールとキー
  - ページ整理
  - 元に戻す
  - 保存についての注意（上書き保存の許可、確定保存は編集できないこと）
  - アプリとしてインストールする方法
  - 対応ブラウザ
  - 「PDF はパソコンの外へ送らない」こと
- `Esc` で閉じる。

## 禁止事項

- 今開いている文書を、確定保存と印刷で変えないこと。
- 外部のサイトから何も読み込まないこと（Service Worker も、同じオリジンのファイルだけをキャッシュする）。
- git の操作をしないこと。自分で起動したサーバーは必ず止め、一時ファイルは削除すること。
