# SPEC-01f-1: 記号の入力と、画面が消えないための安全装置

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: 注釈の中核（自前の外観、代替フォントの埋め込み）と画面の操作にまたがる新機能と、アプリ全体の例外処理の追加のため

---

## 目的

利用者の要望と不具合の報告に応える。

1. **チェックマークなどの記号を入力したい。**
2. **ページ整理の画面をスクロールすると、アプリ全体が真っ白になった**（コミット 56a19bc で原因は修正済み）。
   - 原因は、`onScroll` の中で、setState の更新関数から `event.currentTarget` を読んでいたことだった。
   - 描画中の例外がアプリ全体を外し、Worker まで破棄していた。保存していない書き込みが失われる恐れがある。
   - 同じ種類の事故が起きても**画面全体が消えず、書き込みが失われない**ようにする。

最初に次を読むこと。
- SPEC-00b-1（FreeText の外観）、SPEC-01b、SPEC-01e
- 今の `src/core/annotations.ts`、`src/core/fontMetrics.ts`、`src/editor/`、`src/app/`、`src/App.tsx`

## 調査で分かったこと（Claude Code）

BIZ UDゴシックと BIZ UD明朝には、次の記号が**ある**。

```
✓ ○ ◎ ● × △ ▲ ▽ ▼ □ ■ ◇ ◆ ☆ ★ ※ → ← ↑ ↓ ⇒ ⇔ 〒 ①〜⑩ ㊤㊥㊦ ♪ ♂ ♀ ℃ ° ± ÷ ≠ ≦ ≧ ∞ ∴ ∵ Ⅰ
```

次の記号は**ない**。

```
✔ ✗ ✘ ☑ ☐ ✕
```

MuPDF 内蔵の `new mupdf.Font('ZapfDingbats')` には、`✓` と `✔` がある（`encodeCharacter` が 0 でない）。

## 対象

- 変更してよいファイル: `src/core/annotations.ts`、`src/core/fontMetrics.ts`、`src/worker/`、`src/client/PdfWorkerPool.ts`、`src/editor/`、`src/app/`、`src/App.tsx`、`src/main.tsx`、`src/styles.css`、`tests/`、`e2e/`、`scripts/make-test-pdf.mjs`（試験用 PDF の追加だけ）
- 変更しないファイル: `docs/`（この SPEC を除く）、`public/`、`LICENSE`、設定ファイル、`src/core/textLayout.ts`

## 変更内容

### 1. 記号の道具（キー `S`）

- ツールバーに「記号」を加える。書式パネルに、次の12種類の記号の見本を並べて選べるようにする。
  - ✓（チェック）、✔（太いチェック）、○、◎、●、×、△、▲、□、■、☆、★
- 使い方:
  - ページをクリックすると、その位置を中心に、選んだ記号を置く（既定の大きさ 16pt 四方、色は書式パネルの色。既定は赤）。
  - ドラッグした場合は、その四角に収まる大きさで置く（縦横の比率は保つ）。
  - 置いた後は、ほかの道具と同じく「選択」に戻り、置いた記号を選んだ状態にする。
  - 同じ記号を続けて置きたいときのために、**`Shift` を押しながらクリックした場合は、記号の道具のままにする**。
- 選んでいるとき:
  - 四隅の取っ手で大きさを変える（比率は保つ）。
  - 移動、色の変更、記号の種類の変更ができる。
- **PDF での表し方**: Stamp 注釈とし、外観は**フォントを使わずに線と塗りの図形で描く**（どのソフトでも同じ見た目にするため）。
  - 外観は、`DisplayList` に `Path` で描き、`setAppearanceFromDisplayList` で設定する。
  - 再編集のために `/KaruSymbol /check`（`check`、`heavyCheck`、`circle`、`doubleCircle`、`filledCircle`、`cross`、`triangle`、`filledTriangle`、`square`、`filledSquare`、`star`、`filledStar`）と、色を記録する。
  - `/F 4`（印刷）を付ける。作成者は入れない。
- `AnnotationInfo` と `AnnotationEdit` に `symbol` の種類を加える。
- 他のソフトの Stamp は、今までどおり下地として描き、編集の対象にしない（`/KaruSymbol` があるものだけを編集できるようにする）。

### 2. 文字の中の記号

- 文字または吹き出しの入力欄を開いている間は、書式パネルに「記号を挿入」の見本を並べる。押すと、カーソルの位置に挿入する。
  - 並べる記号: ✓ ✔ ○ ◎ × △ □ ☆ ★ ※ → ← ↑ ↓ ⇒ ① ② ③ 〒 ℃ ±
- **フォントに無い文字の扱い**（外観を作るとき）
  - BIZ UD に無い文字は、MuPDF 内蔵の `ZapfDingbats` で描く。
  - `ZapfDingbats` の字も、一時文書でのサブセット化の対象に含め、埋め込む。
  - 配置の計算（advance）も、その文字だけ代替フォントの値を使う。
  - どちらにも無い文字だけを、今までどおり `〓` にする。その場合は、画面の下に「使えない文字がありました（〓で表示）: …」と表示する。
- 重ね表示と入力欄では、ブラウザのフォントの代替に任せてよい（保存した外観と、字の形が少し違ってもよい）。

### 3. 安全装置（画面全体が消えないようにする）

- **React のエラーバウンダリ**を、次の2か所に置く。
  - 文書ごとの作業領域（本体、ページ一覧、書式パネル、ページ整理の画面）
  - アプリ全体
- 作業領域の中で描画中に例外が起きたら、その領域だけを次の表示に置き換える。
  - 「表示中に問題が起きました。書き込みは消えていません。」
  - ［表示し直す］ボタン: その領域だけを作り直す。
  - ［保存する］ボタン: 別名で保存する。
- `DocumentSession`、`AnnotationStore`、`PdfWorkerPool` は React の外にあるので、作業領域を作り直しても残るようにする。**エラーで Worker pool を破棄しない。**
- `window` の `error` と `unhandledrejection` を拾い、画面の下に短いメッセージを出す。例外の内容はコンソールにも出す。
- 同じ種類の誤り（setState の更新関数の中で、`event.currentTarget` などイベントの値を読む）が他に無いかを、`src/` 全体で確かめる。見つけたら直して、報告する。

## テスト

- **Node の結合テスト**
  - 12 種類の記号を置いて保存し、開き直して、種類・位置・大きさ・色が戻ること。
  - PDFium で描いて、記号が見えること。
  - 「確認✔済み✗」という文字を保存し、外観に BIZ UD と ZapfDingbats の両方のサブセットがあり、`〓` に置き換わっていないこと。
- **単体テスト**: 記号の外接枠と、比率を保った大きさの変更、代替フォントを使う文字の判定。
- **画面のテスト（e2e）**
  1. 記号の道具で ✓ を置く → 保存して開き直す → ✓ があることを確かめる。
  2. `Shift` を押しながら2回クリックして、記号が2つ置けることを確かめる。
  3. 文字の入力中に「記号を挿入」の ✔ を押す → 本文に ✔ が入ることを確かめる。
  4. **ページ整理の画面のスクロール**: 60 ページの試験用 PDF（`scripts/make-test-pdf.mjs` に追加してよい）でページ整理を開き、最後までスクロールしても、画面（ツールバー）が残ることを確かめる。
  5. **エラーバウンダリ**: テスト用の窓口（`?test=1` のときだけ）に、作業領域の中で故意に例外を起こす仕組みを用意する。例外を起こした後も、ツールバーとタブが残ること、［表示し直す］で元に戻ること、書き込みが残っていることを確かめる。

## 禁止事項

- 対象外のファイルを変更しないこと。git の変更操作をしないこと。
- FreeText の外観を MuPDF の `update()` 任せにしないこと。
- ドラッグ中に React の state を更新しないこと。
- 自分で起動したサーバーは必ず止め、一時ファイルは削除すること。
