# SPEC-01f-3: 「他のPDFから挿入」のダイアログをすぐ開く

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: SPEC-01f-2 の続きで、同じスレッドで材料の文書の開き方（Worker の使い方）を直すため

---

## 目的

SPEC-01f-2 の確認で、次の問題が見つかった。

- 実施設計図（30 ページの重い図面）を開いた状態でページ整理を開き、2つの PDF（3 ページと 174 ページ）を選んだ。
- すると、**ダイアログが出るまでに 7.5 秒**かかった。

原因は、ページ数を知るために、材料の文書をすべての Worker で開き、その完了を待っていることだと考えられる。表示用の Worker が重いページの縮小表示を描いている間は、開く処理がその後ろで待たされる。

利用者は「動きが重くなるなら不要」と言っている。**ファイルを選んだら、すぐにダイアログを出す**ようにする。

## 対象

- 変更してよいファイル: `src/organize/`、`src/client/PdfWorkerPool.ts`、`src/worker/`、`src/App.tsx`、`src/app/`、`tests/`、`e2e/`
- 変更しないファイル: `docs/`（この SPEC を除く）、`src/core/`、`public/`、`LICENSE`、設定ファイル

## 変更内容

1. **ダイアログはすぐ出す**
   - ファイルを選んだら（ボタンでもドロップでも）、ファイル名の一覧でダイアログをすぐ表示する。
   - ページ数の欄は「確認中…」とし、分かったものから順に表示する。
   - すべてのページ数が分かるまで、［挿入］は押せないようにする。範囲の入力は先にできてよい。
   - 開けなかったファイル（壊れている、PDF でない、パスワード付き）は、その行に理由を赤字で出し、挿入の対象から外す。
2. **ページ数は Worker 0 だけで調べる**
   - 材料の文書は、まず Worker 0 だけで開き、ページ数とページサイズを返す。
   - 表示用の Worker で開くのは、下書きにカードを入れた後（縮小表示が必要になったとき）に、裏で行う。
3. **開く処理を描画より先にする**
   - Worker 0 で、`open` のメッセージを、描画の待ち行列より先に処理する（今の `applyEdits` などと同じ扱い）。
   - 実行中の描画1件が終わるのは待ってよい。
4. **計測**（e2e）
   - 実施設計図（`test-data/real/七ヶ浜町_実施設計図.pdf` がある場合。無ければ `heavy-300p.pdf`）でページ整理を開き、縮小表示の描画が走っている最中に、2つのファイルを選ぶ。
   - ダイアログが表示されるまでの時間と、全ページ数がそろうまでの時間を測る。
   - 目標: ダイアログの表示は **300ms 以内**、ページ数がそろうまでは **2 秒以内**。

## 禁止事項

- 対象外のファイルを変更しないこと。git の変更操作をしないこと。
- 自分で起動したサーバーは必ず止め、一時ファイルは削除すること。
