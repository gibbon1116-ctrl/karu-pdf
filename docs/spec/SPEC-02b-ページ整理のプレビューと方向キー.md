# SPEC-02b: ページ整理のプレビューと方向キー

- reasoning effort: `high`

- 「ページ整理の画面で PDF の1枚を選んだとき、サブウィンドウなどでその内容が表示されるようにしたい」

## 変更内容

### 1. プレビュー欄

- ページ整理の画面の右側に「プレビュー」欄を置く。
  - 幅は既定 360 CSS px。境目をドラッグして 240〜640px に変えられる。
  - 幅と表示の有無は localStorage に保存する。
- ツールバーに「プレビュー」の表示の切り替え（チェック付き）を置く。
- **表示する内容**
  - 今フォーカスのあるカード（最後にクリックしたか、方向キーで移ったカード）の中身を、欄の幅いっぱいに描く。
  - 下地の回転に、下書きの回転を足した向きで表示する。
  - 下に、次の情報を表示する。
    - 下書きでの位置（例: 12 / 40）
    - 元（「元の文書 8ページ」／「B.pdf 3ページ」／「白紙」）
    - 大きさ（例: A3 横、420×297 mm。規格に近ければ規格名）
- **描画**
  - `RenderScheduler` に、欄の幅 × devicePixelRatio に合うスケールで、優先度 0 の `want` を出す。
  - 描けるまでは、縮小表示の画像を引き伸ばして出しておく。
  - フォーカスが速く動く（方向キーを押し続ける）間は、前の要求を release して、最後のページだけを描く。100ms 止まってから要求する。
- 白紙のカードは、白い紙と大きさだけを表示する。

### 2. 拡大プレビュー

- カードをダブルクリックするか、`Space` を押すと、画面いっぱいの拡大プレビューを開く（半透明の黒い背景の上に表示する）。
- 拡大プレビューの中の操作:
  - `←` と `→`: 前後のページ
  - `Esc`、`Space`、背景のクリック: 閉じる
  - `Ctrl`＋マウスホイール、または［＋］［−］: 拡大・縮小（100〜400%）。拡大したら、ドラッグで移動できる。
- 描画は、窓の大きさに合わせたスケールで行う。拡大したときは、今の本体と同じ詳細描画は使わず、そのスケールで描き直すだけでよい（400% までに限るため）。

### 3. 方向キーでの選択

- ページ整理の格子にフォーカスがあるとき:

| キー | 動き |
|---|---|
| `←` `→` | 前後のカードへ |
| `↑` `↓` | 上下の段の同じ列へ（列の数は今の格子の幅から求める） |
| `Home` `End` | 最初と最後のカードへ |
| `PageUp` `PageDown` | 1画面分、上下へ |
| `Shift`＋上の移動キー | 起点から、選択の範囲を広げる |
| `Ctrl`＋上の移動キー | 選択を変えずに、フォーカスだけを動かす |
| `Ctrl+Space` | フォーカスのカードの選択を切り替える |

- フォーカスのあるカードは、選択とは別の枠（太い青の枠）で示す。
- フォーカスのカードが画面の外に出たら、格子をスクロールして見えるようにする。
- クリックで選んだカードに、フォーカスも移す。
- 下書きの操作（削除・並べ替えなど）の後は、フォーカスを近くの残ったカードに移す。

### 4. SPEC-02a の小さな修正

- 分割ボタン（文字▼、図形▼、ペン▼）の本体と ▼ に、ツールチップでまとまりの名前を出す。
  - 例: 本体「線（図形: 線・矢印・四角・丸）」、▼「図形の道具を選ぶ」
- 元に戻す／やり直しのボタンの記号が、細い弧に見えて分かりにくい。「↶ 戻す」「↷ やり直し」のように、記号と短い文字を並べて表示する。

## テスト

- **単体テスト**: 方向キーの移動（列数から上下の位置を求める、端での止まり方、Shift の範囲、Ctrl でフォーカスだけ）、用紙の規格名の判定（A4・A3・B4 など、縦横、1mm の誤差を許す）。
- **画面のテスト（e2e）**
  1. ページ整理で3ページ目をクリック → プレビュー欄に「3 / 5」と表示され、画像が描かれる（canvas の画素が一様でない）。
  2. `→` を2回押す → 5ページ目がフォーカスになり、プレビューも5ページ目になる。
  3. `Shift+←` を2回押す → 3〜5ページ目が選ばれる。
  4. `Space` で拡大プレビューが開き、`→` で次のページ、`Esc` で閉じる。
  5. 方向キーを押し続けたとき（`→` を 20 回、20ms 間隔）、最後のページのプレビューだけが描かれる（要求のログで確かめる）。
- 既存のテストが、すべて通ること。
