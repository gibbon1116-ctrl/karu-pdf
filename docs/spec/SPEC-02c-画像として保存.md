# SPEC-02c: 画像として保存（文字を選択できない PDF）

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: 複数の Worker を使う重い書き出し処理と、進み具合・中止の画面を加える新機能のため

---

## 目的

利用者から「PDF を、文字を選択できない画像データとして保存できるようにしたい」という要望が出た。

各ページを画像にして、新しい PDF として保存する。書き込み（注釈）も画像に含める（焼き付ける）。今開いている文書は変えない。

最初に次を読むこと。
- `docs/追加機能の計画.md`
- SPEC-01d（確定保存・印刷の書き出しの流れ）、SPEC-01f-3（Worker 0 と描画用 Worker の役割）
- 今の `src/core/output.ts`、`src/core/render.ts`、`src/worker/`、`src/client/PdfWorkerPool.ts`、`src/app/MenuBar.tsx`、`src/App.tsx`

## 対象

- 変更してよいファイル: `src/core/output.ts`（または新規 `src/core/rasterize.ts`）、`src/worker/`、`src/client/PdfWorkerPool.ts`、`src/app/`、`src/App.tsx`、`src/styles.css`、`tests/`、`e2e/`
- 変更しないファイル: `docs/`（この SPEC を除く）、`public/`、`LICENSE`、設定ファイル、`src/core/annotations.ts`、`textLayout.ts`、`src/viewer/`、`src/editor/`、`src/organize/`

## 変更内容

### 1. メニュー

- 「ファイル▼」の「確定して別名で保存」の下に、「画像として保存…」を加える。

### 2. ダイアログ

- 説明: 「ページを画像にして保存します。文字の選択・コピー・検索ができなくなります。書き込みも画像に含まれます。今開いているファイルは変わりません。」
- 項目:
  - **解像度**: 150 dpi（小さい）／**200 dpi（標準、既定）**／300 dpi（細かい）
  - **色**: カラー（既定）／グレー
  - **画質**: 標準（JPEG、品質 85、既定）／劣化なし（PNG。図面の細い線がくっきりする代わりに、ファイルが大きくなる）
  - **範囲**: すべて（既定）／ページ番号を指定（「1-3,5」の形。SPEC-01f-2 のページ番号の読み取りを使う）
- 見込みの大きさ（例: 「約 45MB」）を、最初の2ページを試しに書き出した大きさから推定して表示する（推定の間は「計算中…」）。
- ［保存］で保存先を選び（`showSaveFilePicker`、既定の名前は `<元の名前>_画像.pdf`）、書き出しを始める。

### 3. 書き出しの処理

1. 未反映の書き込みを、Worker 0 で `applyEdits` する（今の確定保存と同じ）。
2. 各ページを、**描画用の Worker で並べて**描く。
   - 解像度は、ページの大きさ（pt）× dpi / 72。注釈とフォームの入力欄も描く（showExtras）。回転はそのまま反映する。
   - グレーのときは、`DeviceGray` で描く。
   - JPEG または PNG にして返す（`Pixmap.asJPEG` と `asPNG`）。
3. Worker 0 で、新しい `PDFDocument` に、元のページと同じ大きさ（向きを反映した大きさ）のページを作り、画像を全面に貼る（`addImage`、`addPage`、`insertPage`）。
4. 全ページがそろったら `saveToBuffer`（全体の書き出し、圧縮）で保存する。
- **メモリ**: 画像のバイト列は、ページごとに Worker 0 へ送り、すぐに文書へ入れて捨てる。main thread にまとめて持たない。
- **進み具合**: 「画像にしています… 12 / 300 ページ」と進みの棒を表示する。
- **中止**: ［中止］で、まだ始めていないページの要求を取り消し、書き出しを止める（ファイルは書かない）。
- **A1 などの大きいページ**: 300 dpi の A1 は約 9900×7000 画素になる。1回で描くとメモリが足りない場合があるので、**画素数が 3,000 万を超えるページは、帯に分けて描き**、Worker 0 で帯ごとの画像として並べて貼る（見た目は1枚の画像に見えるよう、隙間なく並べる）。

### 4. 出力の確かめ

- 出力した PDF について、次を確かめる。
  - 各ページに文字の情報が無い（`toStructuredText().asText()` が空）。
  - 注釈が無い。
  - ページ数と大きさが元と同じ。

## テスト

- **Node の結合テスト**（`src/core/rasterize.ts` の関数として、Worker を使わずに呼べる形にしてテストする）
  - `sample-small.pdf`（回転したページを含む）を 150 dpi、JPEG で書き出し、ページ数・大きさ（回転を反映）・文字が無いこと・注釈が無いことを確かめる。
  - 書き込み（赤い文字）を付けた文書を書き出すと、そのページの画像に赤い画素があること。
  - グレーで書き出した画像が、1成分（Gray）であること。
  - A1 のページ（`heavy-300p.pdf` の 6ページ目。無ければテストの中で作る）を 300 dpi で書き出すと、帯に分けて貼られ、その間に隙間（白い筋）が無いこと。
- **画面のテスト（e2e）**
  - メニューからダイアログを開き、推定の大きさが表示され、書き出しの結果（テスト用の窓口 `rasterizeToBytes(options)` で、ファイルに書かずに受け取る）のページ数が正しいこと。
  - 中止のボタンで止まること。
- **性能**（bench、1回だけ）: `heavy-300p.pdf` の全 300 ページを 150 dpi・JPEG で書き出す時間と、書き出しの最中の Worker のメモリ（分かる範囲で）を報告する。

## 禁止事項

- 今開いている文書を変えないこと。
- main thread に、全ページの画像をまとめて持たないこと。
- 対象外のファイルを変更しないこと。git の変更操作をしないこと。
- 自分で起動したサーバーは必ず止め、一時ファイルは削除すること。
