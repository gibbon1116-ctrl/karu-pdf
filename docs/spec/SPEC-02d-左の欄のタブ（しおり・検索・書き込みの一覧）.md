## 変更内容

### 1. 左の欄のタブ

- 左の欄の上部に、4つのタブを並べる: ページ／しおり／検索／書き込み
- 選んでいるタブは、文書ごとに覚える（タブを切り替えても保つ）。
- 表示▼ メニューに「ページ一覧」「しおり」「検索」「書き込みの一覧」を加え、選ぶとその欄を開く。
- 欄の幅は、境目のドラッグで 160〜480px に変えられる（localStorage に保存）。

### 2. しおり（目次）

- Worker 0 で `document.loadOutline()`（型定義で確かめる）を読み、入れ子の一覧を返す。各項目は、題名、ページ番号、子を持つ。
- 欄には木の形で表示し、折りたたみと展開ができる。クリックで、そのページ（位置の情報があれば、その位置）へ移る。
- しおりが無い文書では、「この PDF には、しおりがありません」と表示する。
- ページ整理を適用した後は、読み直す。
- 今回は表示だけとし、編集は作らない（第3版の予定）。

### 3. 文字の検索（Ctrl+F）

- `Ctrl+F` か、検索のタブで、検索の欄にフォーカスする（ブラウザ標準の検索は `preventDefault` で止める）。
- 入力して `Enter`（または 300ms 止まったとき）で検索を始める。
- **Worker 0 で、ページごとに `page.search(needle)` を行い、見つかった Quad の一覧を返す**。
  - ページ順に少しずつ進め、見つかった分から画面へ送る。
  - 進み具合（「検索中… 120 / 330 ページ」）を表示する。
  - 新しい検索が始まったら、前の検索を止める。
- 選べるもの: 大文字・小文字の区別（既定は区別しない）、全角と半角を同じとみなす（既定はみなす。検索語と文字の両方を、NFKC で正規化して比べる。MuPDF の search が正規化に対応しない場合は、`toStructuredText` の文字列で自前に探し、位置を Quad で返す）。
- 結果の一覧: 「p.12 …前後の文脈…」を並べる（文脈は前後 15 文字程度で、見つかった語を太字にする）。クリックで、その場所へ移る。
- 本体の上で、見つかった場所を黄色の半透明で強調し、今の結果はオレンジで示す。`Enter` と `Shift+Enter`（または［↓］［↑］）で、次と前の結果へ移る。
- 件数を「12 件」と表示する。1,000 件を超えたら打ち切り、「1,000 件以上」と表示する。
- 文字の無いページ（スキャン画像）しか無い場合は、「この PDF には検索できる文字がありません（スキャン画像など）」と表示する。
- `Esc` で強調を消す。

### 4. 書き込みの一覧と CSV 出力

- 文書のすべての書き込み（かるPDF で編集できる種類。他のソフトのものを含む）を、ページ順・上から順に一覧にする。
  - まだ読み込んでいないページの書き込みも出すため、Worker 0 に `listAllAnnotations {docId}` を加える。全ページの `listAnnotations` をまとめて返し、ページごとに少しずつ送る。
- 各行の表示: 種類のアイコン（文字）、ページ番号、本文（文字・吹き出しは本文の先頭 40 文字、記号は記号の名前、図形は「四角」などの名前）、色の見本。
- クリックで、そのページへ移り、その書き込みを選ぶ（見える位置までスクロールする）。
- 絞り込み: 種類（文字・吹き出し・図形・記号・ペン）と、ページの範囲。
- 未保存の変更（新しく作った・動かした書き込み）も、一覧に反映する。
- **CSV に書き出す**（ボタン「CSV に書き出す」）
  - 列: 番号、ページ、種類、本文、色（`#RRGGBB`）、位置（x, y、単位 mm、ページの左上から）、大きさ（幅, 高さ mm）
  - 文字コードは UTF-8 で、先頭に BOM を付ける（Excel で文字化けしないように）。改行は CRLF。値は、必要に応じてダブルクォートで囲み、中のダブルクォートは2つ重ねる。
  - ファイル名の既定は `<元の名前>_書き込み一覧.csv`。`showSaveFilePicker` が無ければダウンロード。

## 性能の条件

- 検索とすべての書き込みの読み出しは、Worker 0 で少しずつ進め、**描画（描画用の Worker）を止めない**。
- 330 ページの仕様書（`test-data/real/公共建築工事標準仕様書_建築_R7.pdf`）で「コンクリート」を検索し、最初の結果が出るまでの時間と、全ページが終わるまでの時間を計測する（目標: 最初の結果 0.5 秒以内、全体 5 秒以内）。
- 検索の最中にスクロールしても、描画が遅れないこと（白抜けの割合が、検索しないときと大きく変わらないこと）。

## テスト

- **Node の結合テスト**
  - `sample-small.pdf`（「Sample page N」の文字がある）で、検索が正しいページと Quad を返すこと。全角と半角の同一視と、大文字・小文字の区別。
  - しおりのある PDF（テストの中で作ってよい）で、入れ子の一覧が返ること。
  - 全書き込みの読み出しが、全ページ分を返すこと。
- **単体テスト**: CSV の作り方（BOM、CRLF、クォート、mm への換算、ページの左上を原点にした座標）、検索の文脈の切り出し。
- **画面のテスト（e2e）**
  1. `Ctrl+F` で「Sample page 3」を検索する → 結果が1件以上 → クリックすると3ページ目へ移る。
  2. しおりのタブで項目をクリックすると、そのページへ移る。
  3. 書き込みを3つ作る → 書き込みのタブに3行出る → 行のクリックでそれが選ばれる → CSV の中身（テスト用の窓口 `exportAnnotationCsv()` で受け取る）に3行と見出しがある。
- **性能**: 上の検索の計測を、`test-data/real` がある場合に1回だけ行う。
