# SPEC-02e: ページ番号・ヘッダー・フッター

## 実行モデル指定（必須）

- モデル: `gpt-5.6-sol`
- reasoning effort: `high`
- 選定理由: ページの内容（コンテンツストリーム）への書き込み、フォントのサブセットの埋め込み、回転したページへの対応、文書の差し替えと元に戻す処理にまたがる新機能のため

---

## 目的

利用者が選んだ「ページ番号・ヘッダー・フッター」を作る（`docs/追加機能の計画.md` の 02e）。

`docs/要件と設計方針.md` の決定:
- ページ番号の初期設定は、下中央の「- 1 -」。
- 開始番号・位置・書式を変更できる。

提出用の書類に使うため、ページ番号などは**注釈ではなく、ページの内容として書き込む**（Acrobat の「ヘッダーとフッター」と同じ扱い）。ただし、かるPDF で付けたものは目印を付けておき、後から**付け直し・削除**ができるようにする。

最初に次を読むこと。
- `docs/追加機能の計画.md`、`docs/要件と設計方針.md`
- SPEC-01c、SPEC-01c-2（ページ整理の適用と、元に戻す処理）、SPEC-02a（メニュー）、SPEC-02c（ダイアログの作り）
- 今の `src/core/pageOps.ts`、`src/core/annotations.ts`（`installTemporaryAppearances`: 一時文書でサブセットを作ってから移す方式）、`src/core/fontMetrics.ts`（`encodeCharacter`、`replaceMissingCharacters`）、`src/worker/pdf.worker.ts`（`applyPageLayout`、`undoPageLayout`、`pageLayoutBackups`）、`src/client/PdfWorkerPool.ts`、`src/App.tsx`（`applyOrganize`、`finishPageLayout`、`undoLastOrganize`）、`src/app/RasterizeDialog.tsx`

## 変更内容

### 1. 画面: ページ▼ →「ページ番号・ヘッダー・フッター…」

ダイアログを開く。並びは次のとおり。

```
┌ ページ番号・ヘッダー・フッター ─────────────────────┐
│ 上  [左          ] [中央        ] [右          ]       │
│ 下  [左          ] [中央 - {ページ} -] [右    ]       │
│ 差し込む: [ページ番号] [総ページ数] [日付] [ファイル名] │
│ ページ番号の形: [- 1 - ▼]（選ぶと、選んでいる欄へ入る）  │
│ 開始番号 [1]   対象 (●すべて ○範囲 [2-10])            │
│ 書体 [ゴシック▼] 大きさ [10.5]pt 色 [■黒▼]             │
│ 余白 上下 [10]mm 左右 [15]mm                           │
│ 日付の形 [2026年10月1日▼]                              │
│ ┌プレビュー──────┐  ‹ 3 / 12 ページ ›                 │
│ │  （ページの縮小図に、│                                 │
│ │   文字を重ねて表示） │                                 │
│ └────────────┘                                 │
│ [削除]                         [キャンセル] [適用]      │
└────────────────────────────┘
```

- 6つの欄（上・下 × 左・中央・右）は、1行の入力欄にする。初期値は、下中央が `- {ページ} -`、ほかは空。
- 差し込みのボタンは、最後にフォーカスのあった欄のカーソル位置へ、次の記号を入れる。
  - `{ページ}`: ページ番号
  - `{総ページ}`: 総ページ数
  - `{日付}`: 適用した日の日付
  - `{ファイル名}`: 拡張子を除いたファイル名
- ページ番号の形（選ぶと、選んでいる欄の内容を置き換える）: `- {ページ} -`、`{ページ}`、`{ページ} / {総ページ}`、`P.{ページ}`、`{ページ}ページ`
- 開始番号: 1 以上の整数。**対象の最初のページ**の番号になる。例えば、対象を「2-10」、開始番号を 1 にすると、2ページ目が「1」になる（表紙を数えない使い方）。
- 対象: すべて、または範囲（`2-10`、`1,3,5-8` の形）。ページ整理と同じ `src/organize/organizeUtils.ts` の `parsePageRange` を使う（読むだけ。`src/organize/` は変更しない）。
- 番号は、対象のページを前から順に（範囲の書き順ではなく、ページの順に）数える。例えば「1,3,5-6」なら、1・3・5・6ページ目が順に 1・2・3・4 になる。
- `{総ページ}` は、最後の対象ページの番号（開始番号 + 対象の枚数 − 1）とする。
- 書体: BIZ UDゴシック／BIZ UD明朝。大きさ: 6〜72pt（既定 10.5）。色: 書式パネルの 8 色（既定は黒）。
- 余白: ページの端から文字までの距離（mm）。上下は既定 10mm、左右は既定 15mm。
- 日付の形: `2026年10月1日`、`2026/10/01`、`令和8年10月1日`（`Intl.DateTimeFormat('ja-JP-u-ca-japanese', …)` を使う）
- プレビュー:
  - 今のページの縮小図に、文字を重ねて表示する。
  - 縮小図は、ページ一覧と同じキャッシュのものを使う。無ければ優先度 1 で1枚だけ描く。
  - 文字の重ね表示は画面側で行う（HTML の文字）。**入力のたびに Worker へ問い合わせない。**
  - ‹ › でプレビューするページを変えられる。対象外のページでは「このページには付けません」と表示する。
- 前に付けた設定がある文書では、その設定を初期値にする（下の「設定の保存」）。
- ［削除］: かるPDF で付けたページ番号・ヘッダー・フッターを、全ページから取り除く。付けていない文書では押せない。
- 入力の誤り（範囲の書き方、開始番号）は、欄の下に赤字で示し、［適用］を押せなくする。6つの欄がすべて空のときも、［適用］を押せなくする。

### 2. 適用（Worker 0、`src/core/headerFooter.ts`）

新しいメッセージ `applyHeaderFooter {docId, settings, fileName, dateText}` と `removeHeaderFooter {docId}` を作る。`dateText` は画面側で作って渡す（Worker の時刻や地域の設定に頼らない）。

処理の流れは、`applyPageLayout` と同じにする。
1. 画面側で、未反映の書き込み（`applyPendingEdits`）を先に反映する。
2. Worker 0 で、適用の前の状態を増分保存のバイト列として、**ページ整理と同じ控え（`pageLayoutBackups`）**に入れる。
3. 全ページから、前にかるPDF で付けたものを取り除き、対象のページに新しく付ける（下の「書き込み方」）。
4. 増分保存して開き直し、バイト列を返す。描画用の Worker を読み直す（`reloadDisplayWorkers`）。
5. 画面は `finishPageLayout` と同じ扱いにする。表示しているページの位置は保つ。

#### 書き込み方

- 各ページの `/Contents` を配列にし、前後に、かるPDF の内容ストリームを足す。
  - 前: `q`
  - 後: `Q` に続けて、ページ番号などの描画
  - 元の内容の描画状態（座標変換など）の影響を受けないようにするためである。
- 足したストリームの辞書には、`/KaruHeaderFooter true` を入れる。取り除くときは、この印のあるストリームだけを `/Contents` から外す。
- 描画は、次の形の印付き内容で囲む。
  ```
  /Artifact <</Type /Pagination /Subtype /Header>> BDC … EMC
  ```
  下の欄では `/Footer` にする。
- フォント:
  - 全ページで使う文字（数字・記号・欄の文字・日付・ファイル名）をまとめ、`installTemporaryAppearances` と同じく、一時文書でサブセットを作ってから文書へ移す。
  - フォントのオブジェクトは1つだけ作り、全ページの `/Resources /Font` に `/KaruHF`（ZapfDingbats を使うときは `/KaruHFD`）として加える。
  - **フォント全体を埋め込まない**（ファイルが数 MB 増えるため）。
  - `/Resources` を親から受け継いでいるページや、他のページと共有しているページでも、正しく動くこと。
  - 文字の符号化と幅は、既存の `encodeCharacter` と `replaceMissingCharacters` を使う。中央・右の欄は、文字の幅を測ってそろえる。
- 位置と向き:
  - 位置は、**利用者に見えている向きのページ**（`/Rotate` と CropBox を反映した向き）の、上下・左右の端から測る。
  - 回転したページ（90°、180°、270°）でも、CropBox の原点が 0 でないページでも、文字は見えている向きで正立し、指定の位置に出ること。
  - `PDFPage.getTransform()` の逆行列で、PDF の座標へ直す。
- 設定の保存:
  - 文書のカタログ（`/Root`）に、`/KaruHeaderFooter` として設定を保存する（JSON を PDF の文字列にしたもの。日本語を含んでも往復できること）。
  - ダイアログを開いたときに、これを読んで初期値にする。
  - `removeHeaderFooter` では、これも消す。
- 新しいメッセージ `getHeaderFooterSettings {docId}` → `{settings | null}` を作る。ダイアログを開いたときだけ呼ぶ。

### 3. 元に戻す

- ページ▼ の「ページ整理を元に戻す」を「**直前のページ操作を元に戻す**」に変える。ページ整理の適用、ページ番号などの適用・削除の、どれでも直前の1回を戻す（控えは1つ。今の `undoPageLayout` をそのまま使う）。
- 状態表示の文言も合わせる（「直前のページ操作を元に戻しました」）。

### 4. ページ整理との関係

- ページ番号はページの内容なので、ページ整理でページを並べ替えると、番号もページと一緒に動く。
- ページ整理を適用したとき、文書に `/KaruHeaderFooter` の設定があれば、状態表示に「ページの並びが変わりました。ページ番号を付け直すときは、ページ▼ → ページ番号・ヘッダー・フッター で［適用］を押してください」と出す。**自動では付け直さない。**

## 動作の軽さ（最重要）

- ダイアログを開いている間の入力やプレビューで、Worker に問い合わせない（開いたときの設定の読み込みと、縮小図1枚だけ）。
- 適用と削除は、ボタンを押したときだけ動く。処理中は「適用中…」と表示し、二重に押せないようにする。
- 適用の時間を計測する（下の「性能」）。

## テスト

- **単体テスト**（`headerFooterText.ts`）
  - 記号の置き換え（`{ページ}` `{総ページ}` `{日付}` `{ファイル名}`）
  - 開始番号と対象の範囲から、各ページの番号と総ページ数を求めること
  - 範囲の書き方の誤りを見つけること
  - 日付の3つの形
- **Node の結合テスト**（`sample-small.pdf` と、テストの中で作る PDF）
  1. 下中央に `- {ページ} -` を付けると、各ページの `toStructuredText` に「- 1 -」「- 2 -」…があり、その行の枠が、ページの下端から余白 10mm 付近の、左右の中央にあること。
  2. 6つの欄すべてに文字（日本語を含む）を入れると、それぞれの位置に出ること。
  3. `/Rotate` が 90・180・270 のページと、CropBox の原点が 0 でないページで、文字が正立し（`StructuredText` の行の向きが横書きの正方向）、見えている向きの指定の位置に出ること。
  4. もう一度適用すると、前のものが残らず、新しいものだけになること（同じ文字が二重に出ないこと）。
  5. 削除すると、元のページの内容だけに戻り、`/KaruHeaderFooter` の設定も消えること。元の内容のストリームは変わらないこと。
  6. 保存して開き直しても、ページ番号と設定が残ること。設定の日本語が往復すること。
  7. 適用の前後で、埋め込んだフォントによる増加が、300 ページで 200KB 以下であること（フォント全体を埋め込んでいないことの確認）。
  8. 既存の書き込み（注釈）とフォームの欄が、適用の後も残ること。
  9. PDFium で描いても、ページ番号が見えること（`tests/pdfium.compat.test.ts` の方式）。
- **画面のテスト（e2e）**
  1. ページ▼ → ページ番号・ヘッダー・フッター → 初期値のまま［適用］→ テスト用の窓口で、各ページの文字に「- 1 -」などがあることを確かめる。
  2. 対象を「2-5」、開始番号を 1 にして適用 → 1ページ目には無く、2ページ目が「- 1 -」になる。
  3. 「直前のページ操作を元に戻す」で、付ける前に戻る。
  4. ［削除］で消える。
  5. 入力の誤り（範囲「5-2」など）で、［適用］が押せない。
- **性能**（1回だけ）
  - `test-data/real/公共建築工事標準仕様書_建築_R7.pdf`（330 ページ）と `test-data/heavy-300p.pdf` で、初期値のまま［適用］を押してから、表示が戻るまでの時間を計測する。
  - 目標は、それぞれ 5 秒以内。

## 禁止事項

- 対象外のファイルを変更しないこと。git の変更操作をしないこと。
- フォント全体を埋め込まないこと。
- 元のページの内容ストリームを書き換えないこと（前後に足すだけにする）。
- 自分で起動したサーバーは必ず止め、一時ファイルは削除すること。
