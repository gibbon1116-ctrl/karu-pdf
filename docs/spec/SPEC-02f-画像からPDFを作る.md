# SPEC-02f: 画像（写真）から PDF を作る・ページ整理で画像を挿入する

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 画像の読み込みと縮小（専用の Worker）、EXIF の向き、PDF の書き出し部品の拡張、ページ整理への組み込みにまたがるため

---

## 目的

利用者が選んだ「画像（写真）→ PDF」を作る（`docs/追加機能の計画.md` の 02f）。

現場の写真やスキャンした画像を、PDF にまとめたり、今の PDF に差し込んだりできるようにする。PDF は外部へ送らず、パソコンの中だけで作る。

動作を重くしないことが最重要。画像の読み込みと縮小は、専用の Worker で1枚ずつ行い、画面を止めない。

## 変更内容

### 1. 入口

1. **ファイル▼ →「画像から PDF を作る…」**
   - 画像のファイルを複数選ぶ（`showOpenFilePicker`。無ければ `<input type="file" multiple>`）。
   - 選んだらダイアログを開く。
2. **画像のファイルを、アプリの画面へドロップ**（PDF のドロップと同じ場所）
   - PDF と画像が混ざっていたら、PDF は今までどおり開き、画像はダイアログへ渡す。
3. **ページ整理の 挿入▼ →「画像を挿入…」**
   - 同じダイアログを「挿入」の形で開く。
   - 作ったページを、今の挿入位置（選んでいるページの後ろ。今の「他の PDF から挿入」と同じ決まり）へ、下書きとして加える。
   - 作った PDF を、今の「他の PDF から挿入」と同じ材料（source）の仕組みで扱う。新しい挿入の仕組みは作らない。

### 2. ダイアログ（`ImagesToPdfDialog.tsx`）

```
┌ 画像から PDF を作る ──────────────────────────────┐
│ ┌ 画像（12 枚） ─────────────┐  ┌ 仕上がり ───────┐  │
│ │ [▢] IMG_0012.jpg  4032×3024 ↑↓│  │ （1ページ目の   │  │
│ │ [▢] IMG_0013.jpg  …          │  │   見本）        │  │
│ │ …                            │  │  ‹ 1 / 12 ›     │  │
│ └────────────────────┘  └─────────┘  │
│ 並び [選んだ順 ▼]（選んだ順・名前順・撮影日時順）      │
│ 用紙 [A4 ▼]（A4・A3・B5・B4・画像の大きさ）           │
│ 向き [自動 ▼]（自動・縦・横）  余白 [10 ▼] mm（0・5・10・15）│
│ 1ページに [1 ▼] 枚（1・2・4）                         │
│ 画質 [標準 ▼]（元のまま・標準・小さく）  見込み 約 18 MB │
│ [画像を追加] [選んだ画像を外す]     [キャンセル] [作成] │
└──────────────────────────────────────────┘
```

- 画像の一覧:
  - 小さな見本・ファイル名・画素数を並べる。
  - 見本は、**見えている行だけ**作る（`IntersectionObserver`）。`image.worker.ts` で、長い辺 96px に縮めて作る。
  - 並べ替えは、↑↓のボタン、ドラッグ、`Alt+↑`・`Alt+↓`。
- 並び:
  - 選んだ順（既定）、名前順（数字は数として比べる。`IMG_2` < `IMG_10`）、撮影日時順（EXIF の撮影日時。無ければファイルの更新日時）
- 用紙と向き:
  - 「自動」は、画像が横長なら横、縦長なら縦にする（1ページに 1 枚のとき）。2・4 枚のときは、用紙の向きを縦にする。
  - 「画像の大きさ」は、1ページに 1 枚のときだけ選べる。画像の画素数を 150dpi とみなした大きさの用紙にし、余白は付けない。
- 1ページに 2・4 枚:
  - 2枚は上下に、4枚は 2×2 に並べる。区画の間は 5mm 空ける。
  - 各画像は、区画の中で縦横の比を保ったまま最大にし、中央に置く。
- 画質:
  - **元のまま**: JPEG は**そのまま埋め込む**（再圧縮しない）。PNG は、`parsePngForPdf` で読めるものはそのまま、読めないもの（透明・パレット・16bit・インターレースなど）は、白の上に描いて PNG に変換し直す。
  - **標準**（既定）: 長い辺を 2,400px までに縮め（それより小さい画像は縮めない）、JPEG（品質 0.85）にする。
  - **小さく**: 長い辺 1,600px まで、JPEG（品質 0.75）。
  - 見込みの大きさ: 元のままは、ファイルの大きさの合計。標準・小さくは、画素数からの概算でよい（「約」を付ける）。
- 読めない画像:
  - HEIC・HEIF は、ブラウザで読めない。一覧に赤字で「HEIC は読めません。JPEG に変換してから選んでください（iPhone は 設定 → カメラ → フォーマット →「互換性優先」）」と表示し、作成の対象から外す。
  - 壊れた画像も、同じく赤字で示して外す。
- 見本（仕上がり）:
  - 選んでいる設定で、ページの枠と、画像の置き場所を、画面側で描く（画像は一覧の見本を使う）。
  - Worker への問い合わせは、見本の画像のためだけにする。

### 3. 作成

- 処理は `image.worker.ts`（新しい Worker。MuPDF の Worker とは別）で、**1枚ずつ**行う。
  - 読み込み: `createImageBitmap(blob, { imageOrientation: 'from-image' })`
  - 縮小と変換: `OffscreenCanvas` と `convertToBlob`
  - 使い終わった画像は、すぐ `close()` する。同時に持つ画像は1枚分だけにする。
- 「元のまま」の JPEG で、EXIF の向き（Orientation）が 1 以外のとき:
  - 再圧縮せず、ページの内容の変換行列（cm）で回転・反転して、正しい向きに置く。
  - 置き場所の計算では、回転した後の縦横を使う。
- 書き出し:
  - `pdfStreamWriter` に、用紙の上の任意の位置へ画像を置くページの書き出し（例: `writeImagesPage(paper, placements)`）を加え、メモリへ書く（`MemoryPdfWriteTarget`）。
  - 書き出した PDF を、入口1・2では**新しいタブ**として開く。名前は `画像から作成_YYYYMMDD.pdf` とし、未保存の印を付ける（保存は `Ctrl+S` で「名前を付けて保存」になる）。入口3では、ページ整理の材料にする。
- 進み具合を「作成中… 5 / 12 枚」と表示する。［中止］で止められる。中止したら、途中のものは捨てる。
- 見込みが 500MB を超えるときは、作成の前に「とても大きな PDF になります。画質を『標準』か『小さく』にしてください」と警告する（それでも作れる）。

## 動作の軽さ（最重要）

- 画像の読み込み・縮小・変換は、すべて `image.worker.ts` で行い、画面のスレッドでは行わない。
- 一度に読み込む画像は1枚だけにする。全部の画像を先に読み込まない。
- 一覧の見本は、見えている行だけ作る。
- ダイアログを開いていないときは、何も動かさない。
- 作成中も、開いている PDF の表示やスクロールを止めないこと。

## テスト

試験用の画像は、テストの中で作ってよい。
- JPEG: mupdf の Pixmap の `asJPEG`、または画面のテストではブラウザの canvas を使う。
- EXIF の向きを持つ JPEG: APP1 を書き足して作る。

- **単体テスト**
  - `exif.ts`: 向き 1〜8、撮影日時、EXIF が無い JPEG、壊れた EXIF（落ちないこと）
  - `imagePdfLayout.ts`:
    - A4 縦・余白 10mm で、横長の画像が余白の内側いっぱいの幅に、比を保って中央に置かれること
    - 自動の向き
    - 2枚・4枚の区画
    - 「画像の大きさ」（150dpi）
    - 回転（EXIF の向き 6・8）した後の縦横
  - 名前順（数の比較）と撮影日時順
- **Node の結合テスト**（`pdfStreamWriter` と配置の計算）
  1. 「元のまま」で JPEG 3枚から作った PDF を mupdf で開ける。ページは 3 枚で、A4 の大きさ。各ページの画像の XObject の中身（DCTDecode のバイト列）が、元の JPEG のバイト列と**同じ**であること（再圧縮していない）。
  2. 画像の置き場所（ページの内容の変換行列から求める）が、余白の内側にあり、縦横の比が元の画像と同じであること。
  3. EXIF の向き 6 の JPEG（左上に赤い印を付けた画像）を「元のまま」で置いて描くと、赤い印が、正しい向きの左上に来ること（画素で確かめる）。
  4. 1ページに 4 枚のとき、4 つの画像が重ならずに 2×2 に並ぶこと。
  5. PDFium で描いても、画像が見えること。
- **画面のテスト（e2e）**
  1. ファイル▼ →「画像から PDF を作る…」で画像 3 枚を選ぶ（テスト用の窓口か `setInputFiles`）。↓ で順を変え、［作成］を押す。新しいタブが開き、3 ページで、ページの順が変えた順になっていること（各画像の色で見分ける）。
  2. 画質「標準」で、長い辺が 4,000px の画像が 2,400px になっていること（作った PDF の画像の幅で確かめる）。
  3. ページ整理の 挿入▼ →「画像を挿入…」で 2 枚を挿入し、［適用］すると、ページ数が 2 増え、挿入位置が正しいこと。
  4. HEIC の拡張子のファイルを選ぶと、赤字の案内が出て、作成の対象から外れること。
  5. 作成中に［中止］を押すと、新しいタブができないこと。
- **性能**（1回だけ）: 4,000×3,000px の JPEG 30 枚を「標準」で PDF にする時間と、その間の画面のフレーム間隔の p95 を計測する。目標は、作成 30 秒以内、p95 20ms 以下。「元のまま」の時間も測る。

## 禁止事項

- 対象外のファイルを変更しないこと。git の変更操作をしないこと。
- 画像の処理に、外部のライブラリを加えないこと（EXIF も自前で読む）。
- 画像を外部へ送らないこと。
- 自分で起動したサーバーは必ず止め、一時ファイルは削除すること。
- テストは「ページがある」だけでなく、**画像の中身・置き場所・向き**を確かめること。作った PDF は画像に描いて、自分の目でも確かめること。
