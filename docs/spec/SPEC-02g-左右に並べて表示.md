# SPEC-02g: 左右に並べて表示

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 作業領域の作り直し（2つ目の表示）、スクロールと倍率の同期、描画の要求の管理にまたがるため

---

## 目的

利用者が選んだ「左右に並べて表示」を作る（`docs/追加機能の計画.md` の 02g）。次の 02h（2つの PDF の比較）の土台にもなる。

使い方の例:
- 旧版の図面を右に出し、左の新版に書き込む
- 仕様書の別のページを右に出したまま、左の図面を確認する

**左は今までどおりの「編集する文書」、右は「見るための表示」にする**。両方で編集できるようにすると、道具・書式・保存の対象が分かりにくくなり、作りも重くなるためである。右の文書を編集したいときは［左右を入れ替える］を使う。

動作を重くしないことが最重要。並べていないときの動作と速さは、今と変えないこと。

最初に次を読むこと。
- `docs/追加機能の計画.md`
- SPEC-01a（画面の骨組み）、SPEC-02a（メニュー）、SPEC-01f-4（詳細描画の要求の同期）
- 今の `src/App.tsx`、`src/app/DocumentWorkspace.tsx`、`src/viewer/Viewer.tsx`、`src/viewer/PageView.tsx`、`src/client/RenderScheduler.ts`、`src/app/MenuBar.tsx`、`src/app/documentModel.ts`

## 変更内容

### 1. 入口

- 表示▼ →「左右に並べて表示」（チェック付きの項目。`Ctrl+\` でも切り替える）。
- 並べるとき、右の文書は次の順で決める。
  1. 前に右に出していた文書が、まだ開いていればそれ
  2. 開いている別のタブがあれば、今のタブの次のタブ
  3. 無ければ、同じ文書
- ページ整理の画面では、並べて表示を使えない（ページ整理を開いたら、一時的に1つの表示に戻す。閉じたら元に戻す）。

### 2. 画面

```
┌ 左（編集する文書）────────────┬┬ 右（見るための表示）──────────┐
│                                ││ [設計図_旧.pdf ▼] p.3/12  − 80% ＋ 幅 │
│   今までどおりの表示と編集       ││ ☑ ページを合わせて動かす [⇄ 入れ替え] [×] │
│                                ││                                │
│                                ││   表示だけ（書き込みはできない）   │
└────────────────────────────────┴┴────────────────────────────────┘
```

- 左のページ一覧（左の欄）と書式パネルは、今までどおり**左の文書**のもの。
- 境目はドラッグで動かせる（左右それぞれ 25%〜75%）。位置は localStorage に覚える。
- 右の見出し:
  - 文書の選択（開いているタブの一覧と「同じ文書」）
  - ページの位置
  - 倍率の［−］［＋］［幅］
  - ［⇄ 入れ替え］［×］（並べるのをやめる）
- 右の表示:
  - スクロール、`Ctrl`＋ホイールの拡大縮小、ページの移動ができる。
  - 書き込みの重ね表示（編集の層）は出さない。保存されている書き込みは、ページの画像の一部として見える。
  - 右の文書に未保存の書き込みがあるときは、見出しに小さく「未保存の書き込みは表示されません」と出す。
- 右の表示をクリックしても、左の選択や道具は変わらない。キーボードの操作（`Ctrl+S`、`Ctrl+Z`、道具のキーなど）は、すべて左の文書に効く。
  - 右の表示にフォーカスがあるときの方向キーと PageUp・PageDown は、右のスクロールに効く。
- ［⇄ 入れ替え］:
  - 右の文書のタブを、今のタブにする（左に移る）。
  - 左にあった文書を、右に出す。
  - 両方が同じ文書のときは、左右の表示位置を入れ替える。
- タブを閉じて、右の文書が無くなったときは、右に「表示する文書を選んでください」と出す。

### 3. ページを合わせて動かす（同期）

- 既定はオン。右の見出しのチェックで切り替える。
- オンのとき、左をスクロールすると、右も同じページ番号の、ページの中の同じ割合の位置へ動く。右をスクロールしたときも、左が同じように動く（**動かした側に、もう片方が合わせる**。互いに追いかけ合って揺れないこと）。
- 倍率も合わせる。ページの大きさが違うとき（A1 と A3 など）は、「幅」の比率が同じになるように合わせる。
- ページ数が違うときは、少ない方の最後のページで止める。
- 同じ文書を左右に出しているときにオンにすると、両側が同じ場所になる。このため、同じ文書のときの既定はオフにする。
- 同期の計算は `viewSync.ts` に置く。表示の位置の更新は、requestAnimationFrame ごとに最大1回とする。

### 4. 描画

- 右の表示は、左とは別の `RenderScheduler` を使ってよい。同じ文書のときは、描画済みの画像（キャッシュ）を左右で共有し、同じページを二重に描かないこと。
- 見えているページの描画を、左右で公平に扱う。今の優先度の決まり（見えている範囲 → 余白付きの範囲 → 先読み）を、左右それぞれに当てはめる。
- 並べていないときは、右の部品を作らない。新しい処理を何も動かさない。

### 5. 状態の保存

- 並べているかどうか、右の文書、境目の位置、同期のオン・オフは、localStorage に覚える（ファイルの中身は保存しない）。アプリを開き直したときは、並べない状態から始めてよい。

### 6. 使い方の画面

- 使い方に、この機能の説明を加える。

## 動作の軽さ（最重要）

- 並べていないときの、開く・スクロール・拡大の速さを変えないこと（`perf.spec` を1回実行し、SPEC-01f-4 以降の結果より悪化していないことを確かめる）。
- 並べているときも、普通の速さのスクロールで白く抜けないこと（左右を同期して、1,500px/s でスクロールしたときの白抜けの割合を計測する）。
- 右の表示に、書き込みの層・文字の層を作らない。

## テスト

- **単体テスト**（`viewSync.ts`）
  - 同じ大きさのページで、同じページ・同じ割合の位置になること
  - A1 と A3 で、幅の比率に合わせた倍率になること
  - ページ数が違うときに、最後のページで止まること
  - 動かした側が決まっているとき、もう片方からの通知で戻されないこと（揺れない）
- **画面のテスト（e2e）**
  1. 2つの PDF を開き、表示▼ →「左右に並べて表示」で、右にもう一方の文書が出る。左の欄のページ数は左の文書のもの。
  2. 同期がオンのとき、左で 3 ページ目へ移ると、右も 3 ページ目になる。右で 2 ページ目へ移ると、左も 2 ページ目になる。
  3. 同期をオフにすると、左右が別々に動く。
  4. 右の表示の上をクリック・ドラッグしても、書き込みができない。左で四角を描くと、左の文書にだけ書き込みが増える。
  5. ［⇄ 入れ替え］で、今のタブが右の文書になり、右に元の左の文書が出る。
  6. 右に出している文書のタブを閉じると、右に「表示する文書を選んでください」と出る。
  7. `Ctrl+\` で並べる・やめるを切り替えられる。並べるのをやめると、右の部品が無くなる（DOM に残らない）。
- **性能**（1回だけ）
  - `perf.spec`（並べていないとき）
  - 並べて同期したときの、1,500px/s のスクロールでの白抜けの割合
