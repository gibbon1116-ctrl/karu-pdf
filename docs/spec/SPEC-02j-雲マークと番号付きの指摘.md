## 変更内容

### 1. 雲マーク

#### 1-1. 道具

図形▼ に次の2つを加える。

| 道具 | 説明（プルダウンの1行） | 操作 |
|---|---|---|
| 雲（四角） | 修正箇所を四角い雲形で囲む | ドラッグで四角を描く（四角の道具と同じ） |
| 雲（多角形） | 修正箇所を自由な形の雲形で囲む | クリックで点を足し、ダブルクリックか `Enter` で閉じる（02i の面積と同じ操作。`Backspace`・`Esc`・`Shift` も同じ） |

#### 1-2. 注釈

- 雲（四角）: Square 注釈に、境界の効果 `/BE << /S /C /I 1 >>` を付ける。
- 雲（多角形）: Polygon 注釈に `/IT /PolygonCloud` と、同じ `/BE` を付ける。
- 書式: 線の色（既定は赤）、太さ（既定 1pt）、透明度、塗り（既定なし）、**雲の大きさ**（小・中・大。`/I` の 0・1・2 に当てる。既定は中）。
- 他のソフトで作られた雲（`/BE /S /C` のある Square・Polygon）も、雲として読み込んで編集できること。

#### 1-3. 見た目

- まず、MuPDF の `update()` が雲形の外観を作るかを確かめる。
  - 作る場合は、それを使う。
  - 作らない場合や、見た目が崩れる場合は、`cloud.ts` の計算で自前の外観（弧をつないだ線）を作る。
- 画面の重ね表示（SVG）は、`cloud.ts` の同じ計算で描く。保存した後の見た目と、編集中の見た目がずれないようにする。
- 弧の大きさは、雲の大きさ（`/I`）と線の太さから決める。弧は外向きにふくらませる。四角の角や多角形の頂点では、弧がつながって見えること。
- 雲（四角）は、大きさの変更のつかみを、四角と同じく 8 か所に出す。雲（多角形）は、頂点ごとにつかみを出す（02i と同じ）。

### 2. 番号付きの指摘

#### 2-1. 道具「指摘」

- 文字▼ に「指摘」を加える（キー `N`）。説明は「番号を付けて、指摘の内容を書く」。
- 図面の上をクリックすると、その位置に**丸に番号**の印（指摘の印）を置き、すぐに指摘の内容を書く小さな入力欄を開く（複数行。`Ctrl+Enter` か、欄の外のクリックで確定。`Esc` で内容を空のまま閉じる。印は残す）。
- 続けて置けるよう、道具はそのまま（記号と同じ）。`Esc` で選択に戻る。

#### 2-2. 注釈

- 記号と同じく、ベクターの外観を持つ Stamp 注釈にする。
  - かるPDF 用の印として `/KaruIssue`（番号・状態を JSON にした文字列）を持たせる。
  - `/Contents` に指摘の内容を入れる（Acrobat の注釈一覧でも読めるように）。
- 印の見た目:
  - 円の中に番号（BIZ UD ゴシック。数字は何桁でもよい）。
  - 既定は赤い円の枠と赤い数字に、白の塗り。
  - 大きさは 小（12pt）・中（16pt）・大（24pt）。既定は中。書式パネルで、色と大きさを変えられる。
- 状態: **未対応**と**対応済**の2つ。対応済の印は、色を灰色にし、右上に小さなチェックを付ける。
  - 状態は、書式パネルと一覧の行から切り替えられる。
- 指摘の内容は、印にカーソルを重ねたときに `title` で表示する。ダブルクリックで、入力欄を開いて直せる。
- 移動、方向キー、削除、`Ctrl+Z` は、ほかの書き込みと同じ。大きさの変更のつかみは出さない（大きさは書式で変える）。

#### 2-3. 番号の振り方（`src/core/issues.ts`）

- 番号は**文書全体で通し番号**にする。新しい印には、文書の中の一番大きい番号 + 1 を付ける。
  - まだ読み込んでいないページの印も数えるため、道具を最初に使ったときに、Worker 0 に `maxIssueNumber {docId}` を1回だけ問い合わせる。
  - 各ページの `/Annots` を見るだけにし、ページの描画や文字の抽出はしない。結果は覚えておく。
- 印を消しても、ほかの番号は詰めない（欠番になる）。
- 貼り付け・複製した印には、新しい番号を付ける（番号が重ならないように）。
- 一覧の［番号を振り直す］: ページ順・上から順・左から順に、1 から振り直す。確認のダイアログを出す。`Ctrl+Z` で戻せる。

### 3. 指摘の一覧と CSV

- 左の欄の「書き込み」タブの絞り込みに「指摘」を加える。
- 「指摘」で絞り込んだときは、行を番号の順に並べる。各行に、番号・ページ・内容の先頭・状態を表示する。
  - 行のクリックで、その場所へ移って選ぶ。
  - 行のダブルクリックで、内容の入力欄を開く。
- ［指摘一覧を CSV に書き出す］: 指摘だけを、番号の順に書き出す。
  - 列: 番号、ページ、指摘の内容、状態、対応（空欄。利用者が Excel で書き込むため）、位置（x, y mm）
  - 文字コードなどは、SPEC-02d の CSV と同じ（BOM 付きの UTF-8、CRLF）。
  - ファイル名の既定は `<元の名前>_指摘一覧.csv`。
- 今の「CSV に書き出す」（すべての書き込み）にも、指摘の行を含める。種類は「指摘」、本文は「№ 3 内容…」の形にする。

## 動作の軽さ（最重要）

- 雲形の計算は、描いている間は画面側だけで行う。外観は、保存か書き込みの反映のときだけ作る。
- 番号の問い合わせ（`maxIssueNumber`）は、文書ごとに、指摘の道具を最初に使ったとき1回だけ。全ページの描画や読み込みをしない。
- 指摘の道具を使っていないときは、新しい処理を動かさない。

## テスト

- **単体テスト**
  - `cloud.ts`: 四角と多角形の雲形で、弧がすべて外向きであること。弧の数が、辺の長さと弧の大きさから期待どおりであること。始点と終点がつながっていること。
  - `issues.ts`: 次の番号、欠番、貼り付け時の番号の付け直し、振り直しの順（ページ・上・左）
  - CSV: 指摘一覧の列と順番、内容に改行・カンマ・ダブルクォートがある場合
- **Node の結合テスト**
  1. 雲（四角・多角形）を作って保存し、開き直す。種類・`/BE`・`/IT`・頂点・色が戻ること。
  2. 雲の外観を画像に描くと、四角の辺に沿って弧の凹凸があること（例: 辺の外側の、弧の頂点の位置に線の色の画素があり、弧と弧の間の位置にはないこと）。
  3. 指摘の印を作って保存し、開き直す。番号・状態・内容が戻ること。外観に番号の文字が描かれていること（`toStructuredText` で番号が読め、その行の枠が印の円の中にあること）。
  4. `maxIssueNumber` が、まだ読み込んでいないページの印も含めた最大値を返すこと。
  5. 元のページの内容と、既存の書き込みが残ること。
  6. PDFium で描いても、雲と指摘の印が見えること。
- **画面のテスト（e2e）**
  1. 雲（四角）をドラッグで描き、保存して開き直しても雲として残る。
  2. 雲（多角形）を4点で描く。`Enter` で閉じる。
  3. 指摘を3つ置き、それぞれに内容を書く。番号が 1・2・3 になる。2 を消してから新しく置くと、4 になる。
  4. ［番号を振り直す］で 1・2・3 になる。`Ctrl+Z` で戻る。
  5. 一覧の「指摘」の絞り込みと、指摘一覧の CSV の中身（テスト用の窓口で受け取る）を確かめる。
  6. 対応済にすると、一覧と CSV の状態が「対応済」になる。

- 対象外のファイルを変更しないこと。git の変更操作をしないこと。
- マウスの動きごとに React の state を更新しないこと。

- テストは「注釈がある」だけでなく、**見た目・値・位置の結果**を確かめること。外観は画像に描いて、自分の目でも確かめること。
