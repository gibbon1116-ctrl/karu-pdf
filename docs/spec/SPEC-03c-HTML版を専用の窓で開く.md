# SPEC-03c: HTML の版を、タブやお気に入りの無い専用の窓で開く

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: Windows の起動用のファイル（cmd と PowerShell）、ショートカットの作成、アイコンの生成、配布物への組み込みにまたがり、日本語や空白を含む場所でも確実に動く必要があるため

---

## 目的

利用者から次の要望が出た（2026-10-02）。

> （HTML の版を）起動すると、Web 画面のタブやお気に入り等が出てくる。GitHub から呼び出していたとき（アプリとしてインストールした窓）のように、アプリの動作に不要な項目は出てこないようにしたい。

HTML の版は `file://` で開くため、PWA としてインストールできない。代わりに、Edge（無ければ Chrome）の**アプリモード**（`--app=<URL>`）で開く。アプリモードの窓には、タブ・アドレスバー・お気に入りのバーが出ない。管理者権限は要らない。

## 確かめたこと（2026-10-02、この PC の Edge）

- `--app=<パス>` は、英数字だけの場所なら、Windows のパスでも `file:///` 付きでも開ける。
- **日本語を含む場所**（例: `…\新しいフォルダー\…`）では、パスのままでは開けず、新しいタブになる。**パーセントエンコードした `file:///` の URL**（`file:///C:/…/%E6%96%B0…/karu%20pdf/…`）なら開ける。
- Windows に標準の Windows PowerShell 5.1 で、`([System.Uri]'C:\…\新しいフォルダー\karu pdf\x.html').AbsoluteUri` が、正しくパーセントエンコードした URL を返す。
- Edge の場所は、`HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\msedge.exe` の既定値で分かる（読むだけなので権限は要らない）。

## 対象

- 新しく作るファイル: `scripts/launchers/`（起動用のファイルの元）、`scripts/make-ico.mjs`（または `package-fixed.mjs` の中の関数）
- 変更してよいファイル: `scripts/package-fixed.mjs`（HTML の版の配布物の作り方）、`scripts/audit-network.mjs` と `scripts/audit-allowlist.json`（新しいファイルの監査）、`src/`（下の 4. の案内だけ）、`tests/`、`e2e/`、`README.md`、`docs/固定版/`
- 変更しないファイル: 通常版・固定版・HTML の版の HTML の生成物の中身（4. を除く）、`package-lock.json`、`public/`、`.github/workflows/deploy.yml`
- 新しい npm パッケージを加えない。

## 変更内容

### 1. 起動用のファイル `かるPDFを開く.cmd`

- HTML と同じフォルダに置く。ダブルクリックすると、アプリモードの窓で HTML を開く。
- 中身は ASCII の文字だけで書く（cmd はファイルを OEM のコードページで読むため。日本語の文字列が要る所は、PowerShell の中で `[char]0x…` で作る）。
- 処理（PowerShell 5.1 を `powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -Command …` で呼ぶ。`.ps1` のファイルは使わない（実行ポリシーで止められうるため））:
  1. cmd のあるフォルダ（`%~dp0`）から、`karu-pdf-v*.html` を探す。複数あれば、版の番号が一番新しいものを使う。無ければ、分かる文で知らせて終わる（メッセージボックス）。
  2. `[System.Uri]` で、パーセントエンコードした `file:///` の URL を作る。
  3. ブラウザを探す: Edge（`App Paths\msedge.exe` を HKCU → HKLM の順）→ Edge の既定の場所 → Chrome（`App Paths\chrome.exe`）→ Chrome の既定の場所。見つからなければ知らせて終わる。
  4. `Start-Process <ブラウザ> -ArgumentList "--app=`"<URL>`""` で開く。利用者の普段のプロファイルを使う（`--user-data-dir` は付けない。最近使ったファイルを引き継ぐため）。
- 黒い窓が一瞬で消えるようにする（`start "" /min` などで、cmd の窓が残らないようにする）。
- 試験のため、環境変数 `KARU_LAUNCHER_DRY_RUN=1` のときは、ブラウザを起動せず、使うブラウザのパスと `--app=` の値を標準出力に出して終わる。

### 2. `デスクトップにショートカットを作る.cmd`

- 1回だけ実行すると、デスクトップ（`[Environment]::GetFolderPath('Desktop')`。OneDrive への移動にも対応）に `かるPDF.lnk` を作る。スタートメニュー（`[Environment]::GetFolderPath('Programs')`）にも作る。
- ショートカットの中身（`WScript.Shell` の `CreateShortcut`）:
  - 対象: 見つけたブラウザの exe
  - 引数: `--app="<パーセントエンコードした URL>"`
  - 作業フォルダー: HTML のあるフォルダ
  - アイコン: 同じフォルダの `karu-pdf.ico`
  - 説明: かるPDF（固定・閉域版）
- 同じ名前のショートカットがあれば上書きする。作ったら、作った場所をメッセージボックスで知らせる。
- フォルダを移したら、もう一度実行する必要があることを、使い方に書く。
- `KARU_LAUNCHER_DRY_RUN=1` のときは、ショートカットを作らず、作る場所と中身（対象・引数・アイコン）を標準出力に出す。

### 3. アイコン `karu-pdf.ico`

- `public/icons/` の PNG から、16・32・48・256px の画像を入れた ICO を、Node の標準機能で作る（ICO の中に PNG をそのまま入れる形でよい。縮小が要る大きさは、MuPDF.js か、ブラウザを使わずにできる方法で作る。難しければ 256px と 48px だけでもよい。報告する）。

### 4. 普通のタブで開いたときの案内（HTML の版だけ）

- HTML の版を、アプリモードではなく普通のタブで開いたとき（`window.toolbar.visible === true` などで判断。判断の方法は実機で確かめる）、最初の画面（PDF を開く前の画面）に、小さく次の案内を出す:
  > 専用の窓で開くには、同じフォルダの「かるPDFを開く.cmd」か、デスクトップのショートカットを使ってください。
- 「今後表示しない」で消せる（localStorage に覚える）。PDF を開いた後の画面には出さない。
- 通常版・固定版には出さない（生成物を変えない）。

### 5. 配布物

- `release/karu-pdf-v1.0.0-single.zip` の一番上の階層に、次を置く: HTML、`かるPDFを開く.cmd`、`デスクトップにショートカットを作る.cmd`、`karu-pdf.ico`、`使い方.txt`、`LICENSE`、`THIRD_PARTY_LICENSES`、`VERSION.txt`、`SHA256SUMS.txt`、`SBOM.cdx.json`
- ZIP の中のファイル名に日本語を使うので、ZIP のファイル名の文字コードを UTF-8 の印（汎用目的のビットフラグの bit 11）付きで書く。Windows のエクスプローラーで展開して、ファイル名が化けないことを確かめる（PowerShell の `Expand-Archive` でも確かめる）。
- `SHA256SUMS.txt` に cmd と ico も入れる。
- 通信の監査（`audit:network`）の対象に、cmd を加える（ブラウザの起動のほかに、外部の URL や通信が無いこと）。

### 6. 使い方

- `使い方.txt` と `README.md` の HTML の版の節を、次の順に直す:
  1. ZIP を展開したフォルダを、自分の PC か共有フォルダに置く。
  2. 「デスクトップにショートカットを作る.cmd」を1回ダブルクリックする（デスクトップに「かるPDF」ができる）。
  3. 以後は、デスクトップの「かるPDF」から起動する。タブやお気に入りの無い専用の窓で開く。
  4. ショートカットを作らずに使うときは「かるPDFを開く.cmd」をダブルクリックする。HTML を直接ダブルクリックした場合は、普通のタブで開く（使えるが、タブなどが出る）。
  5. フォルダを移したら、もう一度 2. を行う。
  6. 組織のポリシーで cmd・PowerShell・file:// が禁止されている場合は使えないこと。

## テスト

- **Node の試験**（`tests/`。Windows で動かす。Windows 以外では飛ばす）:
  - 日本語と空白を含む一時フォルダ（例: `新しいフォルダー/karu pdf/`）に、HTML の版のダミーと cmd を置き、`KARU_LAUNCHER_DRY_RUN=1` で2つの cmd を実行する。
    - `--app=` の値が、パーセントエンコードした `file:///` の URL で、元のパスに戻すと HTML のパスと一致すること。
    - ブラウザのパスが実在する exe であること。
    - ショートカットの対象・引数・アイコン・作る場所が正しいこと。
  - `karu-pdf-v1.0.0.html` と `karu-pdf-v1.2.0.html` があるとき、新しい方を選ぶこと。HTML が無いときは失敗の知らせ（ドライランでは標準出力の文）になること。
  - ICO の形式（先頭のヘッダー、画像の数、各画像が PNG として読めること）。
  - ZIP の中のファイル名が UTF-8 の印付きで、展開すると日本語の名前が元どおりになること。
- **実機の確認（こちらで行う）**: アプリモードの窓で開くこと、ショートカットから開くこと。Codex のサンドボックスでブラウザの窓を開けない場合は、ドライランの試験までで止め、その旨を報告する。

## 禁止事項

- 対象外のファイルを変更しないこと。git の変更操作をしないこと。
- 新しい npm パッケージを加えないこと。
- 試験で、利用者の本物のデスクトップやスタートメニューにショートカットを作らないこと（ドライランを使う）。
- 自分で起動したサーバーやブラウザは必ず止め、一時ファイルは削除すること。
