## 目的

## 変更内容

1. `CountFixture` に任意の項目 `sample` を追加する: `{ png: string（base64）; width: number; height: number; pageIndex: number }`。`width`・`height` は画像の画素数。検証で、PNG の先頭バイト・画素数（各辺 16〜160）・base64 の長さ（1件 48 KiB まで）を確かめ、不正なものは読み込まない。器具リスト全体の上限を 1 MiB から 4 MiB に上げる。
2. 追加・編集の画面（`FixtureDialog`）に「図面から見本を切り取る」「見本を外す」を置く。
   - 「図面から見本を切り取る」を押すと、画面を一時的に閉じて「切り取る範囲を四角で囲んでください（Esc で中止）」と表示し、図面上で四角をドラッグして範囲を決める。Esc で中止すると、画面に戻る。
   - 範囲を決めたら、その範囲を既存の描画処理（Worker）で、長い辺が160画素になる倍率で描画し、PNG にする。注釈（書き込み）は含めず、PDF の本来の図面だけを描く。
   - 画面に戻り、見本の画像を表示する。保存（追加・更新）したときに器具へ記録する。
   - 小さすぎる範囲（例: 2mm 未満）は「範囲が小さすぎます」と表示してやり直させる。
3. 器具リストのタブ（`FixturePanel`）の各行で、印の見本の横に見本の画像を小さく（高さ 20px 程度）表示する。見本がない器具は空欄にする。行にマウスを載せたとき、見本を大きく（160px 以内）表示する。
4. 見本は器具リストと一緒に PDF に保存し、開き直すと戻る。複製すると見本も複製する。「他のPDFから読み込む」でも見本を写す。
5. 性能: 見本の画像は器具リストのタブを開いたときだけ表示する。通常の読込・表示に処理を足さない。切り取りの描画は1回だけ行い、結果を使い回す。

### 未使用の形・塗り・色の提案（2026-10-04 の追加要望）

利用者の要望:

> 器具の追加をする際には、まだ選定していない形、塗り、色を自動で提案するようにしたい。

現在の `nextCountStyle`（`src/core/countFixtures.ts`）は、決まった順の候補のうち「形・塗り・色の組合せが既存と完全に同じでないもの」を選ぶ。そのため、形がすでに使われていても提案されることがある（例: 見本を28種類追加した後の「器具を追加」で、使用済みの「丸」が提案された）。

6. `nextCountStyle` を次の規則に変える。
   - 既存の器具と形・塗り・色の組合せが完全に同じものは提案しない（今と同じ）。
   - 候補の点数を「その形を使っている器具の数＋その色を使っている器具の数＋その塗りを使っている器具の数」とし、点数の小さい候補を選ぶ。つまり、まだ使っていない形・色・塗りを優先する。
   - 点数が同じときは、今の決まった順（i番目の候補 = 形の一覧[i mod 14]、色見本[(i×7) mod 24]、塗りの一覧[floor(i / 14) mod 5]、尽きたら残りの組合せ）で先のものを選ぶ。結果は毎回同じになるようにする。
   - 大きさ・透明度・略号の表示の既定値は今と同じ。
7. 提案を使う場面:
   - 「器具を追加」の初期値。
   - 「複製」の初期値: 名称（「…のコピー」）・略号・分類・メモ・大きさ・透明度・略号の表示は元の器具から写し、形・塗り・色は提案で決める（同じ見た目の器具を作らないため）。
   - 「見本から追加」: 追加する器具を順に、それまでに決めた器具も含めて提案で決める。
   - 「他のPDFから読み込む」は、元の器具の形・塗り・色をそのまま使う（今と同じ）。
8. 追加・編集の画面に「別の組合せを提案」ボタンを置く。押すと、形・塗り・色を次の提案に替える（いま画面に出ている組合せと、編集中の器具自身の元の組合せは除く）。続けて押すと次々に替わる。
9. 試験: 見本の28種類を追加した後の提案が、未使用の形を使っていること。14種類を超えた後は、未使用の色・塗りを優先すること。「別の組合せを提案」で組合せが替わること。提案が既存と完全に同じ組合せにならないこと。
