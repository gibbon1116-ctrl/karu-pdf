## 目的

器具リストの印は、形（14種類）・塗り（5種類）・色（24色）の組合せで100種類以上を見分けるためのもの（利用者の要望）。ところが「二重丸・塗りつぶし」は、外側の丸の内部を全部塗り、内側の丸を同じ色の線で描くため、内側の丸が見えず「丸・塗りつぶし」と同じ見た目になる。SPEC-04f の提案でも、この2つは別の組合せとして扱われる。

Claude Code が実際の画面（`work/screens-04f/`）で確認した: 見本から追加した「BL ベースライト（直付）」（二重丸・塗りつぶし・紫）が、塗りつぶしの丸にしか見えない。

## 変更内容

`countMarkerData`（`src/editor/countMarkers.ts`）で、形が `doubleCircle` のときの塗りの図形だけを変える。

1. 塗り `solid`: 外側の丸と内側の丸（今の `regular(48, r * .68)`）の間の輪だけを塗る。`fills` に外側の丸と、**点の順を逆にした**内側の丸を入れる（巻き方向を逆にして、非ゼロ規則で内側を抜く）。内側は塗らない（紙の色のまま）。
2. 塗り `half`: 輪の左半分だけを塗る。`fills` に `leftHalf(外側の丸)` と、点の順を逆にした `leftHalf(内側の丸)` を入れる。
3. 塗り `none`・`dot`・`hatch` と、`doubleCircle` 以外の形は今と同じにする。外形の線（`outline`）・明るい色の濃い縁取り・略号の位置も今と同じにする。

この図形データは、画面の印（`CountMarker`）、1ページに印が多いときのまとめ描き（`src/editor/AnnotationLayer.tsx`）、PDF に保存する外観（`src/core/annotations.ts` の `drawCountMarker`）の3か所で共通に使っている。3か所とも塗りは非ゼロ規則（SVG の既定、MuPDF の `fillPath(path, false, …)`）なので、図形データを変えるだけで3か所とも輪になる。3か所のコードは変えない。

## 試験

`tests/countFixtures.test.ts` に次を追加する（既存の「creates common SVG/PDF geometry …」の書き方に合わせる）。

- `doubleCircle`・`solid` の `fills` が2つの多角形で、2つ目は内側の丸の点を逆の順にしたもの（巻き方向の符号付き面積が1つ目と逆）。
- 中心の点（印の中心）が塗られていないこと: `fills` を非ゼロ規則で判定する小さな関数（巻き数を数える）を試験の中に書き、中心の巻き数が0、外側の丸と内側の丸の間の点（例: 中心から半径 `r * .84` の点）の巻き数が0でないことを確かめる。`circle`・`solid` では中心の巻き数が0でない（今と同じ）ことも確かめる。
- `doubleCircle`・`half` でも、中心が塗られず、輪の左側の点は塗られ、右側の点は塗られないこと。
- 既存の試験がすべて通ること。
