## 目的

利用者が試用版 1.2.0 を実際の図面（電気設備図 144ページ）で試し、次を求めた（2026-10-04）。

> 器具を追加の画面をドラッグアンドドロップで動かせるようにしたい。書き込みの添付のドロップダウンを「未回答」「回答済み」「修正確認」の三種類にして、それぞれの色を変えてください。なお、修正確認の色は対応完了の「確認済み」の仕様にしてください。「指摘１の詳細」の改行がおかしいので直してください。また、指摘１の詳細がクリックして編集できることが分かりにくいので、編集可能と分かるような表示にしてください。「指摘１の詳細」をクリックしたとき、現在は書き込みタブの最上位の方に詳細記入画面が開きますが、「指摘１の詳細」をクリックしたら、その場で折りたたんだ表示が開くような形で、その場で編集画面が開くようにして下さい。

## 変更内容

### A. 指摘の状態を3種類にし、状態ごとに色を変える

1. 画面で選べる状態を3種類にする: `open`（未回答）・`answered`（回答済み）・`confirmed`（修正確認）。`src/core/issues.ts` に選択肢の一覧（例: `ISSUE_STATUS_CHOICES`）と、保存済みの値を3種類のどれかに読み替える関数（例: `issueStatusChoice(status)`）を作る。
   - 読み替え: `open`→未回答、`answered`→回答済み、`revised`（修正済）→回答済み、`done`（対応済（旧版））→回答済み、`confirmed`→修正確認。修正済と旧版の対応済は、修正の確認が済んでいない扱いにする（これまでの方針「旧 done を確認済と同一視しない」と同じ）。
   - `ISSUE_STATUSES`（読み込みで受け付ける値）は変えない。PDF に保存済みの `revised`・`done` は読めるままにし、開いただけで書き換えない（開いた直後に未保存の印を付けない）。利用者が状態を選び直したときだけ、新しい値（3種類のどれか）で保存する。
   - `unresolvedIssue`（未確認＝`confirmed` 以外）は変えない。
2. 表示の文言を `issueStatusLabel` でそろえる: 未回答・回答済み・修正確認。旧い値も読み替えた先の文言にする（CSV の「状態」の列も同じ）。
3. 色は状態だけで決める（`issueColor`）: 未回答＝赤 `[1, 0, 0]`、回答済み＝青 `[0, 0.25, 1]`（書式欄の色見本の「青」と同じ）、修正確認＝灰 `[.5, .5, .5]`（今の確認済と同じ）。図面上の印（画面の SVG と、保存した PDF の外観）、一覧の色の見本、CSV の「色」の列が、すべてこの色になる。
   - 状態で色が決まるので、書式欄の指摘の「色」の選択欄は出さない（`FormatPanel` の `simpleColorTarget` で指摘を除くなど）。代わりに「色は状態で決まります（未回答 赤・回答済み 青・修正確認 灰）」と短く表示する。
4. チェックの描画をやめる: `done` は回答済み（青）として表示するので、画面（`AnnotationLayer.tsx`）と PDF の外観（`drawIssue`）の `done` のチェックを描かない。
5. 状態の選択欄（書き込みタブの各指摘の行、書式欄の「状態」）の選択肢を3種類にする。値は読み替えた状態を表示する。選択欄自体も状態の色で見分けられるようにする（例: 文字の色と左の太い縁を状態の色にする。`data-status` 属性と CSS で指定）。
6. 絞り込みの文言を合わせる。
   - 書き込みタブの「状態で絞り込み」: すべて・未回答・回答済み・修正確認（読み替えた状態で絞る）。
   - 「書き込みの種類」の「指摘（確認済・旧対応済）」は「指摘（修正確認）」にし、`confirmed` だけを出す。「指摘（未確認）」は今のまま。
   - CSV の書き出し画面の状態: 「未確認だけ」は「未確認だけ（未回答・回答済み）」、「確認済だけ」は「修正確認だけ」に文言を変える（値と絞り方は今のまま）。
7. `IssueDetails` の旧い値の案内を直す: `done` または `revised` のとき「旧版で「対応済」または「修正済」とした指摘です。修正を確認したら「修正確認」にしてください。」
8. `HelpDialog` の指摘の説明（未回答・回答済・修正済・確認済、「対応済は灰色とチェック」）を、3種類と色の説明に直す。

### B. 一覧の「指摘 n の詳細」を直し、その場で開いて編集できるようにする

1. 折り返しの原因を直す: `.annotation-rows button` の指定を、行の本体のボタンだけに当てる（例: 行の本体のボタンに `annotation-row-main` を付け、`.annotation-rows .annotation-row-main` に変える。`:hover` も同じ）。
2. 状態の選択欄と詳細のボタンを、行の下に1行で並べる（例: `.issue-row-actions` の横並び。文字は折り返さない）。
3. 詳細のボタンを、押して開閉できる編集のボタンと分かる見た目にする。
   - 表示: 閉じているとき「✎ 詳細を編集 ▾」、開いているとき「✎ 詳細を閉じる ▴」。枠と背景のある普通のボタンの見た目にし、マウスを載せたときに色を変える。
   - `aria-expanded`、`aria-controls`（開く詳細の欄の id）を付ける。アクセシブルな名前は「指摘 n の詳細を編集」（表示中の「詳細を編集」を含む）。
4. 押したら、その指摘の行のすぐ下（同じ `li` の中）に詳細の編集欄（`IssueDetails`）を開く。もう一度押すと閉じる。一度に開くのは1件だけでよい（別の指摘を開くと前のものは閉じる）。開いた欄は、どの指摘のものか分かるように左に縁を付けて少し字下げする。
   - 一覧の上に詳細を開く今の表示はやめる。
   - 開いたときは、今と同じくその指摘を図面で選び（`onSelect`）、開いた欄が一覧の中で見えるようにスクロールする（`scrollIntoView({ block: 'nearest' })`）。
   - `IssueDetails` の「詳細を閉じる」ボタンは残す。
   - 入力中に一覧が描き直されても、入力欄のフォーカスと入力中の文字が失われないこと。

### C. 器具の追加・編集の画面をドラッグで動かせるようにする

1. `FixtureDialog` の見出し（「器具を追加」「器具を編集」）をつかんでドラッグすると、画面全体が動く。見出しはマウスを載せると移動のカーソル（`cursor: move`）になり、見出しの左に握りの印（例: `⠿`、`aria-hidden`）を付ける。`title` は「ドラッグして移動できます」。
2. 動かし方: ポインターのドラッグ（`setPointerCapture`）で、ダイアログを `translate` で平行移動する。見出しが画面の外に出ないように制限する（見出しの上下は画面内、左右は少なくとも 80px が画面内）。ウインドウの大きさが変わったときも制限し直す。
3. 動かした位置は、アプリを開いている間は覚えておき、次に「器具を追加」「複製」「編集」で開いたときも同じ位置に出す（画面の外に出る場合は制限した位置にする）。保存はしない（再読込で中央に戻る）。
4. 「図面から見本を切り取る」で一時的に閉じて戻ったときも、同じ位置のまま。
5. 入力欄・ボタンの操作、Esc で閉じる動作は今と同じ。見出し以外をドラッグしても動かない（文字の選択などを妨げない）。

## 試験

- 単体試験（`tests/`）:
  - 5つの保存値それぞれの読み替え（選択肢・文言・色）。`revised`・`done` は回答済み・青、`confirmed` は修正確認・灰、`open` は未回答・赤。
  - CSV の「状態」「色」の列が読み替えた文言と色になる。既存の試験の期待値（`done` の色・文言など）は、この SPEC の仕様に合わせて直す。
  - `parseIssue` が `revised`・`done` を読めるままであること（値は書き換えない）。
- 画面試験（`e2e/`）:
  - 各指摘の状態の選択欄の選択肢が3つ（未回答・回答済み・修正確認）で、選ぶと一覧の色の見本と図面上の印の色が赤・青・灰に変わる。保存して開き直すと状態が残り、保存した PDF の外観の色も変わっている（Node 側の MuPDF で外観の色を確かめるなど、既存の試験の書き方に合わせる）。
  - `done`・`revised` の指摘を含む PDF を開くと、選択欄は「回答済み」、色は青で、開いただけでは未保存の印が付かない。
  - 「詳細を編集」のボタンが1行で表示される（ボタンの高さが1行分）。押すと `aria-expanded` が true になり、その指摘の `li` の中に詳細の欄が開く。一覧の上には開かない。入力した分野・回答などが保存される。もう一度押すと閉じる。
  - 器具の追加の画面の見出しをドラッグすると、ドラッグした分だけ動く（±2px）。閉じて開き直しても同じ位置。画面の外へ大きくドラッグしても見出しが画面内に残る。動かした後も名称の入力と追加ができる。
  - 既存の画面試験（`e2e/cloud-issues.annotate.spec.ts`、`e2e/businessCases.ts` など）で、`selectOption('done')`・「指摘 n の詳細」のボタン名など、この SPEC で変わる部分を新しい仕様に合わせて直す。試験の意図（状態の変更・詳細の保存など）は残す。
