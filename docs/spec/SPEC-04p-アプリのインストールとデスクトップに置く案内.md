## 目的

利用者の要望（2026-10-05）:

> https://gibbon1116-ctrl.github.io/karu-pdf/ にアクセスしてアドレスバーの「アプリを開く」をクリックしたとき、デスクトップ上にアプリを保存するかどうかの選択肢を出すようにしたい。

アドレスバーのボタンと、そこから出る画面は Edge のもので、サイトの側から選択肢を足すことはできない。利用者と相談し、**アプリの中に「インストール」と「デスクトップに置く手順」の案内を作る**ことにした。

## 現状（Claude Code が確認したこと）

- 通常版（GitHub Pages）と固定版は PWA（`vite.config.ts` の `VitePWA`。`manifest` は `id`・`start_url`・`scope` が配布パス、`display: 'standalone'`、`file_handlers` で PDF）。単一HTML版は `file://` で開くので PWA ではなく、専用の窓で開く起動ファイル（`scripts/launchers/` の .cmd）と案内（`src/single/LauncherHint.tsx`）がある。
- アプリはインストールの仕組みを使っていない（`beforeinstallprompt`・`appinstalled` を扱うコードはない）。
- Edge の動き（Microsoft の説明。<https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/whats-new/pwa>、<https://support.microsoft.com/ja-jp/edge/install-manage-or-uninstall-apps-in-microsoft-edge>）:
  - インストールした後、アプリを初めて開いたとき、Edge が「タスク バーにピン留めする」「スタート画面にピン留め」「デスクトップ ショートカットを作成します」「デバイス ログインの自動開始」を選ぶ画面を1回だけ出す。
  - インストール済みのアプリは、`edge://apps` を開き、アプリの「詳細」→「デスクトップ ショートカットを作成します」でデスクトップに置ける。
- Web ページから `edge://apps` を開くことはできない。外部への送信の見張り（SPEC-04o）は、`edge:` などのURLを外部として扱う。案内では開かず、アドレスをコピーするだけにする。

## 変更内容

### 1. インストールの状態（`src/app/installApp.ts`）

- `beforeinstallprompt` を、アプリのモジュールを読み込んだ時点で受け取れるように聞く。イベントは `preventDefault()` して保存し、「インストールできる」状態にする。
- `promptInstall()`: 保存したイベントの `prompt()` を呼び、`userChoice` を待って結果（承認・取消し）を返す。イベントは1回しか使えないので、呼んだら保存を消す。
- `appinstalled` を受けたら「インストールした」状態にし、端末に印を残す（例: `localStorage` の `karu-pdf:installed-via-app`）。この印があると、アプリの窓での最初の問いかけ（3）は出さない（Edge が自分の画面で同じ選択肢を出すため）。
- アプリの窓で開いているかは表示モード（`display-mode: standalone`・`window-controls-overlay`・`minimal-ui`）で判定する。
- 状態は購読できる形（`subscribe`・`getSnapshot`）にし、画面は `useSyncExternalStore` で読む。`localStorage` が使えない環境でも例外で止まらないこと。

### 2. インストールの案内（ブラウザーのタブで開いていて、インストールできるときだけ）

- 起動画面（`StartScreen`）に「アプリとしてインストール」のボタンと、短い説明を出す: 「インストールすると、専用の窓で開けます。インストールの後に初めて開いたときに、Edge が『デスクトップ ショートカットを作成します』などを選べる画面を出します。」
- 「ヘルプ」メニューに「アプリとしてインストール…」を足す（インストールできないときは使えない表示）。
- 押すと `promptInstall()` で Edge のインストール画面を出す。インストールしたら、ボタンとメニューの項目を消し、状態欄に「インストールしました。デスクトップに置くかどうかは、アプリを初めて開いたときに Edge が出す画面で選べます。」と出す。

### 3. アプリの窓で初めて開いたとき（端末ごとに1回）

- アプリの窓（表示モードが standalone など）で開き、まだ聞いていない（`localStorage` の印がない）とき、画面の上に帯で「デスクトップにかるPDFを置きますか？」と出す。ボタンは「置く手順を見る」「置かない」。どちらを押しても、聞いた印を残して帯を消す。PDF の表示や操作を妨げない帯にする（モーダルにしない）。
- `karu-pdf:installed-via-app` の印があるとき（アプリの中の案内からインストールしたとき）は出さない（聞いた印だけ残す）。

### 4. デスクトップに置く手順の画面

- 「ヘルプ」メニューに「デスクトップにアプリを置く手順…」を足す（いつでも開ける）。3 の「置く手順を見る」でも開く。
- 内容（Edge）:
  1. Edge のアドレスバーに `edge://apps` と入力して開きます。［アドレスをコピー］（`navigator.clipboard.writeText('edge://apps')`。使えないときは文字を選んだ状態にして、手でコピーするよう案内する）
  2. 「かるPDF」の「詳細」を選びます。
  3. 「デスクトップ ショートカットを作成します」を選びます。
- まだインストールしていない場合（タブで開いていて、インストールできる場合）は、先に「アプリとしてインストール」を案内し、ボタンも置く。
- Chrome の場合（`navigator.userAgentData` の銘柄で Edge でないと分かる場合）は、`chrome://apps` を開き、かるPDF を右クリック →「ショートカットを作成」→「デスクトップ」を選ぶ手順を出す。分からない場合は Edge の手順を出す。
- 画面のページを移動させない（`edge://`・`chrome://` を開こうとしない）。

### 5. 配布形態

- 通常版と固定版で動かす。単一HTML版（`file://`）には PWA がないので、インストールの案内とヘルプの2項目を出さない（配布形態の印 `/* @single */` などで出し分けるか、単一HTML版では表示しない判定にする。既存の起動ファイルの案内はそのまま）。

### 6. ヘルプ

- `HelpDialog` に1段落を足す: アプリとしてインストールすると専用の窓で開けること、インストール後に初めて開いたときに Edge がデスクトップ ショートカットなどを選べる画面を出すこと、後からは「ヘルプ → デスクトップにアプリを置く手順…」（`edge://apps` →「詳細」→「デスクトップ ショートカットを作成します」）で置けること。

## 試験

- 単体試験（`tests/`）: 偽の `window` で、`beforeinstallprompt` を受けると「インストールできる」状態になり、`promptInstall()` が `prompt()` を1回だけ呼び、結果を返すこと。`appinstalled` で印が残り、状態が変わること。表示モードの判定。アプリの窓での最初の問いかけを出す条件（印の有無）。`localStorage` が例外を投げても止まらないこと。
- 画面試験（`e2e/`、通常版）:
  - 偽の `beforeinstallprompt`（`prompt` と `userChoice` を持つイベント）を送ると、起動画面に「アプリとしてインストール」が出て、押すと偽の `prompt` が呼ばれる。`appinstalled` を送ると、ボタンが消えて状態欄に案内が出る。
  - 表示モードを standalone にした状態（`addInitScript` で `matchMedia` を差し替える）で開くと、帯「デスクトップにかるPDFを置きますか？」が出る。「置く手順を見る」で手順の画面が開き、`edge://apps` と3つの手順が出る。「アドレスをコピー」でクリップボードに `edge://apps` が入る（権限を与えるか `navigator.clipboard` を差し替える）。再読込すると帯は出ない。`karu-pdf:installed-via-app` があると帯は出ない。
  - 外部への送信の警告が出ないこと（ページの移動をしない）。
- 単一HTML版の既存の画面試験が通り、インストールの案内とヘルプの2項目が出ないこと。
- 既存の単体試験・画面試験がすべて通ること。
