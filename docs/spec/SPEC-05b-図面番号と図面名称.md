- 選定理由: Worker での文字の読み取り（裏で動かす長い処理）、候補の判定の考え方、PDF のページへの保存、ページ操作との整合、画面にまたがる新機能のため（判定表「新規機能の実装」）

## 目的

利用者の改修指示書（2026-10-06）の 3・4 と、利用者の回答:

- 各ページの**図面番号**（例 `E-101`）と**図面名称**（例 `1階 電灯設備平面図`）を、PDF の文字から読み取る。OCR は使わない。
- 表記の揺れ（`A-101`・`A101`・`E-101`・`E101`・`M-101`・`S-001`、全角・半角、いろいろなハイフン）を考える。
- 読み取れないときは無理に推測せず「未設定」にする。
- 利用者が手で直せる。手で直した値は、その後の読み取りで上書きしない。
- 図面番号・図面名称は**ページの属性**として扱い、数量の所在の一覧・ページへの移動・数量 CSV・ページの整理で使う（一覧・CSV は SPEC-05d）。ページの並べ替え・削除・追加・抽出・分割をしても、ページとの対応を壊さない。保存して開き直しても残る。
- **読み取りの時期**（利用者の回答）: その PDF で**数量タブを初めて開いたとき**に、裏で全ページを読む（画面は止めない）。結果は PDF に保存し、次からは読まない。「読み直す」ボタンも置く。数量拾いを使わない通常の閲覧は、今のまま（全ページの文字の読み取りを足さない。AGENTS.md の方針）。

## 変更内容

### 1. データ（`src/core/drawingInfo.ts`）

```ts
export interface DrawingInfo {
  number?: string          // 図面番号。無ければ未設定
  name?: string            // 図面名称。無ければ未設定
  numberManual?: boolean   // 利用者が手で決めた（自動の読み取りで上書きしない）
  nameManual?: boolean
  scanned?: boolean        // 自動の読み取りを済ませた（何も見つからなくても true）
}
```

- ページの辞書の `/KaruDrawing` に JSON の文字列で保存する（`version: 1` を入れる。2KB まで。文字列は 80 文字まで）。読めない・壊れているときは「無い」として扱う。
- 開くときに、`pageScales` と同じ形で全ページ分を読み、画面へ渡す（ページの辞書のキーを1つ見るだけ。文字は読まない）。
- `AnnotationStore` に、縮尺と同じ持ち方で `getDrawingInfo(pageIndex)`・`setDrawingInfo(pageIndices, info)`（手での変更。`Ctrl+Z` で戻せる。文書を変更ありにする）を足す。保存のときに書き込みの流れで `/KaruDrawing` を書く。
- **自動の読み取りの結果**は、取り消しの履歴に積まない。文書を「変更あり」にもしない（自動の結果だけで閉じるときに保存を聞かない）。ただし、次に保存したときには一緒に PDF へ書く。手で決めた欄（`numberManual`・`nameManual`）は、自動の結果で決して上書きしない。

### 2. 候補の判定（`drawingInfo.ts`）

入力は、1ページの行（文字・位置・向き）とページの大きさ・回転。出力は図面番号・図面名称（それぞれ見つからなければ無し）と、判定の理由（試験と調査のため）。

**文字の正規化**: 全角英数字→半角、`‐ - – — − ー －` などのハイフンの類→`-`、前後と途中の余分な空白を詰める。

**図面番号の候補**:
- 形: 英字1〜3字 ＋（ハイフン有り無し）＋ 数字2〜4桁 ＋（任意で `-` と英数字1〜3字）。例 `E-101`・`E101`・`A-101`・`S-001`・`EM-201`・`E-101-1`。正規化した表記を保存する（`E101` は `E101` のまま。ハイフンを勝手に足さない）。
- 点数を付けて最も高いものを選ぶ。
  - 「図面番号」「図番」「図 番」「DWG No」「図面No」などの見出しの**同じ行の右か、すぐ下の行**にある: 大きく加点。
  - 表題欄らしい位置（表示の向きで、ページの右下の4分の1。回転したページでは、見えている向きで判定する）: 加点。ページの下の端に近いほど加点。
  - 文字の大きさ（行の高さ）が周りより大きい: 少し加点。
  - 通り芯の記号（`X1`・`Y12` のような英字1字＋数字1〜2桁で、ページの端に並ぶもの）、機器の記号らしいもの（数字が1桁）は除く。
- **ページをまたいだ判定**（全ページを読み終えた後に行う）: 多くのページで同じ形（英字の部分と数字の桁数）の候補が選ばれていれば、その形に合う候補を優先する。逆に、**全ページでまったく同じ値**の候補（工事番号など）は図面番号から外す。
- 点数が基準に満たないときは「無し」（推測しない）。

**図面名称の候補**:
- 「図面名称」「図名」「図面名」「名称」などの見出しの右か、すぐ下の行: 大きく加点。
- 「平面図」「立面図」「断面図」「詳細図」「系統図」「配置図」「展開図」「姿図」「結線図」「配線図」「リスト」「凡例」「特記仕様書」「図」で終わる行: 加点。
- 図面番号の近く（表題欄の中）にある: 加点。
- 長すぎる行（40文字を超える）、注記の文（「。」を含む）は除く。
- 見出しの文字そのもの（「図面名称」）は名称にしない。
- 点数が基準に満たないときは「無し」。

**判定の基準**は、試験用の PDF と、実際の図面 `test-data/real/七ヶ浜町_実施設計図.pdf`（30ページの実施設計図。`test-data/shichigahama-drawing.pdf` と同じもの）、`test-data/real/UR_電気設備標準詳細設計図集_R3.pdf`、`test-data/real/設備工事標準図_電気_R7.pdf` で調整する。これらは Git の管理外で、手元の測定・調整にだけ使う（試験のコードから必須にしない。無ければ飛ばす）。各 PDF で、目で確かめた正解と比べた認識の結果（正しく読めたページ・誤って読んだページ・未設定のページの数）と、どの基準にしたかを報告する。**誤って読むより未設定の方がよい**（誤読を減らすことを優先する）。

### 3. 読み取りの時期と進め方

- その文書で**数量タブを初めて開いたとき**、`scanned` でないページがあれば、裏で読み取りを始める。読み取り済みのページは読まない。
- Worker では、ページを1枚ずつ読み、1枚ごとに他の依頼（表示・操作）を先に通す（今の依頼の優先順位の仕組みに乗せ、表示より低くする）。読み取りの途中で文書を閉じたら止める。
- 数量タブに進み具合を出す: 「図面番号・図面名称を読み取っています（12 / 30 ページ）」。終わったら「図面番号・図面名称を読み取りました（認識 28 / 30 ページ）」。
- 数量タブに「図面番号・図面名称を読み直す」ボタンを置く。押すと、手で決めた欄を除いて、全ページを読み直す（ページをまたいだ判定もやり直す）。
- 読み取りは、ページを表示するための描画や、文字の選択のための読み取りの仕組みと結果を共有してよいが、通常の読込・表示の処理には何も足さないこと。

### 4. 表示と手での変更

- **ページタブのサムネイル**: ページ番号の下に図面番号を出す（あれば）。`title` に「E-101 1階 電灯設備平面図」。
- **下の帯**（ページ番号の横）: 今のページの図面番号・図面名称を出す（例「E-101 1階 電灯設備平面図」）。無ければ出さない。クリックで変更の画面を開く。
- **変更の画面**（小さなダイアログ）: 図面番号・図面名称の入力欄。
  - 入力して決定すると、その欄を手で決めたもの（`…Manual: true`）にする。
  - それぞれの欄に「自動に戻す」を置く。押すと手の印を外し、自動の値（あれば）に戻す。
  - ページタブのサムネイルの右クリック（今の右クリックの項目があれば、そこに「図面番号・図面名称を変更…」を足す）からも開ける。
- 未設定のときは、画面では「未設定」と出す（試験では、値が無いことを確かめる）。

### 5. ページ操作との整合

- 並べ替え・削除・白紙の追加: ページの辞書に付いているので、ページと一緒に動く。画面の `AnnotationStore` の図面情報も、縮尺と同じように、整理の後に読み直す（SPEC-04n の `finishPageLayout` の流れ）。
- 他の PDF から足したページ、抽出・分割の出力: `graftPage` で `/KaruDrawing` が写るかを試験で確かめる。写らない場合は、写した後に `/KaruDrawing` をそのページへ書き写す処理を足す（写さない理由が無い限り、図面情報はページに付いて回るようにする）。
- 白紙の追加や、図面情報の無い PDF から足したページは「未読み取り」のまま。次に数量タブを開いたとき（または「読み直す」）に、そのページだけ読む。

## 動作の軽さ（必須）

- 通常の読込で増えるのは、ページの辞書のキーを1つ見ることだけ（縮尺と同じ）。文字は読まない。
- 読み取りは数量タブを開いたときと、ボタンを押したときだけ。画面を止めない。表示・拡大・スクロールの描画を待たせない。
- 再描画のたびに判定し直さない（結果を持つ）。
- `heavy-300p.pdf` と試験用の図面で、読み取りにかかる時間（全ページ、1ページあたり）と、読み取り中のスクロールのフレーム間隔の p95 を1回測って報告する。

## 禁止事項

- 通常の読込・表示に、全ページの文字の読み取りや判定を足さないこと。OCR を使わないこと。
- 読み取れないときに推測で値を入れないこと。手で決めた値を自動で上書きしないこと。
- 既存の保存の形（書き込み・縮尺・数量拾い）を壊さないこと。
- 対象外のファイルを変更しないこと。git の変更操作をしないこと。python・pytest は使わない。
