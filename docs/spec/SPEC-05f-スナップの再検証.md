## 目的

利用者の改修指示書（2026-10-06）の 18:

> 既存 SPEC-02i では性能への影響を理由として「図面の線へのスナップを作らない」という判断があります。今回、その判断を現在の実装・性能を前提に再検証してください。最初から全面実装する必要はありません。（中略）今回の要求は「スナップを必ず全部実装」ではなく「実測に基づいて実用範囲を決める」ことです。

比べるもの:

| 記号 | スナップ先 |
|---|---|
| A | 既存の数量拾い・計測・書き込みの頂点 |
| B | PDF の図面の線（ベクター）の端点 |
| C | PDF の図面の線の上（最も近い点） |
| D | 線どうしの交点（実用的なら） |

最重要の条件:

- スナップを足しても、通常の操作の速さを悪くしない。**スナップがオフなら、今とほぼ同じ処理の重さ**であること。
- マウスが動くたびに、全ページの解析・PDF の再解析・React の state の大量の更新をしない。
- 目安: 操作中のフレーム間隔の p95 が 20ms 程度以下（`e2e/measure.perf.spec.ts` の基準と同じ）。
- 性能を満たせないものは作らない（例: A と B は採用、C・D は不採用、という結論でよい）。

## 進め方（2つの段）

### 第1段: 試作と実測（作業用。採否を決めるため）

1. **線の取り出し**: Worker で、1ページの図面の線分を取り出す関数を作る（MuPDF の表示リストを、線を描く命令だけを受け取る自前の装置（Device）で歩く。曲線は短い線分に分ける。塗りの輪郭は除くか含めるかを試して決める。書き込み（注釈）は除く）。結果は、ページの座標の線分の配列（`Float32Array` で `x1,y1,x2,y2` の並び）にして画面側へ送る。上限（例: 1ページ 200,000 本）を決め、超えたら打ち切って「線が多すぎるためスナップしない」とする。
2. **空間の索引**: 画面側（または Worker 側）で、ページを格子に分けた索引（格子の大きさは試して決める）を作り、「点から一定の距離にある端点・線分」を探せるようにする。交点（D）は、近くの格子の線分どうしだけで、カーソルの近くだけを計算する方式を試す。
3. **実測**（Edge、`npm run build` の配布物で。測定中は他の重い試験を動かさない）:
   - 図面: `test-data/real/七ヶ浜町_実施設計図.pdf`（実際の CAD 出力の図面。無ければ `test-data/shichigahama-drawing.pdf`）の、線の多いページ（平面図など）を3枚。`test-data/heavy-300p.pdf` の A1 のページ。
   - 測るもの: 1ページの線の取り出しの時間と本数、送る量、索引を作る時間、使う記憶の量、1回の探索の時間（A・B・C・D それぞれ、p50・p95）、400% に拡大して面積を 20 点置く間のフレーム間隔の p95（`e2e/measure.perf.spec.ts` と同じ操作。スナップ オフ・A だけ・A+B・A+B+C・A+B+C+D の5通り）、スナップ オフのときに今と差が無いこと。
   - 結果を `docs/調査/スナップの再検証.md` に書く（Codex が書いてよい唯一の docs のファイル）。表で、各方式の数値と採否、採否の理由を示す。
4. **採否の基準**（この基準で決めること。迷うときは不採用）:
   - 線の取り出しと索引作り: 1ページあたり 500ms 以下（Worker で行い、画面は止めない）。
   - 1回の探索: p95 で 1ms 以下。
   - 操作中のフレーム間隔の p95: 20ms 以下。スナップ オフとの差が 2ms 以下。
   - 記憶の量: 1ページあたり 50MB 以下。

### 第2段: 採用したものを作る

採用した方式だけを、次の決まりで作る。不採用の方式のための線の取り出しなどは残さない（試作のコードは消す）。

- **使う場面**: 計測（距離・連続した長さ・面積）、数量拾いの長さ・面積・体積、縮尺の「なぞって合わせる」。個数の印や、ふつうの図形・書き込みの道具には使わない。
- **入切**: 道具の段（ズームの近く）に「スナップ」の切替ボタンを置く。**既定はオフ**。状態は覚える（`localStorage`。読み書きは `try/catch`）。上の場面でだけ押せる。`Alt` を押している間は、一時的に効かせない。
- **吸い付く距離**: 画面で 8px 以内（拡大率に合わせてページの座標に換える）。候補が複数あるときの優先: 頂点（A）→ 端点（B）→ 交点（D）→ 線の上（C）。
- **表示**: 吸い付いた点に小さな印（頂点・端点は四角、交点は ×、線の上は △）を出す。マウスの動きごとに React の state を更新しない（今の計測と同じく、ref で SVG を書き換える）。
- **線の取り出しの時期**: スナップがオンで、上の場面の道具を選んでいるときに、表示中のページの分だけ、初めて必要になったときに Worker で取り出す（ページごとに結果を覚える。文書を閉じたら捨てる）。取り出しが終わるまでは、A だけで吸い付く。スナップがオフのときは何もしない。
- **計算の場所**: マウスが動くたびに Worker へ問い合わせない（往復で遅れるため）。索引は画面側に持つか、探索だけを画面側で行えるようにする。
- `Shift` の角度そろえ（水平・垂直・45°）と同時のときは、角度そろえを先に行い、その線の上で吸い付ける点があれば吸い付く（無ければ角度そろえだけ）。

- **単体（`tests/snap.test.ts`）**: 索引の探索で、決めた距離の内の頂点・端点・線の上の最も近い点・交点が見つかること、距離の外では見つからないこと、優先の順。
