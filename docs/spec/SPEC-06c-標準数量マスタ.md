- reasoning effort: `high`
- 選定理由: 新しいデータ・新しい画面・既存の見本の画面と多数の e2e の置き換えにまたがり、遅延読み込みで通常の表示に影響を出さないことが条件のため（判定表「新規機能の実装」「複数ファイルにまたがる改修」）

## 目的

利用者の指示（要約）:

- 数量拾いの項目は、利用者が毎回名称・規格を打つのではなく、**かるPDF に最初から入っている標準マスタから選ぶ**のを基本にする。
- 今の見本は「EM-CE」「CV」「PF」など**種類**単位で粗い。実際に拾うときに選ぶ**規格**単位（例: `EM-CE 5.5sq-3C`、`PF22`、ケーブルラック `W300`、`SGP-VB 25A`、角ダクト `400×250`）まで持たせる。
- 数百〜数千の候補になっても、**全候補を PDF の項目として登録しない**。標準マスタは軽い静的データとして持ち、利用者が選んだものだけを今の PDF の項目に足す。
- 検索を付ける（例: `60` で `EM-CE 60sq-3C`・`CV 60sq-3C` などを絞り込む）。通常の表示に影響を出さない。
- 規格は人が探しやすい自然な順（2 → 3.5 → 5.5 → 8 → 14 → 22 → 38 → 60 …）。文字列の並べ替えで 14 → 2 → 22 のようにしない。

## 変更内容

### 1. データの形（`src/core/quantityMaster.ts`）

```ts
import type { FixturePreset, QuantityKind, QuantityMethod, QuantityDefaults } from './countFixtures'
export interface MasterType {
  field: string        // 分野: 電気設備 / 機械設備 / 建築 / 仮設・土工
  category: string     // 分類: 項目の category にそのまま入れる
  type: string         // 種類の見出し（例 'EM-CE'）
  name: string         // 名称（項目の name）
  kind: QuantityKind; method: QuantityMethod; defaults?: QuantityDefaults
  code: string         // 略号
  codeFromSpec?: 'concat' | 'replace'  // 'concat': code = code + spec, spec = ''（電線管 PF22 など）。'replace': code = spec, spec = ''（同軸 S-5C-FB など）
  specs: readonly string[]  // 規格。この配列の順がそのまま表示の順。空配列なら規格なしの1件
}
export interface MasterEntry extends FixturePreset { key: string; field: string; type: string; search: string }
export const QUANTITY_MASTER: readonly MasterType[]
export function masterEntries(): readonly MasterEntry[]          // 初回だけ展開して以後は同じ配列を返す
export function searchQuantityMaster(query: string, limit = 200): { entries: MasterEntry[]; total: number }
export function normalizeMasterText(text: string): string
```

- `MasterEntry` は `FixturePreset` として `addMany` にそのまま渡せる形にする: `category`・`code`・`spec`（無ければ省く）・`name`・`kind`（`count` のときは省いてよい）・`method`・`defaults`・`aggregation`（`count` → `'location'`、それ以外 → `'document'`）。
- `key` は `field/category/type/spec` から作る一意の文字列。`search` は検索用に正規化した `field category type code spec name` の文字列。
- 展開は `QUANTITY_MASTER` の並び（分野 → 分類 → 種類 → 規格の配列の順）のまま。並べ替えない。
- 規格の生成に関数を使ってよい（例: CV の「太さ × 心数」）。その場合も生成した順が自然な順になるようにする。

### 2. 検索

- `normalizeMasterText`: NFKC → 小文字 → 空白を除く → `×`・`*` を `x` に、`φ`・`Φ`・`ø` を `φ` にそろえる、`ｓｑ`（全角）も NFKC で `sq` になる。
- `searchQuantityMaster(query)`: 問い合わせを空白で区切った語（それぞれ正規化）が**すべて** `search` に含まれる項目を、マスタの順で返す。`limit` 件まで `entries` に入れ、`total` に全件数。空の問い合わせは `{ entries: [], total: 0 }`。
- 例: `60` → `CV 60sq-1C`…、`EM-CE 60sq-3C`、`CVT 60sq`、`IV 60sq` など。`em-ce 60` → `EM-CE 60sq-…` だけ。`pf22` → `PF22`。`400x250` → 角ダクト `400×250`。

### 3. 標準マスタのデータ

下の表をそのまま入れる（名称・略号・規格の表記もこのとおり）。`m`＝長さ（`kind: 'length'`, `method: 'polyline'`）、`囲む`＝面積（`area`・`polygon`）、`長さ×高さ`＝面積（`area`・`lengthHeight`）、`囲む×深さ`＝体積（`volume`・`polygonDepth`）、`長さ×幅×深さ`＝体積（`volume`・`lengthWidthDepth`）、`個`＝個数（`count`・`click`）。

### 4. 画面（`FixturePresetDialog.tsx`）

- 数量タブのボタン「見本から追加」を「**標準マスタから追加**」に名前を変える。開くダイアログの `aria-label`・見出しも「標準マスタから追加」。
- ダイアログの上に2つのタブ（`role="tab"`）: 「**規格から選ぶ**」（既定）と「**分野の一式**」。
  - 「分野の一式」: 今の見本の画面そのもの（`aria-label="見本の分野"` の select、`FIXTURE_PRESETS` のチェックボックスの一覧、すべて選んだ状態で始まる、「選んだ項目を追加」）。動作を変えない。
  - 「規格から選ぶ」:
    - 上に検索欄（`aria-label="標準マスタを検索"`、開いたときにフォーカス）。
    - 検索欄が空のとき: 分野（ボタン）→ 分類（ボタン）→ 種類（ボタン。規格の件数を添える）を選ぶと、その種類の規格をチェックボックスで並べる（「すべて選ぶ」「選択を解除」ボタン付き）。最初は 電気設備 → 最初の分類 → 最初の種類 を選んだ状態。
    - 検索欄に文字があるとき: `searchQuantityMaster` の結果を平らに並べる（最大 200 件。`total` が多ければ「ほか N 件。言葉を足して絞り込んでください」）。
    - 1行: チェックボックス + `fixtureCode` + 名称 + 種別・単位（今の見本の画面と同じ表記の「（長さ・m）」など）。今の PDF にすでにある項目（略号・規格・名称が同じ）はチェック済みで無効にし「追加済み」と出す。
    - 選んだものは、分類・種類の切り替えや検索をまたいで保たれる。下に「選んだ項目を追加（N件）」。0件なら無効。
    - 1つの種類の規格が多くても、描くのは選んだ種類の規格か検索の結果だけ（全候補を常に描かない）。
- 「選んだ項目を追加」は `addMany`（今の処理）に `MasterEntry` を渡す（`key`・`field`・`type`・`search` は項目に入れない）。追加後、最初に足した項目を選び（`store.selectFixture`）、状態欄に「N件を追加しました」。
- 標準マスタのデータは、「規格から選ぶ」を開いたときに `import('../core/quantityMaster')` で読む（読み込み中は「標準マスタを読み込んでいます…」）。`FixturePresetDialog.tsx` の先頭で静的に import しない（ダイアログ自体は lazy だが、後の段階で別の画面からも動的に読むため）。
- 「他のPDFから読み込む」（`sources` あり）の画面は今のまま（タブを出さない）。
- 幅の狭い画面では分野・分類・種類・規格を縦に積む。

## テスト

### 単体（新規 `tests/quantityMaster.test.ts`）

- 展開: 件数が 500 件以上。`key` が一意。すべての項目が `addMany` に渡せる形（`kind`・`method` の組が `QUANTITY_METHODS` に合う、`aggregation` が種別どおり）。
- 自然な順: EM-CE の規格の並びが `2sq-2C, 2sq-3C, 2sq-4C, 3.5sq-2C, …` で、太さが 2 → 3.5 → 5.5 → 8 → 14 → 22 → 38 → 60 → 100 の順に出てくる。PF の略号が `PF14, PF16, PF22, PF28, PF36, PF42` の順。
- `codeFromSpec`: `PF22` は `code: 'PF22'` で `spec` なし、同軸は `code: 'S-5C-FB'`。
- 検索: `60` に `EM-CE 60sq-3C` と `CV 60sq-3C` が入る。`em-ce 60` は EM-CE だけ。`pf22` → `PF22`。`400x250` と `400×250` が同じ結果。全角の `６０ｓｑ` でも当たる。空は 0件。
- 速さ: 展開後、`searchQuantityMaster('60')` を 100 回の中央値が 5ms 未満（`performance.now()`）。初回の展開が 50ms 未満。
- 仮設・土工の今の8件が、`FIXTURE_PRESETS['仮設・土工']` と同じ略号・名称・種別・初期値で入っている。

### 画面（新規 `e2e/quantity-master.annotate.spec.ts`）

白紙1ページを開き、数量タブ →「標準マスタから追加」:

1. 検索欄にフォーカスがある。`60` と打つ → `EM-CE 60sq-3C` と `CV 60sq-3C` が見える。2つにチェック → 「選んだ項目を追加（2件）」→ 数量タブの一覧に `EM-CE 60sq-3C`（名称 600V架橋ポリエチレン絶縁耐燃性ポリエチレンシースケーブル）が分類「ケーブル（低圧）」の中に出る。Ctrl+Z で2件とも消え、Ctrl+Y で戻る。
2. もう一度開き、検索を空にして 電気設備 → 電線管 → PF を選ぶ → `PF16`・`PF22` にチェック → 追加 → 一覧に `PF16`・`PF22`。もう一度開くと `PF16` は「追加済み」で無効。
3. 規格から選んだ長さの項目でそのまま経路を拾える（`PF22` を選んで縮尺 1/100 で2点をなぞり、全図面の値が出る）。
4. PDF を保存して開き直すと、項目一覧（`readCountFixtures`）に足した項目だけが入っている（マスタの全候補は入っていない。件数が足した数と同じ）。
5. 「分野の一式」タブで今までどおり一式を追加できる。
6. 通常の読込で標準マスタを読まない: PDF を開いて数量タブを開いただけでは、`quantityMaster` の chunk のネットワーク要求が無い（`page.on('request')` で JS の URL を集め、ダイアログで「規格から選ぶ」を開いて初めて増えることを確かめる。chunk 名は vite の出力名に依存するので、マスタのデータにだけ入っている文字列（例 `EM-CEE-S`）を含む JS の応答がダイアログを開く前に無いことで確かめてもよい）。

## 禁止事項

- 標準マスタの全候補を PDF の項目として登録しないこと（選んだものだけ）。
- 標準マスタのデータを、通常の読込で読まれる chunk に入れないこと（静的 import 禁止）。
- 名称の文字列で分類・集計を決める処理を足さないこと。
- `FIXTURE_PRESETS` と、PDF に保存する項目の形（`KaruCountFixtures`）を変えないこと。
- 試験から `work/` など Git の管理外のフォルダへ書き込まないこと。
- 対象外のファイルを変更しないこと。git の操作をしないこと。python・pytest は使わない。
- 試験の実行はしなくてよい（Claude Code が実行する）。書くだけでよい。`npx tsc --noEmit` は実行してよい。
- 同じ作業フォルダで、別の作業（保存状態: `App.tsx`・`AnnotationStore.ts`・`documentModel.ts`・`DocumentTabs.tsx`・`MenuBar.tsx`、選択の表示: `AnnotationLayer.tsx`・`MeasurementOverlay.tsx`・`styles.css`）が同時に進んでいる。`styles.css` は末尾に新しい規則を足すだけにし、既存の規則を書き換えないこと。対象外のファイルに型エラーや変更があっても触らず、報告だけすること。
