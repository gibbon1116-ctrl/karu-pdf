## 目的

利用者の指示（要約）:

- 数量の一覧と詳しい集計を、同じ狭い欄に詰め込みすぎない。役割を「数量の一覧＝項目を選ぶ」「PDF＝拾う」「拾いバー・右欄＝今の項目・経路構成」「**詳しい集計＝ページ別・図面別・階・部屋別の確認**」に分ける。詳しい集計は狭い欄に限らず、**画面の幅を使う表示**にする。
- 全体の数量から、ページ別・図面番号別・階別・部屋別へ展開できる。項目を押すと、その数量の図面の位置へ移る。
- 図面番号・図面名称の読み取り結果を、数量の内訳・ページ一覧・CSV・図面への移動に使う（CSV と内訳のページの行はすでに使っている）。
- 数量の一覧から「どこで拾ったか」を簡単に確かめられる: 内訳の項目を選ぶと、ページへ移り、その箇所を表示し、その数量を選び、一時的に最前面に出す（SPEC-06b）。

## 変更内容

### 1. 集計表（`QuantityTable.tsx`）

- 数量タブ（「拾う」「管理」の両方）に「集計表」ボタン（`aria-label="集計表を開く"`）。押すと、図面の表示領域（`.viewer-slot`）の**下側**に、表示領域の幅いっぱいの集計表の欄を開く（`role="region"`、`aria-label="数量の集計表"`）。高さの既定は表示領域の 40%、上の縁をドラッグして 20〜70% で変えられる（`localStorage` の `karu-pdf:quantity-table-height`）。「閉じる」ボタンと Esc で閉じる。図面は欄の上で今どおり操作できる。
- 上の段:
  - 列の切替（`aria-pressed` のボタン）: 「図面別」（既定）・「階別」・「階・部屋別」
  - 分類の絞り込み（select、既定「すべて」）、種別の絞り込み（個数・長さ・面積・体積・すべて）、名称・略号の検索
  - 「CSVに書き出す」（今の数量 CSV の画面を開く）
- 表:
  - 行: 項目（分類ごとの見出しの行を挟む。数量タブと同じ順）。左の固定の列: 見本・`fixtureCode`・名称・単位・**全図面**。
  - 列: 「図面別」では数量のあるページ（索引の `pagesOf` の合併、ページの順）。列の見出しは2段で、上に図面番号（無ければ `p.N`）、下に図面名称（省略表示、`title` に全文）。「階別」では階（`compareFloors` の順、階なしは `（階なし）`）。「階・部屋別」では階ごとに部屋の列（見出しは2段: 階・部屋）。
  - セルは数量（個数は整数、それ以外は小数2桁）。0 は空。
  - 見出しの行と左の列は、スクロールしても固定。
- 描く量を絞る:
  - 行は見えている範囲だけ描く（行の高さを固定にして、スクロール位置から描く行を決める）。
  - 列が 80 を超えるときは、最初の 80 列だけ描き、`ほか N 列。分類・種別・検索で絞り込むか、CSV で確かめてください` を出す。
  - 表のデータは `store.quantityIndex()` が変わったときだけ作り直す（`useMemo` の依存に索引を使う）。集計表を閉じているときは何も作らない。
- セルを押す → その項目の、そのページ（「図面別」）・その階（「階別」）・その階と部屋（「階・部屋別」）の拾いへ移る（下の 2.）。同じセルをもう一度押すと、次の拾いへ（上から順、左から順。最後の次は最初）。セルの右下に `2 / 5` のように今の位置を出す。
- 全図面のセルを押すと、その項目の今の内訳（`QuantityBreakdown`）を数量タブで開く。

### 2. 所在の確認（移動・選択・強調）

- 共通の関数（例 `revealPickup(session, annotationId)`）: そのページの注釈を読み込み（`ensurePageLoaded`）、項目を表示する状態にし（今の `go` と同じく `selectFixture`・`setFixtureVisible`）、その拾いを選び（`selectOnly` → SPEC-06b で最前面に出る）、`navigate(pageIndex, rect)` で表示し、**位置を知らせる一時的な輪**を出す。
- 一時的な輪: `AnnotationStore` に `flashId`（メモリだけ、保存しない）。`AnnotationLayer` は `flashId` の拾いの外接四角の周りに、太めの円か角丸の四角（`#ff8a00`、画面上 3px、CSS のアニメーションで 1.2 秒かけて広がりながら消える）を描く。1.5 秒後に `flashId` を消す。`pointer-events: none`。輪は PDF の画像を描き直さない。
- 内訳（`QuantityBreakdown`）のページの行を押したときも、この関数を使う（今の動作に輪が加わる）。

### 3. 性能

- 集計表を開いていないときは何も作らない・描かない。
- 集計表は索引だけを使う。注釈を走査して数え直さない。
- 輪は選んだ1件だけ。

## テスト

### 単体（`tests/`）

- 集計表のデータを作る純粋な関数（例 `buildQuantityTable(index, fixtures, mode, filters, drawingInfo)`）: 図面別の列（数量のあるページだけ、ページの順、見出しに図面番号・名称）、階別の列の順（B1階 → 1階 → 2階 → RF → 階なし）、階・部屋別、分類・種別・検索の絞り込み、全図面の値が索引の `total` と同じ、80 列の上限。
- 1,000 項目・ページ 100・注釈 10,000 件の索引で、表のデータを作るのが 50ms 未満（`performance.now()` の中央値）。

### 画面（新規 `e2e/quantity-table.annotate.spec.ts`）

白紙3ページ。2ページ目・3ページ目に図面情報（`__karu.setDrawingInfo(1, { number: 'E-101', name: '1階電灯設備平面図', numberManual: true, nameManual: true, scanned: true })` など）。個数の項目 LED を、1ページ目に2個（階 1階）、2ページ目に3個（階 1階・部屋 事務室）、3ページ目に1個（階 2階）拾う。長さの項目 CV を2ページ目で1本。

1. 「集計表を開く」→ 欄が図面の下に開き、図面の表示領域の高さが減る（図面は見えたまま）。LED の行の全図面が 6、列の見出しに `p.1`・`E-101`（下に `1階電灯設備平面図`）・3ページ目の番号。
2. LED の `E-101` のセル（3）を押す → 2ページ目へ移り、その LED の印が1つ選ばれ、輪が出る（`flashId` の輪の要素がある）。もう一度押すと次の印が選ばれ、セルに `2 / 3`。
3. 「階別」→ 列が `1階`・`2階`、LED の 1階 が 5。「階・部屋別」→ `1階／事務室` が 3。
4. 種別「長さ」で CV だけ。検索 `led` で LED だけ。
5. 欄の縁をドラッグして高さを変え、`page.reload()` 後に同じ高さ。Esc で閉じる。
6. 内訳（数量タブの全図面の値）からページの行を押しても、選択と輪が出る。
