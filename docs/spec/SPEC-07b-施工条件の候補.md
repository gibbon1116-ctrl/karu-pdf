## 変更内容

### 1. 項目の保存形式（`src/core/countFixtures.ts`）

`CountFixture` に次を足す。

| 項目 | 内容 |
|---|---|
| `conditions?: string[]` | 施工条件の候補。0〜30 件。各 1〜30 文字、前後の空白なし、改行なし、重複なし。並びは表示の順。 |
| `routeDefaults?: RouteConditions` | 長さ（線）の項目だけ。新しい経路での部分ごとの既定。`null` は「この部分を数えない」。文字列は既定の条件。 |
| `defaultCondition?: string` | 長さ（線）以外の項目と個数の項目。新しい拾いの既定の条件。 |

- `routeDefaults`・`defaultCondition` の条件は、`conditions` の中にあるものに限る。
- **古い `routeScope` の置き換え**
  - 読み込み時に `routeScope` を `routeDefaults` に変える（`'rise'` → `{ plan: null, slack: null }`、`'noSlack'` → `{ slack: null }`）。
  - メモリ上では `routeScope` を持たない。
  - 書き出しでは、古い版のために近い `routeScope` も書く（SPEC-07a の拾いの `scope` と同じ対応）。
- 読み書きで変わらないこと（`serializeCountFixtures` → 読み込みで同じ）。

### 3. 標準マスタへの項目の追加（機械）

指示書が保温・塗装の積算区分を求めているため、次を足す。分類名は `保温`・`塗装` とする。

| 項目 | 種別・方法 | 規格 | 備考 |
|---|---|---|---|
| 配管保温（グラスウール） | 長さ・`polyline` | 呼び径 `15A〜150A`（既存の `a15`） | |
| ダクト保温（長方形） | 面積・`lengthHeight` | なし | 「長さ×周長」。高さの欄の表示名を「周長」にできないなら、名称に「（長さ×周長）」と書く |
| 配管塗装 | 長さ・`polyline` | 呼び径 `15A〜150A` | |

既存のマスタの並び・キー（`key`）・コード検索は変えない。追加は末尾の機械設備の範囲に入れる。

### 4. 項目の編集画面（`src/app/FixtureDialog.tsx`）

「施工条件」の欄を足す。

- **候補の一覧**
  - 追加（入力＋「追加」）、名前の変更、削除、上へ・下へ。
  - 検証は 1. の規則。誤りは欄の下に日本語で出す。
- **「標準の候補を入れる」ボタン**
  - この項目と同じ分類・略号（`code` の先頭の種類）の標準マスタの候補を、今の一覧に足す。重複は足さない。
  - 古い PDF の項目に候補を入れるための操作。自動では入れない。
- **既定**
  - 長さ（線）の項目は「平面」「立上り・立下り」「その他の加算」それぞれに、既定の条件を選ぶ。選択肢は、未設定・候補・数えない。
  - 今の「経路での範囲（初期値）」の選択は、これに置き換えて消す。
  - それ以外の項目は、既定の条件を1つ選ぶ（未設定・候補）。
- 今の「余長・その他（初期値）」は、名前を「その他の加算（初期値）」に変える。
  - 説明（`title`）に「図示されない付加長を、設計図書に指示がある場合だけ入れる。切り無駄・割増は入れない（単価に含まれる）」と書く。

### 5. 改名・削除の反映（`src/editor/AnnotationStore.ts`）

- 項目の編集を保存するとき、候補の名前を変えていたら、その項目の拾いの条件の文字列も新しい名前に置き換える。
  - 対象は、線の部材の `cond`（`plan`・`rise`（配列も）・`slack`）、`QuantityMark.condition`、`CountMark.condition`。
  - 項目の変更と同じ 1 回の Undo で戻る。
- 候補から削除した条件は、拾いからは消さない（候補外の条件として残る）。
- 新しい拾いの既定の順:
  1. 同じ項目で直前に設定した条件（SPEC-07a の引継ぎ）
  2. 項目の既定（`routeDefaults`・`defaultCondition`）
  3. 未設定

  今の `MeasurementOverlay.tsx`（`routeScope` の参照）・`LinePicker.tsx`・`routeSets.ts` の `routeScope` の参照は、`routeDefaults` に置き換える。

## テスト

### 単体

- 項目の読み書き:
  - `conditions`・`routeDefaults`・`defaultCondition` の検証。
  - 古い `routeScope` の読み替えと、書き出しで `routeScope` が書かれること。
  - 読み書きで変わらないこと。
- マスタ:
  - 表のとおりの候補が付く。
  - マスタから足した項目に既定が付かない。
  - 追加の3項目が検索で見つかる。
  - 既存のキーが変わらない。
- 改名:
  - 線の部材（立上りの配列を含む）・面積・器具の条件が置き換わる。
  - 1 回の Undo で、項目と拾いが戻る。
- 既定の順（引継ぎ → 項目の既定 → 未設定）。

### 画面（e2e、書くだけ）

- 標準マスタから CV を足すと、項目の編集に候補が並び、既定は未設定。
- 候補の追加・改名・削除・並べ替え・「標準の候補を入れる」。
- 長さの項目の部分ごとの既定を「ケーブルラック配線」にして新しい経路を描くと、その条件になる。

## 禁止事項

- 標準マスタの既存の項目の並び・キー・コードを変えないこと。
- PDF を開く・表示・スクロールのときに処理を足さないこと。
- 対象外のファイルを変更しないこと。git の操作をしないこと。python・pytest は使わない。
- `npx tsc --noEmit` と単体試験は実行してよい。e2e は実行しなくてよい。
