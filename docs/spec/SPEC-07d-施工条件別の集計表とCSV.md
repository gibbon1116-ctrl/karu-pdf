# SPEC-07d: 施工条件別の集計表・内訳・CSV と、未設定の抽出

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 集計の正確さ（二重計上の防止）と、大きな表の性能にかかわるため

---

## 目的

計画: `docs/調査/施工条件別数量拾い_計画.md`。前提: SPEC-07a（`QuantityEntry.condition`・`part`・`riseIndex`、`QuantityIndex.byCondition`）、SPEC-07b（`CountFixture.conditions`）、SPEC-07f（順に確認の `reviewCursor.ts`）。

利用者の指示:
- 材料・規格・施工条件・数量単位ごとに集計する。
- 線状部材は、必要に応じて平面と立上り・立下りの内訳を確かめられるようにする。
- 同じ材料について、施工条件別の数量と、材料全体の数量を確かめられるようにする。
- 全長は施工区分にしない。
- 図面別・階別・部屋別の今の集計を保つ。
- CSV に、材料・規格・施工条件・区間・数量などを出す。
- 施工条件が未設定の数量を、簡単に抜き出して確かめられるようにする。
- 複数の経路・複数の部材の数量を、二重に数えない。

## 用語

- **項目**: 材料＋規格。今の `CountFixture`。
- **部分**: SPEC-07a の `part`。表示名は、平面・立上り・立下り・その他の加算。CSV の列名は「区間」。
- **未設定の対象**: 項目に施工条件の候補（`conditions`）があり、その entry の `condition` が `undefined` のもの。候補の無い項目は、未設定の対象にしない。

## 変更内容

### 1. 集計表（`src/app/QuantityTable.tsx`）

**データの作り方**

- `buildQuantityTableData` で、各項目の値を施工条件ごとにも持つ。
  - `values[mode]` に加えて、`byCondition: Map<conditionKey, { values: Record<mode, Map<columnKey, number>>; total; plan; rise; slack }>`。
  - `conditionKey` は条件の文字列、未設定は `''`。
- 今と同じく、索引が変わったときに1回だけ作る。
  - entry の走査は、この関数の中の1回だけ。
  - 絞り込みや表示の切り替えでは、走査し直さない（今の方針どおり）。

**行**

- 項目の行の名称の左に、展開のボタン（▸／▾）を出す。
  - 出すのは、施工条件が2種類以上か、未設定と設定済みが混ざる項目だけ。
  - 展開すると、項目の行の下に施工条件ごとの行を出す。
- 施工条件の行の内容:
  - 略号の欄は空。
  - 名称の欄に `└ ケーブルラック配線` または `└ 未設定`。
  - 単位・全図面・各列の値は、その条件の値。
- 線の項目の施工条件の行は、全図面の値の下に、小さく `平面 120.4 ／ 立上り 30.0` と出す。
  - 0 の部分は出さない。
  - `title` で、その他の加算も含めた全文を出す。
- 項目の行（材料全体）の値は今どおり。施工条件の行の合計は、項目の行と一致する。
- **ツールバーに足すもの**
  - 「施工条件別」のトグル: オンで、展開できる項目をすべて展開する。
  - 「未設定だけ」のチェック: オンで、未設定の対象がある項目だけを出し、その項目は未設定の行だけを展開して出す。
- 行の仮想化（今の `ROW_HEIGHT` の固定の高さ）を保つ。施工条件の行も同じ高さ。

**値の欄を押したとき（順に確認）**

- 施工条件の行の値の欄は、その条件の entry の拾いだけを、順に確認する。
- SPEC-07f の `nextReview` を使う。
- cursor の key に条件を含める。

**表示・絞り込みを変えたとき**

- 展開の状態は、項目の id ごとに保つ。
- 索引が変わっても、展開の状態は初期化しない。

### 2. 数量の内訳（`src/app/QuantityBreakdown.tsx`）

- タブに「施工条件別」を足す。並びは、ページ別・階・部屋別・施工条件別。
- 施工条件別のタブの行は、`ケーブルラック配線 120.40 m`（線の項目は下に `平面 … ／ 立上り …`）。
- 行を押すと、その条件で絞り込んだ「ページ別」に切り替わる（今の階・部屋の絞り込みと同じ仕組み）。
  - 絞り込みの表示は「施工条件: ケーブルラック配線」と「絞り込みを解除」。
- 未設定の行は `未設定` と出し、項目に候補があるときは、未設定の対象であることを示す（例: 橙の文字）。

### 3. CSV（`src/app/annotationCsv.ts`）

**集計（summary）**

- 行は項目×施工条件。
- 施工条件が1種類だけの項目は1行。2種類以上の項目は、条件ごとの行と、項目全体の行（区分「材料計」）。
- 列（この順）:
  - 分類、略号、名称、規格
  - 施工条件（未設定は空）
  - 集計区分（「施工条件別」か「材料計」）
  - 種別、単位、集計方式
  - 平面、立上り・立下り、その他の加算（線の項目だけ。それ以外は空）
  - 全図面の合計、表示中の図面（p.n）、各ページ

**明細（detail）**

- 行は項目×施工条件×区間×ページ×階×部屋。
- 区間は、平面・立上り・立下り・その他の加算。線以外の項目は空。
- 列（この順）:
  - 分類、略号、名称、規格
  - 施工条件、区間
  - 種別、単位、集計方式
  - 階、部屋、ページ番号、図面番号、図面名称
  - 数量、拾いの件数

**拾いの件数**

- `annotationId` の重複を除いて数える。
- 1 本の経路の平面と立上りは、同じ行なら 1 件と数える。

**二重計上の防止**

- 集計の行（条件別）の合計 ＝ 材料計 ＝ 今の全図面の合計。
- 明細の合計 ＝ 集計の合計。
- この3つが一致することを試験で確かめる。

**その他**

- 既存の列名・既存の CSV の読み手のため、ファイル名と BOM・改行は今どおり。
- 列が増えることは、ヘルプとダイアログの説明に書く。

### 4. 立上り・立下りの名前

- 立上りか立下りかの区別は、データに無い（どちらも長さだけ）。
- 表示と CSV では「立上り・立下り」とまとめて書く。

## テスト

### 単体

- `buildQuantityTableData`:
  - 施工条件ごとの値と、項目の値が一致する。
  - 線の平面・立上り・その他の内訳。
  - 未設定の扱い（候補の無い項目は対象外）。
- CSV（集計・明細）:
  - 列の並び、条件別と材料計の行、区間、件数の重複除外。
  - 明細の合計 ＝ 集計の合計 ＝ 索引の `total`。
  - 2本の経路×3部材×立上り2か所の例で確かめる。
- 古いデータ（条件なし）の CSV:
  - 施工条件が空の1行になる。
  - 数量が今の版の CSV と同じ。

### 画面（e2e、書くだけ）

- 条件の違う2本の CV で、集計表を「施工条件別」にすると2行に分かれる。
  - 合計が項目の行と一致する。
  - 条件の行の値を押すと、その条件の経路だけが順に選ばれる。
- 「未設定だけ」で、未設定の拾いのある項目だけが出る。
  - 値を押して拾いを選び、書式欄で条件を付けると、その行が消える（索引の更新）。
- 内訳の「施工条件別」から絞り込んで、ページ別に移る。
- CSV の集計・明細の列と値。

## 性能

- 集計表を開く・展開する・絞り込むときに、全 entry を走査し直さない（データは索引ごとに1回）。
- 2,000 件の拾い（線 1,000 本×部材3・立上り2）で、`buildQuantityTableData` が 50ms 以内（Node の単体試験で測って報告。上限の確認であり、試験の合否にはしない）。

## 禁止事項

- 数量の値（合計）を変えないこと。条件を自動で付けないこと。
- PDF を開く・表示・スクロールのときに処理を足さないこと。集計表は開いているときだけ動く（今のまま）。
- 対象外のファイルを変更しないこと。git の操作をしないこと。python・pytest は使わない。
- `npx tsc --noEmit` と単体試験は実行してよい。e2e は実行しなくてよい。
