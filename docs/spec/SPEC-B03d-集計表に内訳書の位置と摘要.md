# SPEC-B03d: 集計表に「摘要」「内訳書の位置」の列と、内訳書の位置でまとめる表示

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 仮想スクロールの表の固定列の追加、並べ方の切替（内訳書のマスタ順）、Excel の集計表の列とのそろえ、既存の試験の更新にまたがる

---

## 利用者の要望（試用版 第2版、2026-10-11）

> 電気設備から電灯分岐までの中科目までの設定は、集計表の表示でも内訳書の位置が分かるようにしたい。

- 集計表には今、略号・名称・規格・単位しか出ないため、内訳書の位置（編・種目・科目・中科目）も摘要（盤名称・形式・種類など）も見えない。同じ「LD ライティングダクト」が摘要の違いで 9 行になっても区別できなかった（利用者の画面）。

## 対象

- 変更: `src/app/QuantityTable.tsx`、`src/app/quantityXlsx.ts`、`src/styles.css`
- 試験: `tests/quantityTable.test.ts`、`tests/quantityXlsx.test.ts`（足す・合わせる）、`e2e/quantity-table.annotate.spec.ts`（列の数・見出しの確認があれば合わせる。1件足す）
- 変えない: `src/core/*`、CSV（`annotationCsv.ts`）、Excel の「明細」「細目別内訳」「別紙明細」のシート

## 変更内容

### 1. 列を2つ足す（画面）

固定列を **見本・略号・名称・規格・摘要・内訳書の位置・単位・全図面** にする。

- 「摘要」: `summaryText(f)`（施工条件の行は空）。`title` に同じ文字。幅 120px。
- 「内訳書の位置」: 項目に `breakdown` があれば `${subject}／${middle}`（中科目が無ければ `${subject}`）。`title` には `${book}／${section}／${subject}／${middle ?? ''}／${item}`（空は省く）。位置が無ければ空。施工条件の行は空。幅 150px。
- 固定列の `left`・表の幅・区分の行の `colSpan`・間隔の行の `colSpan` を合わせて直す（今の `6` を列の数の定数にする）。CSS の `.quantity-table-fixed-*` を 0〜7 にする。

### 2. 内訳書の位置でまとめる

- 集計表の操作の段（「未設定だけ」の隣）に `<label><input type="checkbox" aria-label="内訳書の位置でまとめる">内訳書の位置でまとめる</label>` を足す。状態は `localStorage` の `karu-pdf:quantity-table-group-by-breakdown` に覚える（読めなければオフ。`localStorage` が使えなくても動く）。
- オンのとき、`projectQuantityTable` の区分の行を、分類ではなく **内訳書の位置**（編・種目・科目・中科目）にする:
  - 区分の行の文字: `${book} ${section}／${subject}／${middle}`（中科目が無ければ省く）。位置の無い項目は最後の区分 `（内訳書の位置なし）`。
  - 区分の並び: Excel の「細目別内訳」と同じ（`breakdownEntries()` の群の順。マスタに無い群は後ろに、群の中の項目の `order` の最小値の順）。区分の中の項目は `order` の順。ただし `breakdownMaster` は集計表のファイルから**静的に import しない**（集計表は通常の画面にあるため）。オンにしたときだけ `import('../core/breakdownMaster')` で読み込み、読み込むまでは今の分類の並びで出す。`projectQuantityTable` には、群の並びを返す関数（または群の鍵 → 順番の Map）を引数で渡す形にする（純粋な関数のまま試験できるように）。
  - 「集計表の分類」の絞り込みは、オンでも項目の分類で絞る（今のまま）。
- オフのときは今と同じ（分類でまとめる）。

### 3. Excel の集計表（`quantityXlsx.ts`）

- 「集計表」シートの固定列を画面と同じ8列にする（摘要・内訳書の位置を、規格の後ろに）。列幅は 摘要 24、内訳書の位置 24。見出しの結合（2行）・列の数の上限の検査（`8 + 列数`）・見本の画像の位置（0 列目）を合わせて直す。
- 「内訳書の位置でまとめる」がオンなら、Excel の集計表もその並びで書く（`QuantityWorkbookOptions.display` に `groupByBreakdown?: boolean` と、群の順の情報を足す）。
- ほかのシートは変えない。

### 4. 試験

- `tests/quantityTable.test.ts`: 位置でまとめたときの区分の文字・並び（マスタの群の順、位置なしは最後）、摘要と位置の列の値。オフでは今と同じ結果。
- `tests/quantityXlsx.test.ts`: 集計表シートの見出しが8つの固定列になり、摘要・位置の値が入る。既存の試験の期待値（列の位置）は、この変更に合わせて直す（直した箇所を報告する）。
- e2e（`e2e/quantity-table.annotate.spec.ts` に1件）: 内訳書の位置を持つ項目（`page.evaluate` で `window.__karu` を使うか、標準マスタの「内訳書から選ぶ」で分電盤 L-1 を電灯分岐に追加）を作り、集計表に「内訳書の位置」列で `電灯設備／電灯分岐`、「摘要」列で `L-1` が出る。「内訳書の位置でまとめる」をオンにすると、区分の行が `電気設備 庁舎／電灯設備／電灯分岐` になり、再読み込みしてもオンのまま。

## 禁止事項

- 集計表の数量の計算・絞り込み・展開の動き、CSV を変えないこと。
- `breakdownMaster` を通常の画面の塊に入れないこと（オンにしたときだけ遅延読込）。
- 依存パッケージを足さないこと。指定外のファイルを変えないこと。
