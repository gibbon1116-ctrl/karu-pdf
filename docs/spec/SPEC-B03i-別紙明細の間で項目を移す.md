# SPEC-B03i: 数量タブの一覧で、別紙明細の間で項目を移し、科目・中科目の順番を入れ替える

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 項目の一覧のドラッグの受け先（項目・見出し）の判定、内訳書の位置と並び順の書き換え、集計表・Excel と共通の並べ方の変更、取り消しにまたがる

---

## 利用者の要望（2026-10-12）

> 細目別明細等の同じ階層の内容であれば添付のように違う別紙明細間でも移動ができるようにして下さい。現状、同じ別紙明細内でなければ移動ができません。
>（添付: 数量タブの一覧。「配線器具（別紙明細）（7）」の下の S スイッチの行と、「設備プレート（別紙明細）（1）」の見出し）

> 科目、中科目の順番を入れ替えられるようにして下さい。

SPEC-B03g・B03h では、見出しの並び（科目・中科目・別紙明細）は内訳書のマスタの順に固定で、並べ替えは「同じ位置（細目まで同じ）の項目どうし」に限っていた。

## 対象

- 変更: `src/app/breakdownOutline.ts`（並べ方）、`src/app/FixturePanel.tsx`、`src/app/fixtureAppend.ts`（追加の位置）、`src/app/FixturePresetDialog.tsx`（追加の位置の情報を渡す）、`src/styles.css`
- 試験: `tests/breakdownOutline.test.ts`、`tests/quantityTable.test.ts`（並べ方の期待値）、`tests/fixtureAppend.test.ts`、`e2e/breakdown-master.annotate.spec.ts`
- 変えない: 分類で表示しているときの動き、集計表・Excel の見出しの形

## 1. 並べ方を「項目の順番」に従わせる（`breakdownOutline.ts`）

- 位置のある項目の見出しの並びを、**各見出しの下の項目の `order` の最小値の順**にする（編・種目・科目・中科目・別紙明細のどの段も同じ）。マスタの順（`breakdownOrder`）は並べ方には使わず、別紙明細の判定（`rows.separate`）と、2. の追加・4. の並べ直しにだけ使う。
- 中科目の中では、今と同じく細目そのものの項目（分電盤など）を先に、別紙明細の群を後に並べる。それぞれの中は `order` の最小値の順。
- 位置の無い項目は今と同じく最後。
- 集計表・Excel（`projectQuantityTable`）と数量タブの一覧は、どちらもこの並べ方を使う（共通の関数のまま）。

## 2. 追加するときは内訳書の順の場所に入れる（`fixtureAppend.ts`）

- `appendFixtures(existing, additions, options?)` に省略可能な `rank?(f: CountFixture): number | undefined`（マスタの行の順。位置が無ければ undefined）を足す。
- 位置のある追加の項目は、
  - 同じ位置の項目があれば、その最後の項目の直後。
  - 無ければ、今ある位置のある項目のうち `rank` がその項目より大きい最初の群（今の並びで）の直前。無ければ位置のある項目の最後の直後。
- 入れた後、全体の `order` を 0 から振り直す（今の並びを保つ）。`rank` が無いとき・位置の無い項目は今と同じ（最後）。
- `FixturePresetDialog.tsx` は、内訳書のマスタ（`breakdownEntries()`）から `rank` を作って渡す（このダイアログはマスタを読み込み済み）。

## 3. 一覧のドラッグ（`FixturePanel.tsx`、内訳書の構成で表示しているとき）

### 3.1 項目
- 項目を項目の上に落とす:
  - 同じ位置 → 今と同じ並べ替え。
  - 編・種目・科目・中科目が同じで、**どちらの細目もマスタの別紙明細の行** → 動かす項目の `breakdown.item` を落とした先の `item` に変え、落とした先の前（上半分）・後（下半分）に入れる。
  - それ以外 → 何も変えず、状態の文 `別紙明細の間で移せるのは、同じ中科目の中だけです（ほかは項目の編集で内訳書の位置を変えてください）`。
- 項目を別紙明細の見出し（段 4）の上に落とす: 上と同じ条件なら、その別紙明細の末尾へ（`item` を変える）。
- 変えるのは `breakdown.item` と `order` だけ。状態の文 `${名称}を「${細目}（別紙明細）」へ移しました（Ctrl+Z で戻せます）`。

### 3.2 見出し（科目・中科目・別紙明細）
- 段 2（科目）・段 3（中科目）・段 4（別紙明細）の見出しをドラッグできるようにする（編・種目・「（内訳書の位置なし）」は動かさない）。
- 見出しは、**同じ親（一つ上の段が同じ）で同じ段の見出し**の上にだけ落とせる。上半分なら前、下半分なら後へ、その見出しの下の項目をまとめて動かす（`order` をまとめて動かす。ほかの項目の相対の順は変えない）。
- 違う親・違う段に落としたときは何もしない（状態の文 `同じ${段の名前}の中でだけ入れ替えできます`。段の名前は 科目なら「種目」、中科目なら「科目」、別紙明細なら「中科目」）。
- 状態の文 `${見出し}を移しました（Ctrl+Z で戻せます）`。

### 3.3 共通
- どの移動も `store.setCountFixtures` を1回（Ctrl+Z 1回で戻る）。
- ドラッグ中の見た目は今の分類の見出し・項目と同じ（`fixture-drop-before`／`after`／`inside`）。
- 「上へ」「下へ」は今のまま（同じ位置の中だけ）。
- 検索中は今と同じく並べ替えできない。

### 3.4 内訳書の順に並べ直す
- 「内訳書の構成で表示」の隣に、ボタン `内訳書の順に並べ直す` を置く（内訳書の構成で表示しているときだけ）。押すと、位置のある項目を、マスタの行の順（同じ位置の中は今の `order` の順、マスタに無い位置は後ろ）に並べ直して `order` を振り直す（位置の無い項目は最後に今の順で）。1回の取り消しで戻る。状態の文 `内訳書の順に並べ直しました（Ctrl+Z で戻せます）`。

## 4. 純粋な関数と試験

`breakdownOutline.ts` などに純粋な関数として置き、単体試験する:
- `orderByBreakdown`（新しい並べ方）: 見出しの並びが `order` の最小値の順、中科目の中は細目そのものの項目が先。
- `moveFixtureInOutline(fixtures, sourceId, target, order)`（項目の移動。同じ位置／別紙明細の間／不可 → null）。
- `moveHeadingInOutline(fixtures, headingKey, target, order)`（見出しの移動。同じ親・同じ段だけ。不可 → null）。
- `sortByBreakdownMaster(fixtures, order)`（並べ直し）。
- `appendFixtures` の `rank`（同じ位置の後ろ、マスタの順の場所、rank が無ければ最後）。

既存の `tests/quantityTable.test.ts` の階層の試験は、並べ方が `order` に従うように期待値を直す（マスタの順と `order` が一致するデータなら結果は同じ。違うデータの期待値だけ直し、直した箇所を報告する）。

e2e（`e2e/breakdown-master.annotate.spec.ts`）:
1. 内訳書から、電灯分岐の「配線器具」の項目（2件）と「設備プレート」の項目、電灯幹線の項目を足す。配線器具の1件を設備プレートの項目の上へドラッグ → 見出しの数が変わり、その項目の `breakdown.item` が `設備プレート`。Ctrl+Z で戻る。分電盤（細目そのもの）の上へ落としても変わらず状態の文。
2. 追加した直後は書式の順（電灯幹線 → 電灯分岐）。中科目「電灯分岐」の見出しを「電灯幹線」の見出しの上半分へドラッグ → 一覧の見出しが 電灯分岐 → 電灯幹線 の順になる。集計表を開いても同じ順。Ctrl+Z で戻る。
3. もう一度入れ替えてから `内訳書の順に並べ直す` を押すと、書式の順（電灯幹線 → 電灯分岐）に戻る。
