# SPEC-B03j: 集計表の見出し（科目・中科目など）をたためるようにし、選んでいる項目の見出しは自動で開く

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 仮想スクロールの表の行の投影（たたんだ見出しの子を除く）、選んでいる項目による自動の展開、状態の保存、既存の試験との整合にまたがる

---

## 利用者の要望（2026-10-12）

> 添付の部分と同様に、集計表でも科目や中科目等をたためるようにしたい。ただし、入力するために選択した細目が含まれた細目別の一覧は自動で表示されるようにしたい。
>（添付: 数量タブの一覧。「電気設備（26）」「庁舎（26）」「電灯設備（23）」「受変電設備（2）」「発生材処理（1）」の見出しが、押すとたためる）

## 対象

- 変更: `src/app/QuantityTable.tsx`（必要なら `src/app/breakdownOutline.ts`）、`src/styles.css`
- 試験: `tests/quantityTable.test.ts`、`e2e/quantity-table.annotate.spec.ts`
- 変えない: Excel・CSV（たたんだ状態に関係なく、すべての行を書く）、数量タブの一覧

## 変更内容

1. **見出しの行をたためる**: 集計表の区分の行（内訳書の構成の段 0〜4 の見出し、分類でまとめるときの分類の見出し）の見出しの文字の前にボタン（`▾`／`▸`、`aria-expanded`、`aria-label` は `${見出し}をたたむ`／`${見出し}を開く`）。押すと、その見出しの下の見出しと項目の行（施工条件の行を含む）を表に出さない。見出しの文字の後ろに、下の項目の数 `（N）` を出す（数量タブと同じ）。
2. **たたむ状態の鍵**: 見出しの鍵（`groupKey`。段と上の段を含む全体）。同じ名前の中科目が別の科目にあっても混ざらない。分類の見出しは分類名。
3. **選んでいる項目の見出しは自動で開く**: 拾いに使うために選んでいる項目（`store.selectedFixtureId`。数量タブ・拾いバーで選んだもの）があれば、その項目の上の段の見出しはすべて、たたんでいても開いて表示する（たたむ状態は変えずに、表示のときだけ開く）。その見出しのボタンは開いた形で出し、押せばたためる（押したら、その見出しは自動では開かない — 選んでいる項目が変わるまで）。選んでいる項目が変わったら、新しい項目の見出しが開く。表は選んでいる項目の行が見える位置までスクロールする（行が表の中にあるとき。今の「表示中の行へ」の動きがあればそれを使う）。
4. **まとめて**: 操作の段に `すべてたたむ`・`すべて開く` のボタン。
5. **状態の保存**: たたんだ見出しの鍵の一覧を `localStorage` の `karu-pdf:quantity-table-collapsed` に覚える（読めなければすべて開く）。表を閉じて開いても同じ。
6. **投影**: `projectQuantityTable` に `display.collapsed?: ReadonlySet<string>` と `display.expandedFor?: string`（選んでいる項目の id）を足し、たたんだ見出しの子の行を除いた `rows` を返す（純粋な関数のまま試験できる）。Excel の書き出し（`quantityWorkbookSheets`）には `collapsed` を渡さない（すべての行）。
7. 分類でまとめているとき（チェックを外したとき）も、分類の見出しで同じようにたためる。

## 試験

- `tests/quantityTable.test.ts`: 見出しをたたむと子の見出し・項目・施工条件の行が消え、見出し自身は残る。`expandedFor` の項目の上の見出しは、たたんでいても子が出る。分類の見出しも同じ。Excel のシートはたたんでも全部の行。
- e2e（`e2e/quantity-table.annotate.spec.ts` に1件）: 内訳書の位置のある項目が2つの科目にある状態で集計表を開き、`電灯設備をたたむ` → その下の項目が消え、`すべて開く` で戻る。数量タブで受変電設備の項目を選んだ状態で `すべてたたむ` → 受変電設備の見出しとその項目の行は見えたまま（自動で開く）、電灯設備の項目は見えない。再読み込みしても、たたんだ状態が残る。

## 禁止事項
