# SPEC-B14: RC 部材の入口の改善（拾いの深さを厚さに使う・元の無い連動の案内）

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 計算部の検査の変更、項目の編集画面・数量タブ・標準マスタの 3 画面の案内、別の項目の編集へ移る操作、e2e にまたがる

---

## 背景（利用者の試用の結果、2026-10-12）

> 普通コンクリートと鉄筋を入力しても、何も連動しない。普通コンクリートの数量を入れても反応しない。

原因: 異形鉄筋（`link.kind === 'rc'`、`auto.rcKinds: []`）の元は「RC 部材の設定（`CountFixture.rc`）を持つ項目」だけ。標準マスタから足した「普通コンクリート（軸部）」（体積 = 囲む × 深さ、`method: 'polygonDepth'`）は `rc` を持たないので、拾っても鉄筋は 0。設定の場所（項目の編集の「RC 部材」の欄）の案内が無く、体積で拾うときも厚さを別に入れないと計算されない。

利用者の決定: 「配筋の設定＋案内」（コンクリートの項目に配筋を入れて計算する今の方式を、見つけやすくする。体積で拾ったコンクリートは拾いの深さを厚さに使う）。

## 対象

- 変更: `src/core/rcMember.ts`、`src/app/FixtureDialog.tsx`、`src/app/FixturePanel.tsx`、`src/app/FixturePresetDialog.tsx`
- 試験: `tests/rcMember.test.ts` に追記、新規 `e2e/rc-guidance.annotate.spec.ts`
- 変えない: データ（`src/core/breakdown/*`）、連動の計算（`fixtureLink.ts`）、ほかの画面

## 1. 拾いの深さを床板の厚さに使う（`rcMember.ts`）

- `rcMemberError`: 床板・基礎スラブ（`slab`・`foundationSlab`）は `thicknessMm` を省略できる（あれば正の数）。壁は今のまま必須。
- `computeRcMember`: 床板・基礎スラブの厚さ = `thicknessMm`（mm）があればそれ、無ければ拾いの深さ `metrics.depthM`（`polygonDepth` の拾い）。どちらも無ければ `RC部材の厚さを入れるか、深さ（体積）で拾ってください。` の誤り。
- 試験: 囲む × 深さ 0.15 の 4m×3m・`thicknessMm` なしで コンクリート 1.80 ㎥、型枠 12 ㎡、鉄筋は B07 の試験（D13@200 ダブル 2 方向）と同じ。`thicknessMm` があれば深さより優先。どちらも無い（`polygon`）なら誤り。壁の厚さの省略は今のまま誤り。

## 2. 項目の編集画面（`FixtureDialog.tsx`）

### 2.1 RC 部材の欄
- 「コンクリートの項目」= 分類（`category`）が `コンクリート`、または内訳書の位置の科目（`breakdown.subject`）が `コンクリート`、または名前に `コンクリート` を含む項目（連動の項目は除く）。コンクリートの項目では、`rc` が無くても RC 部材の欄を**開いた状態**で始め、欄の最初に次の文を出す:
  `配筋を入れると、異形鉄筋・型枠・ガス圧接などの連動の項目に数量が出ます。`
- 体積（`polygonDepth`）の項目で床板・基礎スラブのとき、厚さの入力の `placeholder` を `空なら拾いの深さ`、横に `空なら拾いの深さを厚さにします` と出す。
- 新しい省略可能な props `initialSection?: 'rc'`: 指定されたら RC 部材の欄を開き、欄までスクロールし、`RC 部材にする` のチェックにフォーカスする（自動でチェックは付けない）。

### 2.2 連動の欄（RC から）
- 連動の種類が `rc` で、元（手で選んだ元 ＋ 自動の元）が 0 件のとき、連動の欄の元の一覧の上に次を出す（`role="status"`）:
  `元になる RC 部材の項目がありません。コンクリートなどの項目を開いて「RC 部材」で配筋を入れてください。`
  その下に、候補の項目ごとのボタン `${code} ${name}に配筋を入れる`（候補 = 連動でない項目のうち、RC 部材にできる拾い方（囲む・囲む×深さ・長さ×高さ・線・個数）で、コンクリートの項目を先に、ほかの項目を後に、最大 8 件）。押すと新しい省略可能な props `onOpenFixture?(id: string, section: 'rc')` を呼ぶ（今の下書きは保存しない。未保存の変更があれば `window.confirm('変更を保存せずに移りますか？')`）。

## 3. 数量タブ（`FixturePanel.tsx`）

- 項目の行の札: 連動の種類が `rc`・`shape`・`steel`・`crossing` で元が 0 件の項目に、`連動` の札の代わりに `元なし` の札（`title="元になる項目がありません。項目を開くと案内が出ます。"`、クラス `fixture-link-badge fixture-link-missing`。色は `連動の誤り` と同じ系統でよい）。元の数え方は `fixtureLinkSources(全項目, 項目)`。
- `onOpenFixture` の実装: 今の編集を閉じ、指定の項目の編集を `initialSection: 'rc'` で開く。

## 4. 標準マスタから追加（`FixturePresetDialog.tsx`）

- `rc` の規則で連動の項目を作り、今ある項目（追加する項目を含む）に RC 部材の項目が 1 つも無いとき、状態の文の後ろに次を足す:
  `${名前の並び}は RC 部材の項目から計算します。コンクリートの項目を開き「RC 部材」で配筋を入れてください。`

## 5. 試験（e2e、新規 `e2e/rc-guidance.annotate.spec.ts`。`e2e/rc-members.annotate.spec.ts`・`e2e/breakdown-master.annotate.spec.ts` の作り方に倣う）

1. 標準マスタの「内訳書から選ぶ」→ 建築 → 庁舎 → コンクリート → 躯体 → 普通コンクリート（軸部）を追加（ふつうの体積の項目）。同じく 鉄筋 → 躯体 → 異形鉄筋 を追加 → 状態の文に `RC 部材の項目から計算します`。ダイアログを閉じる。
2. 数量タブの異形鉄筋の行に `元なし` の札。異形鉄筋の編集を開くと案内の文と `…普通コンクリート（軸部）に配筋を入れる` のボタン。押すと普通コンクリートの編集に移り、RC 部材の欄が開いていて、案内の文 `配筋を入れると…` がある。
3. `RC 部材にする` を付け（部材は床板）、厚さは空のまま、鉄筋 x 方向 D13@200 ダブル・y 方向 D13@200 ダブル を入れて保存。
4. 4m×3m を深さ 0.15m で拾う（体積の拾いの深さの入れ方は既存の e2e に倣う）→ 普通コンクリートが 1.80 ㎥、異形鉄筋の行の札が `連動` になり、全図面がおよそ `0.35`（t、所要）。

## 禁止事項

- データを変えないこと。連動の計算（`fixtureLink.ts`）を変えないこと。RC 部材の無い項目・連動の無い項目の画面を変えないこと（コンクリートの項目の RC 部材の欄が開いて始まることを除く）。依存パッケージを足さないこと。指定外のファイルを変えないこと。
