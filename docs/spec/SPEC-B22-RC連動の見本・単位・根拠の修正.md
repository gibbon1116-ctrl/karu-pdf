# SPEC-B22: RC の連動の見本・単位・計算の根拠を直す

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 2 か所の編集画面への見本の計算の共通化、連動の既定値の決め方、RC の計算結果の根拠の拡張（計算部・画面・Excel）、e2e にまたがる

---

## 背景（利用者の試用の結果、2026-10-12）

> 鉄筋とコンクリートの数量を連動させると、入力当初は単位が「t」で表示されるが、一度項目を編集から連動を解除して、再度連動設定をすると、単位が「m3」になり、「t」にならない。今の拾いで計算した見本が0tになっているが、連動の結果は0.16tになっている。見本の計算結果が合っていない。計算式も鉄筋の本数の計算や本数から重量への換算もないので正しいのか分からない。

Claude の調査（再現済み）:
1. **単位**: `FixtureDialog.tsx` の「連動にする」を付けると、いつも `{ kind: 'factor', sources: [] }` で始まる（標準の規則・前の設定を使わない）。種類を「RC 部材から」にしても出力の既定が「コンクリート」なので単位が ㎥ になる。
2. **見本が 0**: 画面右の「項目を編集…」から開く編集画面（`src/App.tsx` の `fixtureEdit` の `FixtureDialog`）には `previewLink`・`previewRc`・`previewSteel`・`onOpenFixture` が渡されていない。見本の計算に形の計量が渡らず、「普通コンクリート（基礎部）の形の計量が渡されていません」「0 t」になる（数量タブから開いた画面では正しい）。
3. **根拠**: 見本・内訳の根拠が `普通コンクリート（軸部）（自動） 0.35244 m³ × 1 ＝ 0.35244 t（new-1: コンクリート 1.80011㎥、型枠 12.00073㎡、D13 x 32本 165.44106m、D13 y 42本 175.146623m）` で、元の数量の単位が誤り（t のはずが m³）、`× 1` は意味がなく、本数の出し方・1 本の長さ・長さから質量への換算・所要の割増が無い。

## 対象

- 新規: `src/app/fixturePreviews.ts`（見本の計算の共通化）
- 変更: `src/app/FixturePanel.tsx`、`src/App.tsx`、`src/app/FixtureDialog.tsx`、`src/core/rcMember.ts`（`RcResult.bars` に根拠の値を足す）、`src/core/fixtureLink.ts`（RC の根拠の文）、`src/app/QuantityBreakdown.tsx`・`src/app/quantityXlsx.ts`（根拠の表示で単位と係数の出し方を直す。必要な所だけ）
- 試験: `tests/rcMember.test.ts`・`tests/fixtureLink.test.ts` に追記、`e2e/rc-guidance.annotate.spec.ts` に追記
- 変えない: データ、数量の値（計算結果）

## 1. 見本の計算の共通化（`fixturePreviews.ts`）

- `FixturePanel.tsx` の `previewLink`・`previewRc`・`previewSteel` の中身を `createFixturePreviews(store: AnnotationStore)` に移し、`{ previewLink, previewRc, previewSteel }` を返す。`FixturePanel` と `App.tsx` の `fixtureEdit` の `FixtureDialog` の両方で使う。
- `App.tsx` の編集画面にも `onOpenFixture`（別の項目の編集へ移る）を渡す（`fixtureEdit` の id を切り替える）。
- 見本と連動の結果（`store.quantityIndex().linkResult(id)`）は、同じ設定なら同じ値になること（e2e で確かめる）。

## 2. 連動の既定値（`FixtureDialog.tsx`）

- 「連動にする」を付けたとき、次の順で始める:
  1. 編集画面を開いたときの項目（`initial`）に連動があれば、その連動（外して付け直したときに元へ戻る）。
  2. 項目の名前に標準の規則（`linkRuleForDetail(name)`）があれば、規則の連動（`FixturePresetDialog.tsx` で連動の項目を作るときと同じ中身: `kind`・`auto`・`factor`・`rc`・`shape`・`crossing`・`steel`・搬入の区分）。状態の文に `標準の規則「${rule.label}」で始めました`。
  3. どちらも無ければ今のまま `factor`。
- 種類を「RC 部材から」に切り替えたときの出力の既定: 規則があれば規則の出力、無ければ名前から（`鉄筋` を含む → 鉄筋、`型枠` → 型枠、`圧接` → ガス圧接、`重ね継手` → 重ね継手、ほか → コンクリート）。鉄筋のときの数量は、名前に `加工組立`・`運搬` を含めば設計数量、ほかは規則があれば規則、無ければ所要数量。

## 3. RC の計算の根拠

### 3.1 計算部（`rcMember.ts`）
- `RcResult.bars` の各要素に、根拠の値を足す（省略可能・数量は変えない）: `layers`（段数）、`spacingMm`（間隔の筋）または `countPerLayer`（本数の筋の 1 段の本数）、`spanM`（間隔で割り付けた長さ。床板は割り付けた方向の幅、壁の縦筋は壁の長さ、横筋は高さ、スタラップは梁の長さ など）、`perLayerCount`（1 段の本数 = 割付本数）、`anchorageM`（1 本あたりの定着の長さの合計）、`lapM`（重ね継手の長さの合計）、`massKgPerM`（JIS の単位質量）。
- 本数の出し方の文を作る関数 `rcBarCountText(bar)`: 間隔の筋 `${span}m ÷ ${spacing}m → ${n}本`（切り上げ＋1 の結果。壁の横筋は −1）、本数の筋 `${countPerLayer}本`、段 `× ${layers}段`、拾いの数 `× ${count}`。

### 3.2 連動の根拠の文（`fixtureLink.ts`、`link.kind === 'rc'`）
- 拾いごとの `note` を、部材と出力に合わせて次の形にする（数値は 2 桁、質量は 3 桁）:
  - 鉄筋: `床板 12.00㎡ 厚さ 0.15m（拾いの深さ）: D13 x方向 3.00m÷0.200m→16本×2段=32本 計165.44m（1本 平均5.17m、定着・継手を含む）、D13 y方向 …｜D13 計340.59m × 0.995kg/m = 338.9kg = 0.339t × 1.04（所要）= 0.352t`（径ごとに 計・単位質量・質量。径の絞り込みがあればその径だけ）
  - コンクリート: `床板 12.00㎡ × 厚さ 0.15m = 1.80㎥`、型枠: `底面 12.00㎡`（部材ごとの式）、ガス圧接・重ね継手: `D19 主筋 … か所`
- 元の行（`LinkResult.sources` の表示）で、`rc`・`shape`・`steel`・`crossing` の連動は、元の数量の単位を**連動の出力の単位**（`quantityUnit(連動の項目)`）で出し、係数が 1 のときは `× 1` を出さない（`普通コンクリート（軸部）（自動） 0.352 t`）。係数・引き算・開口からの係数があるときは今のまま出す。表示する所: 編集画面の見本、内訳（`QuantityBreakdown`）の「計算の根拠」、Excel の「計算根拠」シート。

## 4. 試験

- 単体: `RcResult.bars` の根拠の値（4m×3m の床板 D13@200 ダブル 2 方向: x 方向は 3.00÷0.200→16本×2段=32本、y 方向は 4.00÷0.200→21本×2段=42本、単位質量 0.995）。壁の横筋の −1。RC の連動の `note` に `÷0.200m→16本`・`× 0.995kg/m`・`× 1.04（所要）` が入る。数量の値は今と同じ（既存の試験が通ること）。
- e2e（`e2e/rc-guidance.annotate.spec.ts` に追記）: (1) 異形鉄筋の編集で「連動にする」を外して保存 → 開き直して付ける → 種類が RC 部材から・出力が鉄筋・所要数量で始まり、保存すると一覧の単位が `t`、全図面がおよそ `0.35`。(2) 画面右の「項目を編集…」（`App.tsx` の編集画面）から異形鉄筋を開くと、見本の合計が一覧の全図面の値と同じ（`0.35 t`）で、`形の計量` の警告が無い。(3) 見本の根拠に `本` と `kg/m` と `1.04` が出て、元の行に `m³` が出ない。
