# SPEC-B23: 連動の元と先を見えるようにし、項目の説明のカードを構成要素・線要素・最近の選択にも出す

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 一覧・集計表・ホバーのカードの 3 か所の表示、元と先の両方向の対応（自動の元を含む）、性能（一覧の描画のたびに全項目の元を計算しない）、e2e にまたがる

---

## 背景（利用者の要望、2026-10-12）

> 連動させたときは、何の項目と連動されているのか分かるようにしたい。

> 数量拾いで構成要素を追加する際にも、名称が同じで摘要が異なるものの区別がつかない。先ほどの改修と同様に、カーソルを合わせると詳細のカードが出るようにしたい。

今は、数量タブの一覧・集計表の連動の項目に「連動」の札が付くだけで、元の項目（手で選んだ元・自動の元）は項目の編集を開くか、内訳の「計算の根拠」を見ないと分からない。元の項目の側からも、どの連動の項目に使われているか分からない。

## 対象

- 変更: `src/app/FixturePanel.tsx`（一覧の札・ホバーのカード）、`src/app/QuantityTable.tsx`（集計表の札）、`src/app/ComponentPicker.tsx`（構成要素を追加）、`src/app/LinePicker.tsx`（線要素を追加）、`src/app/fixtureQuickList.tsx`（最近）、`src/styles.css`
- 新規: `src/app/linkRelations.ts`（元と先の対応を作る。純粋な関数）、`src/app/FixtureHoverCard.tsx`（項目の説明のカードの共通の部品）
- 試験: 新規 `tests/linkRelations.test.ts`、e2e を 1 件（`e2e/linked-fixtures.annotate.spec.ts` に追記）
- 変えない: 連動の計算（`fixtureLink.ts`）、保存

## 1. 元と先の対応（`linkRelations.ts`）

- `linkRelations(fixtures): { sources: Map<連動の項目の id, Array<{ id; code; name; auto: boolean; sign: 1 | -1 }>>; dependents: Map<元の項目の id, Array<{ id; code; name }>> }`。元は `fixtureLinkSources(fixtures, 項目)`（手で選んだ元と自動の元）。区画の項目（交差）は元に含めない。
- 項目の一覧が変わったときだけ作る（`useMemo`、依存は項目の一覧）。拾いの数量は使わない。

## 2. 数量タブの一覧

- 連動の項目の行: 今の `連動` の札の右に、元の名前を短く出す（`← 普通コンクリート（軸部）`。元が 2 件以上なら `← 普通コンクリート（軸部） ほか2`）。札と元の文はクラス `fixture-link-source-text`（文字は小さめ、はみ出しは省略記号）。`元なし` の札のときは出さない。
- 元の項目（連動の先がある項目）の行: 名前の後ろに小さく `→ 2件`（クラス `fixture-link-dependent-count`）。
- ホバーのカード（SPEC-B21 の `fixture-hover-card`）に行を足す:
  - 連動の項目: `連動: ${種類の表示名}（${出力}）`（例: `RC 部材から（鉄筋・所要数量）`、`係数で計算する`）、続けて `元: ${略号} ${名前}（自動）`（1 件 1 行、引き算は `−` を前に、8 件まで、残りは `ほか n 件`）。
  - 元の項目: `連動先: ${略号} ${名前}`（1 件 1 行、8 件まで）。

## 2.5 項目の説明のカードの共通化と、構成要素・線要素・最近の選択

- SPEC-B21 で `FixturePanel.tsx` に作ったカード（`fixture-hover-card`: 略号・名前、規格、摘要、内訳書、単位・分類、備考、連動、見本。同名が 2 件以上なら規格・摘要を太字。位置は対象の右、画面内に収める）を `FixtureHoverCard.tsx` に移し、`<FixtureHoverCard fixture fixtures anchorRect relations />` で使えるようにする（`fixtures` は同名の数え上げ用、`relations` は 2 の連動の元・先の行用）。数量タブの一覧の見た目・動きは今のまま。
- 次の項目の選択ボタンにカーソルを合わせると、**すぐに**同じカードを出す（離れる・スクロール・選ぶ・閉じると消す）:
  - 数量拾いの「構成要素を追加」（`ComponentPicker.tsx`）の「よく組み合わせる」「最近使った」「この PDF の項目」の各ボタン
  - 「線要素を追加」（`LinePicker.tsx`）の各ボタン
  - 数量タブの「最近」（`fixtureQuickList.tsx`）の各ボタン
- ボタンの見た目は今のまま。カードはクリックの邪魔をしない（`pointer-events: none`）。

## 3. 集計表

- 集計表の行の `連動` の札（`QuantityTable.tsx`）の右に、一覧と同じ `← 元の名前（ほか n）` の文を出し、札の `title` に元の全件（`略号 名前（自動）` を改行区切り）。元の項目の行には `→ n件` を名前の後ろに出す（`title` に連動先の名前）。

## 4. 試験

- 単体 `linkRelations`: 手で選んだ元・自動の元（`auto.rcKinds` など）・引き算の元・連動の連鎖（根切り → 埋戻し）で、元と先の対応が正しい。区画は含めない。
- e2e（構成要素）: 名前が同じで摘要の違う 2 項目（例: アウトレットボックス 摘要 `種別 天井用` と `種別 壁用`）がある文書で、数量拾いの「構成要素を追加」を開き、「この PDF の項目」の 1 件目のボタンにカーソルを合わせるとカードに `摘要: 種別 天井用`、2 件目で `壁用`。数量タブの一覧のカードも今のまま出る（SPEC-B21 の e2e が通ること）。
- e2e: 普通コンクリート（RC 部材）と異形鉄筋（自動の元）の文書で、一覧の異形鉄筋の行に `← 普通コンクリート（軸部）`、普通コンクリートの行に `→ 1件`。異形鉄筋の行にカーソルを合わせるとカードに `元: … 普通コンクリート（軸部）（自動）`、普通コンクリートの行では `連動先: … 異形鉄筋`。集計表の異形鉄筋の行にも `← 普通コンクリート（軸部）`。

## 禁止事項

- 連動の計算・保存を変えないこと。連動の無い文書の一覧・集計表の見た目を変えないこと。依存パッケージを足さないこと。指定外のファイルを変えないこと。
