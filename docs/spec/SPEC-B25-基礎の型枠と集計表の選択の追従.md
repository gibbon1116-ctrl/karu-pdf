# SPEC-B25: 基礎のコンクリートの部材の種類・型枠の案内、集計表の選択の追従を固定しない

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: RC 部材の既定の種類の決め方、連動の元が当たらないときの案内（自動の元の条件の説明）、集計表のスクロールの追従の作り直し、e2e にまたがる

---

## 背景（利用者の試用の結果、2026-10-12）

> 型枠を連動で入れようとしても、記入されない。また、型枠運搬は数量が自動で入るが、長さ23.46mは自動で入っているようだが、高さの2.5mが反映されていない。反映されるようにしたい。（数量タブの）材料一覧で項目を選択しているとき、集計表でもそれが選択されている画面で固定される。項目を選択したときには集計表もその項目が表示されている画面に移動したいが、固定はしないようにしたい。

Claude の調査（再現済み。4m×2m・深さ 2.5m の普通コンクリート（基礎部））:
- 体積（囲む × 深さ）の項目で「RC 部材にする」を付けると、部材の種類の既定は**床板**（`rcKindsFor` の先頭）。床板の型枠は底面の面積（8 ㎡）。
- 標準の規則「型枠（基礎部）」の自動の元は基礎スラブ・基礎梁・独立基礎だけなので、床板のコンクリートからは **0**。「型枠運搬」は RC 部材すべてが元なので床板の底面の面積（利用者の 23.46 ㎡）になり、高さ（深さ 2.5m）が掛からない。
- 基礎スラブにすると、型枠 = 周長 12m × 2.5m = 30 ㎡、型枠運搬も 30 ㎡（正しい）。
- 集計表（`QuantityTable.tsx`）は、選んだ項目の行へのスクロールを `[selectedFixtureId, table.rows]` の効果で行うため、数量の更新（拾い・連動の計算）のたびに選んだ行へ戻され、利用者が表を動かせない。

## 対象

- 変更: `src/app/FixtureDialog.tsx`、`src/app/QuantityTable.tsx`
- 試験: `e2e/rc-guidance.annotate.spec.ts` に追記、`e2e/quantity-table.annotate.spec.ts` に追記
- 変えない: 計算部（`rcMember.ts`・`fixtureLink.ts`）、データ

## 1. RC 部材の種類の既定（`FixtureDialog.tsx`）

- 「RC 部材にする」を付けたときの部材の種類は、項目の名前・内訳書の位置（細目・中科目）から決める（拾い方で選べる種類の中から）:
  - `基礎` を含む → 囲む・囲む×深さ: **基礎スラブ**、線: **基礎梁**、個数: **独立基礎**
  - `柱` → 柱、`梁` → 梁、`壁` → 壁、`床`・`スラブ`・`土間` → 床板
  - どれでもなければ今のまま（拾い方の先頭）
- RC 部材の欄で、名前に `基礎` を含むのに部材の種類が床板・梁・柱・壁のとき、欄の中に注意の文: `名前が「基礎」です。部材の種類を基礎スラブ（基礎梁・独立基礎）にすると、型枠は側面（周長 × 厚さ）になり、型枠（基礎部）の連動の元になります。`

## 2. 連動の元が当たらないときの案内（`FixtureDialog.tsx`）

- 連動の種類が RC で、自動の元の `rcKinds` に種類の絞り込みがあり、当たる項目が 0 件で、**ほかの種類の RC 部材の項目がある**とき、連動の欄に（`role="status"`）:
  `部材の種類が合う RC 部材がありません。この連動は ${絞り込みの種類の表示名（、区切り）} を元にします。今ある RC 部材: ${項目名}（${種類の表示名}）…`
  その下に、それらの項目ごとのボタン `${code} ${name}の部材の種類を直す`（`onOpenFixture(id, 'rc')` で RC 部材の欄へ移る。SPEC-B14 と同じ）。
- 数量タブの札（`元なし`）は今のまま（自動の元が 0 件なら `元なし`）。

## 3. 集計表の選択の追従（`QuantityTable.tsx`）

- 数量タブ（材料一覧）で項目を**選んだとき（選ぶ項目が変わったとき）だけ**、集計表をその項目の行へスクロールし、行を含む見出しを開く。数量の更新・表の再計算・表の手動のスクロールでは動かさない（固定しない）。
- 同じ項目を選び直したとき（一覧で同じ行をもう一度押したとき）は、もう一度その行へスクロールしてよい（選び直しの合図を受け取れれば。無理なら不要）。
- 利用者が見出しをたたんだ後は、選ぶ項目が変わるまで、その見出しを自動で開き直さない。

## 4. 試験（e2e）

- `rc-guidance`: 標準マスタから 普通コンクリート（基礎部）を追加し、項目を開いて「RC 部材にする」→ 部材の種類が `基礎スラブ`。厚さは空のまま保存し、4m×3m を深さ 2.5m で拾う。標準マスタから 普通合板型枠（基礎部）と 型枠運搬 を追加 → 型枠（基礎部）の全図面が `35.00`（周長 14m × 2.5m）、型枠運搬も `35.00`。部材の種類を床板に変えると、型枠（基礎部）の編集の連動の欄に `部材の種類が合う RC 部材がありません` と `…の部材の種類を直す` のボタン、RC 部材の欄に `名前が「基礎」です` の注意。
- `quantity-table`: 項目が多い文書で集計表を開き、数量タブで下のほうの項目を選ぶ → 集計表がその行までスクロールする。集計表を上へスクロールし、拾い（またはほかの項目の数量の更新）をしても、集計表のスクロールの位置が戻されない。別の項目を選ぶと、その行へスクロールする。
