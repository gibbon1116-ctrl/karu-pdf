# SPEC-B27: 柱・壁を線で拾う RC 部材、線要素の「1m あたり」の係数（スパイラル筋）、線要素に溝掘削

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: RC 部材の計算の拡張、拾いの保存形式（線要素の係数）の拡張、数量の索引の線要素の計算、線要素の選択画面、図面の札、単体・e2e にまたがる

---

## 背景（利用者の要望、2026-10-12）

> 梁や柱は直線でその長さと周長で計算できる設定が欲しい。RC部材にも設定できるようにしたうえで、スパイラル筋を線要素の追加で計上できるようにしたい。また、電気の埋設管を計上する際にも、土工の溝掘削を線要素として追加できるようにしたい。

今:
- 線（`polyline`）の拾いで選べる RC 部材は梁・基礎梁だけ。柱は個数、壁は長さ×高さの拾いが前提（`src/app/FixtureDialog.tsx` の `rcKindsFor`、`src/core/rcMember.ts` の `computeRcMember`）。
- 「線要素を追加」（`src/app/LinePicker.tsx`、拾いの `QuantityMark.extra: { itemId, count, cond? }[]`）は、線で拾う項目だけを、整数の条数で重ねる。スパイラル筋のように部材 1m あたりの長さ（径 × π ÷ ピッチ）を掛ける係数は持てない。
- 「ケーブル・配管の溝掘削（長さ×幅×深さ）」（土工、`method: 'lengthWidthDepth'`、既定 幅 0.6・深さ 0.8）は体積の項目なので、線要素に選べない。

## 対象

- 変えない: データ、連動の計算

## 1. 線で拾う柱・壁（RC 部材）

- 線の項目の RC 部材の種類に **柱** と **壁** を足す（梁・基礎梁は今のまま）。
- 柱（線）: 線の長さ L = 柱の高さ（立面・断面の図で柱を線で拾う）。断面 幅 b × せい D（入力、必須）。コンクリート = b × D × L、型枠 = 断面の周長 2(b＋D) × L、主筋 = 本数 × (L ＋ 重ね継手)（今の柱の式の高さを L に）、フープ = 本数 L ÷ 間隔 の切り上げ＋1、1 本 = 2(b＋D)。
- 壁（線）: 線の長さ L = 壁の長さ。厚さ（入力、必須）、高さ H（`heightMm`、必須）。コンクリート = L × H × 厚さ、型枠 = 2 × L × H、縦筋・横筋は今の壁の式に L・H。
- 拾いの数（同じ線の重なり）は今の梁と同じ扱い。根拠の文に `柱 0.60×0.60m 断面の周長 2.40m × 長さ 3.50m` のように読んだ値を出す。
- 名前からの既定の種類（SPEC-B25）: 線の項目で `柱` → 柱、`壁` → 壁、`梁` → 梁、`基礎` → 基礎梁。

## 2. 線要素の「1m あたり」の係数

- 拾いの線要素 `extra` の各要素に省略可能な `perM?: number`（線 1m あたりの数量。0 より大きく 10000 以下、小数 3 桁まで。省略は 1）。読込で不正な値は捨てる（要素は残す）。保存の上限・形式の検査に入れる。
- 線要素の数量 = 線要素の長さ（今の計算: 平面＋立上り＋余長、施工条件ごと）× 条数 × `perM`。数量の換算（`convert`、例: スパイラル筋 D10 の t）は今のとおり後でかかる。
- 線要素の画面（線要素の一覧の各行）に「1m あたり」の入力（空 = 1、`aria-label="${略号 名前}の1mあたり"`）。名前に `スパイラル` を含む項目の行には `径とピッチから` のボタン: 径（m）とピッチ（m）を入れると π × 径 ÷ ピッチ を小数 3 桁に丸めて入れる。
- 図面の札・集計の根拠: `SP D10 ×18.850/m` のように出す（1 のときは今のまま）。
- 同じ項目の印すべてに構成を反映（今の「同じ項目の印すべてにこの構成を反映」）でも `perM` を写す。

## 3. 線要素に溝掘削（体積の項目）

- 線要素の候補に、`method: 'lengthWidthDepth'`（長さ×幅×深さ）の項目も出す（今の線で拾う項目に加えて。見出し「この PDF の項目」の中で同じ並び）。標準マスタからの候補（`LinePicker` の標準マスタ）にも、長さ×幅×深さの項目（土工の溝掘削など）を出す。
- その線要素の数量 = 線要素の長さ × 条数 × `perM` × 幅 × 深さ（幅・深さは**その項目の既定値** `defaults.widthM`・`defaults.depthM`。無ければ 0 で、線要素の行に `幅・深さを項目に入れてください` と出す）。単位は ㎥。
- 立上り・余長は、溝掘削の線要素では使わない（平面の長さだけ。線要素の施工条件の「平面」「立上り」「余長」の扱いは今の仕組みのまま、溝掘削の行は既定で平面だけ）。

## 4. 試験

- 単体: 柱（線 3.5m、0.6×0.6、主筋 D22 12本、フープ D10@100）→ コンクリート 1.26㎥、型枠 8.4㎡、フープ 36本 × 2.4m。壁（線 5m、厚さ 0.2、高さ 3m）→ コンクリート 3㎥、型枠 30㎡。線要素 `perM` 18.85 のスパイラル筋（D10 の換算 0.56kg/m → t）を 10m の線に → 188.5m → 0.10556 t。読込の不正な `perM`（0・負・文字）を捨てる。溝掘削（幅 0.6・深さ 0.8）を 25m の線要素に → 12㎥。今の線要素（`perM` なし）の数量は今と同じ。
- e2e: (1) 電気の埋設管（FEP など線の項目）を 25m 拾い、線要素を追加で「ケーブル・配管の溝掘削」を選ぶ → 溝掘削の全図面が `12.00`（㎥）。(2) 線の項目を RC 部材の柱にし、スパイラル筋（D10）を線要素に足して `径とピッチから` 0.6・0.1 → 1m あたり 18.850。拾った長さに応じた t が出る。
