# SPEC-B31: RC 部材の連動で、鉄筋の項目の摘要の径・規格に合う鉄筋だけを数える

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: RC 部材のデータ（鉄筋の規格）の追加・読込・検査、連動の計算の絞り込み、根拠の文、項目の編集画面、e2e にまたがる

---

## 背景（利用者の試用の結果、2026-10-13）

> RC部材に設定したとき、径をD13の鉄筋を選択していても、D10やD19の配筋も全て0.68で数量が計上される。指定した鉄筋だけ数量が計上されるようにしたい。また、D13の鉄筋でも、規格が違う場合は選ばれないようにしたい。

今:
- RC 部材（`CountFixture.rc: RcMember`、`src/core/rcMember.ts`）の鉄筋 `RcBar` は 役割・径・間隔/本数・段 を持つ。規格（SD295 など）は無い。
- 異形鉄筋の項目（内訳書の摘要 `規格`・`径`、例: `SD295`・`D13`）は、連動 `link.kind === 'rc'`・`link.rc.output === 'rebar'` で RC 部材から数量を出す。`link.rc.sizes`（「径で絞る」のチェック）が無いと全部の径を合計するため、D10・D13・D19 の 3 項目がどれも同じ値（0.68t）になる。
- 規格のデータ: `src/core/breakdown/rcData.ts` に `REBAR_GRADES = ['SD295', 'SD345', 'SD390', 'SD490']`（Claude が追加済み、変えない）。

## 対象

- 変更: `src/core/rcMember.ts`（`RcBar.grade`、検査・読込、計算結果の鉄筋に `grade` を写す）、`src/core/fixtureLink.ts`（絞り込み・根拠）、`src/app/FixtureDialog.tsx`（鉄筋の表の規格の欄、連動の説明）
- 試験: 単体（`tests/rcMember.test.ts`・`tests/fixtureLink.test.ts` など既存に追記、または新規 `tests/rcRebarFilter.test.ts`）、e2e 1 件（RC 部材の既存の e2e のファイルに追記）
- 変えない: データ、コンクリート・型枠の連動、`link.rc.sizes` の保存形式

## 1. 鉄筋の規格（`rcMember.ts`・`FixtureDialog.tsx`）

- `RcBar` に省略可能な `grade?: string`（`REBAR_GRADES` のどれか）。`rcMemberError` で、あるのに一覧に無ければ `鉄筋の規格は SD295・SD345・SD390・SD490 から選んでください。`。`readRcMember` で写す（不正なら今のとおり部材ごと捨てる）。`computeRcMember` の結果の `bars[]` に `grade`（あれば）を写す。
- 項目の編集の RC 部材の「鉄筋」の表に、径の右へ `規格` の列（select、`aria-label` は `鉄筋${n}の規格`、選択肢は `—`（指定なし、値 ''）と `REBAR_GRADES`）。「＋ 鉄筋を足す」で足す行は、直前の行の規格を引き継ぐ（無ければ指定なし）。
- 見本（今の拾いで計算した見本）の鉄筋の径ごとの表は、規格があれば `SD295 D13` のように径の前に出す（径と規格の組でまとめる）。

## 2. 連動の絞り込み（`fixtureLink.ts`）

連動の先の項目（`fixture`、`link.kind === 'rc'`）の出力が `rebar`・`gasJoint`・`lapJoint` のとき、元の RC 部材の鉄筋を次で絞ってから計算する（今の `lapJoint` の前処理と同じく、`computeRcMember` に渡す部材の `bars` を絞る形にまとめてよい。コンクリート・型枠は絞らない）。

- **径**: `link.rc.sizes` があればそれ（今のまま、優先）。無ければ、先の項目の摘要（`fixture.summary` の `label === '径'` の値）と `fixture.spec` から `/D\d+/g` で取り出した、`REBAR_MASS_KG_PER_M` にある径。どれも無ければ絞らない（今のまま）。
- **規格**: 先の項目の摘要（`label === '規格'`）と `fixture.spec` から `REBAR_GRADES` の語を取り出す。あれば、鉄筋のうち `grade` がその中にあるもの **と、`grade` が無いもの** を数える（規格の指定が無い鉄筋は、どの規格の項目にも入る。今のデータを壊さないため）。規格の語が無い項目は規格で絞らない。
- 絞った結果 RC 部材のどの鉄筋も合わないとき、その部材の数量は 0 とし、根拠の文に `この部材に ${径・規格} の鉄筋はありません` を出す（警告には入れない）。
- 規格の指定が無い鉄筋を規格で絞る項目に入れたときは、根拠の文の鉄筋の説明に `（規格の指定なし）` を付ける。
- 根拠の文（`rcOutputNote`）の鉄筋の説明は、規格があれば `SD295 D13 x方向 …` と規格を径の前に出す。

## 3. 項目の編集の連動の説明（`FixtureDialog.tsx`）

- 「径で絞る（どれも付けなければ全部）」の見出しを、`径で絞る（どれも付けなければ摘要の径 ${D13}。摘要にも無ければ全部）` にする（摘要に径が無いときは `径で絞る（どれも付けなければ全部）` のまま）。その下に摘要の規格があれば `規格: 摘要の ${SD295} の鉄筋と、規格の指定が無い鉄筋を数えます` を出す。

## 4. 試験

- 単体:
  - 基礎スラブ（x・y 方向 D13@200、規格 SD295）の RC 部材の拾い 1 件から、異形鉄筋の項目 3 件（摘要の径 D10・D13・D19、規格 SD295、所要数量）が連動する。D13 の項目だけが数量を持ち、D10・D19 は 0、根拠に `この部材に D10 の鉄筋はありません`（文の形は 2 の通り）。
  - 同じ部材で、D13・SD345 の項目は 0。鉄筋の規格を指定なしにすると SD345 の項目にも入り、根拠に `（規格の指定なし）`。
  - `link.rc.sizes` が摘要の径より優先する。摘要に径の無い項目（鉄筋加工組立など）は全部の径を数える（今のまま）。
  - `rcMemberError`・`readRcMember`: 正しい規格を写す、不正な規格の部材を捨てる。
- e2e: RC 部材（基礎スラブ、D13@200 SD295 の x・y）に、異形鉄筋の D10 と D13 の項目（SD295）を連動させ、数量の一覧で D13 だけが 0 でなく、D10 が 0.00 になる。鉄筋の表の規格の欄で SD345 を選ぶと D13 の項目も 0.00 になる。

## 禁止事項

- データを変えないこと。コンクリート・型枠の数量を変えないこと。摘要に径・規格の無い連動の項目の数量を変えないこと。依存パッケージを足さないこと。git と試験の実行をしないこと。
