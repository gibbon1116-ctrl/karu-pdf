# SPEC-R6c: 選択済みの関連項目を、ボタン1つで経路の線要素・頂点の個数に入れる

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: R6a のストアの処理（履歴をまとめる）を既存の項目にも使えるよう変える判断を伴うため既定の sol-high。

---

## 背景

R6a で、関連の候補の「追加する」で項目を**新しく追加したとき**は、起点の線項目の経路（線要素）や選んでいる経路（頂点の個数）に自動で入るようになった。

ただし、提案先の項目が**すでに文書にある**ときは、候補が「選択済み」になる（R5a。判断のボタンを出さない）。この場合、経路に入れる手段が無い。

例: PF22（電線管）がある文書で、ケーブルの候補 E-001「保護管・配線用電線管」は選択済みになり、ケーブルの経路に PF22 を線要素として入れられない。

## 変更内容

### 1. ストア

`addRelatedFixturesToRoute(originId, fixtures, routeId?)`（R6a）の第2引数に、**文書にすでにある項目も渡せる**ようにする。

- ID が文書の項目にあるものは既存として扱い、追加しない（`newFixtures` にしない）。
- 無いものだけを新しい項目として追加する。
- 線要素・頂点の個数・これからの経路・テンプレートへの反映と、1つの履歴にまとめる規則は R6a のまま。
- 引数の名前は `fixtures` に変える。呼び出し側（`fixtureAdd.ts`）は、今の新しい項目をそのまま渡す。

### 2. 候補のカード（`RelatedSuggestions`）

次の条件をすべて満たすカードに、ボタン**「経路に入れる」**（`aria-label="経路に入れる"`）を出す。

- 選択済み（`flags.registered`）で判断が無い。
- 右のパネルの項目（起点）が線項目（`quantityMethod === 'polyline'`、連動でない）。
- 当たる項目に、次のどちらかがある。当たる項目は、item は提案先の分類・名称、check は `create.name` で照合する（選択済みの判定と同じ）。
  - 線項目、または面積の線要素の項目（`isRouteSurfaceFixture`）
  - 個数の項目で、`routeId` がある

押したときの動き:

- 判断「必要」を記録する（今の `decide`）。
- 当たる項目（線・面積・個数）を `context`（`originFixtureId`・`routeId`）と一緒に新しいコールバック `onApplyToRoute(fixtureIds: string[], context: RelatedAddContext)` に渡す。
- `FormatPanel` は `store.addRelatedFixturesToRoute(起点, 当たる項目, routeId)` を呼ぶ。
- 状態の文は `fixtureAdd.ts` の文の作りと同じ。
  - 例「PF22 を VVF 1.6-2C の経路 2 本とこれからの経路の線要素に入れました（Ctrl+Z で戻せます）」
  - 文は `FormatPanel` の既存の状態欄（`pickupError` の `role="alert"` ではなく `role="status"` の小さな文）に出す。
- 経路は選んだまま（選択を変えない）。
- 当たる項目が複数あるとき（例: 電線管が PF16・PF22 の2つ）は、カードの中に `<select aria-label="経路に入れる項目">` を出して1つ選ばせる。既定は並びの先頭。

### 3. 試験

- 単体（ストア）: 既存の項目を渡すと、項目は増えず、経路の線要素・これからの経路に入る。Undo 1回で戻る。既存と新規を混ぜたときは新規だけ増える。
- e2e（`e2e/related-route.annotate.spec.ts` に追加）:
  - ケーブル（低圧）の経路を選んだ状態で、選択済みの E-001（PF22 がある）の「経路に入れる」を押す。
  - 選んでいる経路と、もう一方のケーブルの経路の線要素に PF22 が入る。
  - Ctrl+Z で戻る。

## 受入条件・停止条件

- 選択済みのカードの表示は、起点が線項目でないときは今と同じ（ボタンを出さない）。
- 関連・経路の e2e と単体試験全件が合格。
- 戻し方: この段階のコミットの revert。

## 禁止事項

- 保存形式を変えない。
- 押されない限り経路を変えない。
- 外部通信を足さない。`https://` を含む文字列を足さない。git 操作をしない。
