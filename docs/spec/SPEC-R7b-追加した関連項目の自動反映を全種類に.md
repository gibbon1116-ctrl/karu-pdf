# SPEC-R7b: 「追加する」で追加した関連の項目を、起点の種類にかかわらず自動で反映する

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 連動（`FixtureLink`）・構成要素・経路への反映を起点と提案先の種類ごとに振り分け、1つの履歴にまとめる判断を伴うため既定の sol-high。

---

## 背景（利用者の意見、2026-10-14）

> 現状、自動で数量拾いで関連する項目を追加するとき、長さの要素だけ、「追加する」を選択した項目が自動で追加されるようになっているが、個数や面積等他の全ての項目についても同様に対応したい。

今（R6a）は、起点が線項目（`polyline`）のときだけ、追加した項目を経路の線要素・頂点の個数に入れる（`src/app/fixtureAdd.ts` の `commitAddedFixtures` → `store.addRelatedFixturesToRoute`）。それ以外の起点では、項目を追加するだけ。

## 決めごと（Claude）

起点の項目（`context.originFixtureId`）と、追加した項目の種類の組で、次のように自動で反映する。
- 「種類」は `quantityMethod` / `quantityKind`。
- 「連動」は `CountFixture.link`（`src/core/fixtureLink.ts`）。

| 起点 | 追加した項目 | 自動の反映 |
|---|---|---|
| 線（`polyline`） | 線・面積の線要素 | 経路の線要素（R6a。変えない） |
| 線 | 個数 | 選んだ経路の頂点の個数（R6a。変えない） |
| 個数（`click`） | 個数 | 起点のすべての個数の印と、これからの印の**構成要素**（R5b の `store.addComponentToFixture` と同じ。数 1） |
| 個数 | 長さ・面積・体積 | **連動（係数）**: `link = { kind: 'factor', sources: [{ itemId: 起点, factor: 1 }] }`（1個あたり 1。項目の画面で直せる） |
| 面積（`polygon`・`lengthHeight`） | 面積 | **連動（係数）**: `sources: [{ itemId: 起点, factor: 1 }]`（同じ面積） |
| 面積（`polygon`） | 長さ | **連動（形・周長）**: `link = { kind: 'shape', shape: { output: 'perimeter' }, sources: [{ itemId: 起点 }] }` |
| 体積（`polygonDepth`・`lengthWidthDepth`） | 体積 | **連動（係数）**: `sources: [{ itemId: 起点, factor: 1 }]` |
| 上の表に無い組（面積 → 個数 等）、起点が連動の項目 | なし | 項目を追加するだけ。状態の文で「図面で拾ってください」と案内する |

- **連動にする**のは、追加した項目に、まだ印・拾いが無いとき（`fixtureMarkCount === 0`）だけ。
  - 新しく追加した項目は印が無い。
  - 連動の項目は図面に拾えないので、印のある項目は連動にしない（案内だけ）。
- **同じ項目がすでに連動（係数）のとき**は、その連動の元に起点を足す（`sources` に `{ itemId: 起点, factor: 1 }`。重複しない。元は 50 件まで）。
  - 例: 天井ボード A から追加した「軽量鉄骨天井下地」に、天井ボード B からも追加すると、元が A と B の2件になる。
  - 標準マスタで同じ項目（`fixtureIdentity` が同じ）を選んだときは、新しく作らず既存の項目を使う。
- 連動の検査は `fixtureLinkError`（今のまま）。検査に通らないときは連動にせず、項目の追加だけにして理由を状態の文に出す。
- R6c の「経路に入れる」と同じく、**選択済み**（提案先の項目がすでにある）のカードにも、起点が個数・面積・体積のとき、上の表の反映をするボタンを出す。
  - ボタンの名前: 起点が線なら「経路に入れる」、個数で提案先が個数なら「構成要素に入れる」、連動になる組なら「連動にする」。
  - 印のある項目は連動にできないので、その組ではボタンを出さない。

## ストア

- 新しいメソッド `applyRelatedAdditions(originId, fixtures, routeId?)` を作る。
  - 振り分けは `fixtureAdd.ts` ではなくストアに置き、1つの履歴にまとめる。
  - 上の表に従って次をすべて行い、**Undo 1回**で戻るようにする:
    - 項目の追加（引数の項目のうち文書に無いもの）
    - 経路（R6a の `addRelatedFixturesToRoute` の処理）
    - 構成要素（R5b の処理）
    - 連動の設定（項目の `link` の設定・元の追加）
  - 戻り値は、反映の件数（経路・頂点の行・構成要素の印・連動にした項目・元を足した項目・案内だけの項目）。
- `addRelatedFixturesToRoute`・`addComponentToFixture` は残し、新しいメソッドから共通の処理を使う（既存の呼び出し・試験は変えない）。

## 画面

- `src/app/fixtureAdd.ts` の `commitAddedFixtures` は、起点の種類にかかわらず `applyRelatedAdditions` を呼ぶ。
- 状態の文は反映の種類ごとに作る。例:
  - 「軽量鉄骨天井下地 を天井ボード の連動（同じ面積）にしました」
  - 「スイッチボックス を S スイッチ の印 12 個とこれからの印の構成要素に入れました」
  - 「天井点検口 は図面で拾ってください」

  末尾に「（Ctrl+Z で戻せます）」。
- 連動にした項目は、今の連動の項目と同じく一覧で「連動」の印が付き、数量が起点から計算される（今の仕組み）。

## 試験

- 単体（ストア）:
  - 個数の起点 → 個数の項目を追加すると、起点の印すべて（とこれからの印）の構成要素に入る。
  - 面積の起点 → 面積の項目を追加すると、その項目が連動（係数 1、元＝起点）になり、`QuantityIndex` の数量が起点と同じになる。
  - 面積（囲む）の起点 → 長さの項目を追加すると、連動（形・周長）になる。
  - 個数の起点 → 長さの項目を追加すると、連動（係数 1）になる。
  - 体積 → 体積は連動（係数 1）。
  - 同じ項目に2つ目の起点から追加すると、元が2件になる。
  - 印のある項目は連動にしない。
  - 面積 → 個数は追加だけ。
  - それぞれ Undo 1回で全部戻る。
- e2e（`e2e/related-auto-apply.annotate.spec.ts`）:
  - 天井の面積の項目（`polygon`）を起点に、確認事項の「追加する」（新しい項目の画面で単位 ㎡）→ 保存。
  - 追加した項目が連動になり、起点の面積と同じ数量になる。
  - Ctrl+Z で戻る。
- 既存の関連・経路・構成要素・連動の e2e と単体試験全件が合格。

## 受入条件・停止条件

- 「追加する」・選択済みのボタンを押さない限り、項目・印・連動は変わらない。
- 戻し方: この段階のコミットの revert。

## 禁止事項

- 保存形式（`CountFixture`・`FixtureLink`・印）を変えない。今ある連動の計算を変えない。
- 外部通信を足さない。`https://` を含む文字列を足さない。git 操作をしない。
