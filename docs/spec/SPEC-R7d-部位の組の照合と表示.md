# SPEC-R7d: 部位の組（建築）の照合と、役割ごとの表示・どれか1つの畳み

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 照合（名称の正規化・品目作業の未設定）と、提案の表示のまとめ方を変える判断を伴うため既定の sol-high。

---

## 背景

利用者の依頼と決定（2026-10-14）:

- 建築の関連項目が少なすぎる（例: 軽量鉄骨天井下地の改修・更新で、天井仕上げの撤去・養生・足場・廻り縁・ボード・点検口・塗装/クロスが出ない）。
- 決定:
  - 「どれか1つ」の候補は、1つ追加したら残りを畳む。
  - 改修で品目作業が未設定なら、撤去は確認事項として出す。
  - 仮設は部位ごとに毎回出す。
  - 書式に独立の行が無い作業は標準マスタに事前に作る。

Claude がデータを作成済み（コミット 714d734）:

- `src/core/related/rules.ts` に部位の組のルール 274 件（ID `A-…`）。
  - 天井・壁・床・建具・外壁・屋上防水・塗装（塗替え）・内部のユニット・金物。
  - 各ルールに `role`（仮設・撤去・下地・主仕上げ・表面処理・附属・処理・確認）・`assembly`（部位名）・必要なら `oneOf`（同時にはあり得ない候補の群）がある。
  - 起点は `origin.any[].names`（品目名の完全一致）。
  - 改修で品目作業が未設定のときの撤去の確認事項は `works: ['未設定']`。
- `src/core/related/types.ts`: `AssemblyRole`・`ASSEMBLY_ROLES`・`UNSET_WORK = '未設定'`・`WorkMatch`。`RelatedOriginMatch.works` は `WorkMatch[]`。
- `src/core/breakdown/buildingGroups.ts`: 書式に無い撤去の行 11 件を追加。
- 品目名の長音の記号ゆれ（－・-）を「ー」にそろえた。

## 変更内容

### 1. 照合（`src/core/related/suggest.ts`）

- **品目作業の未設定**: `originMatches` で、`match.works` に `'未設定'` があり起点の品目作業が無い（`undefined`）ときは一致とする。ほかは今と同じ。
- **名称の正規化**: 起点の名称の照合（`buildRelatedIndex` の `names` の索引と `originMatches`）を、正規化した名称で比べる。提案先の解決（`src/app/relatedModel.ts` の `resolveTarget` の `item.name === target.name`）も正規化して比べる。

  正規化の関数 `normalizeItemName(text)` を `src/core/related/suggest.ts`（またはそれが使う新しいファイル）に置く:
  - NFKC
  - カタカナの直後の `-`・`－`・`‐`・`−` を「ー」
  - 空白（全角・半角）を除く

  これで、以前の PDF に残る「天井せっこうボ－ド張り」等の項目にも当たる。
- **選択済み**の判定（提案先の項目が文書にあるか）も、名称を正規化して比べる。check の `create.name` との比較も同じ。
- `RelatedSuggestion` に `role?`・`assembly?`・`oneOf?` を足す（ルールから写す。集約したときは最初に見つかった値を残す）。

### 2. 表示（`src/app/RelatedSuggestions.tsx`、右の数量拾いの「関連の候補」）

- 判断の無い候補（今の `ordinary` と選択済み）のうち **`role` があるもの**は、役割ごとの見出しでまとめる。
  - 見出しの順は `ASSEMBLY_ROLES`。見出しは「仮設 3件」のように `<h4>` 相当で、`data-testid="related-role-group"`・`data-role` を付ける。
  - `role` の無い候補（Excel 由来）は、今までどおりその後に並べる。
  - 「すべて見る」（5件まで）の扱いは、役割の見出しのある候補には使わない（全部出す）。役割の無い候補には今のまま使う。
- **どれか1つ（`oneOf`）の畳み**: 同じ `oneOf` の候補のうち、どれかが次のどれかになったら、残りの候補（判断の無いもの）を `<details>`「ほかの候補 n件」に畳む。
  - 選択済み（提案先の項目が文書にある）
  - 判断「必要」・「構成要素で拾う」
  - 畳んだ候補は、未判断の件数にも数えない（`relatedReviewList` で、同じ起点の同じ `oneOf` に選択済みか「必要」のものがあれば、残りを未判断から除く）。
- 確認事項の撤去（`kindText` が「撤去の確認」）は、今の確認事項のカードと同じ（「追加する」で新しい項目の画面）。

### 3. 標準マスタの追加の行

書式に無い行（`note` が「書式に独立の行なし…」）も、標準マスタの検索・内訳書の位置の候補（R6d）に今の行と同じく出る（データの追加だけで出るはず。出なければ合わせる）。
