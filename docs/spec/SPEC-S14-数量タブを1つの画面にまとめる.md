# SPEC-S14: 数量タブの「拾う」「管理」を 1 つの画面にまとめ、一覧を広くする

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 数量タブの画面の作りを変える。既存の部品をすべて残しつつ、並びと高さの配分を決め直す判断が要る

---

## 利用者の要望

> 数量拾いで「拾う」「管理」画面が分かれていると使いづらい。統合したいが、管理画面の2枚目に添付した縦スクロールできる部分（項目の一覧）が小さく見にくい。設置した項目の種類は変えずに配置を見直して、使用しやすい構成にしたい。

利用者が選んだ配置（案 A：操作が上・一覧が下）：

```
数量拾い   [集計表][数量をCSVに書き出す][同じ記号を探す]
┌■ BE 20形 ベースライト（埋込）─────┐
│ この図面 8個 ／ 全図面 8個          │
│ [編集][複製][削除][上へ][下へ]      │
└──────────────────────┘
[項目を追加][標準マスタから追加][他のPDFから読み込む]
最近: [DL φ100][BE 20形]  構成: [幹線A]
場所 階[5階    ] 部屋[        ]
▸ 表示の設定・図面番号（折りたたみ）
[名称・略号で検索                ]
┌─一覧（残りの高さをすべて使う）───┐
│表示 印 見本 略号 名称 この図面 全図面│
│▾ 照明器具（12）              👁 │
│👁 ○ ▣ DL ダウンライトφ100  0  15│
│  …                               │
└──────────────────────┘
```

## 現状（Claude Code が確かめたこと。`src/app/FixturePanel.tsx`）

- `mode`（`'pickup' | 'manage'`、`localStorage` の `karu-pdf:fixture-panel-mode`）で表示を切り替える。見出しに「拾う」「管理」のボタン。
- 「管理」だけに出るもの：図面番号の読み取り状態の文（読み取り中・失敗のときは「拾う」でも出る）、「図面番号・図面名称を読み直す」、「複製」「編集」「削除」、「他のPDFから読み込む」「数量をCSVに書き出す」「上へ」「下へ」、4 つのチェック（選択中の項目だけ表示・図面に長さ…の数値を表示・スナップ・図面の線の端点にも合わせる）、「すべて表示」、一覧の「表示」（目）の列・「見本」の列・つまみ（ドラッグで並べ替え）・規格の表示・見本の拡大表示。
- 「拾う」だけに出るもの：最近使った項目（`RecentFixtures`）、よく使う構成。
- 両方に出るもの：集計表、同じ記号を探す、選んだ項目の数量の欄、項目を追加、標準マスタから追加、現在の場所、名称・略号で検索、一覧。
- 一覧（`.fixture-groups`）は残りの高さを使うが、その上に部品が縦に積まれ、一覧が狭い。

## 変更内容

### 1. 切替をやめる（`src/app/FixturePanel.tsx`）

- `mode`・`managing`・「拾う」「管理」のボタンを無くす。`localStorage` の `karu-pdf:fixture-panel-mode` は読まない（残っていても無視）。
- **部品の種類は 1 つも減らさない。** 上の「管理だけ」「拾うだけ」「両方」のすべてを、1 つの画面に出す。
  - 一覧の列は「管理」のもの（表示・印・見本・略号・名称・この図面・全図面）。つまみ・ドラッグでの並べ替え（検索が空で、編集できるとき）・規格・見本の拡大表示も出す。
- ボタンの名前（表示の文字と `aria-label`）は今と同じにする（試験と利用者の慣れのため）。
- `section` の class は `fixture-panel` だけにする（`fixture-panel-pickup`・`fixture-panel-manage` を外す）。

### 2. 並べ方（上から）

1. 見出しの行：`数量拾い` と、ボタン「集計表」「数量をCSVに書き出す」「同じ記号を探す」（今の条件で出す）。幅が足りなければ折り返す。
2. 書き込みタブの絞り込みの警告（今と同じ条件）。読込み中の表示。
3. **選んだ項目の欄**（今の `fixture-count-summary`）。その欄の中、数量の下に「編集」「複製」「削除」「上へ」「下へ」。
   - 項目を選んでいないときは、今の文「数量拾いの一覧で項目を選んでください」と、押せないボタン。
   - 印が多いときの注意（`visibleCountTotal > 1000`）はこの欄の下。
4. 追加の行：「項目を追加」「標準マスタから追加」「他のPDFから読み込む」。
5. 最近使った項目とよく使う構成。1〜2 行に収まる小さなボタンで、横に並べて折り返す（今の「拾う」の見た目）。無ければ出さない。
6. 現在の場所：1 行（今の「拾う」の見た目。階・部屋を横に並べる。図面名からの推定の小さな文字は、入力欄の `placeholder` か `title` に移してよい）。
7. **折りたたみ「表示の設定・図面番号」**（`<details>`、`summary` の文字は「表示の設定・図面番号」）：
   - 中身：図面番号の読み取り状態の文、「図面番号・図面名称を読み直す」、4 つのチェック、「すべて表示」。
   - 初めは閉じる。開閉は `localStorage` の `karu-pdf:fixture-panel-settings-open` に覚える（読めなければ閉じる）。
   - 読み取り中・失敗のときは、状態の文を折りたたみの外（この行の上）にも出す（今の「拾う」と同じ）。
8. 名称・略号で検索（一覧のすぐ上）。
9. 状態・エラーの文（`status`・`error`）。
10. 一覧（残りの高さをすべて使う）。

### 3. 高さの配分（`src/styles.css`）

- パネルは今と同じく縦の flex（`.fixture-panel`）。
- 上の部品（1〜9）を入れる部分は、高さがパネルの 45% を超えたら、その部分の中で縦にスクロールする（一覧の高さを守る）。
- 一覧（`.fixture-groups`）は残りの高さをすべて使い、最低 200px。見出しの行（`fixture-list-heading`）は今と同じく一覧の上に固定。
- 選んだ項目の欄のボタン・追加の行のボタンは、今の「管理」の小さなボタンと同じ大きさ。
- 「拾う」「管理」の見出しのボタン用の CSS、`fixture-panel-pickup` 用の CSS は、使わなくなるので消すか、新しい並びに合わせて直す。`fixture-panel-manage` 用があれば同じ。
- 画面の幅が狭い（パネル 300px 程度）ときも、横にはみ出さないこと。

### 4. ヘルプ（`src/app/HelpDialog.tsx`）

- 「左の数量タブは「拾う」と「管理」で表示を切り替え…」の文を、統合後の説明に直す。例：
  > 左の数量タブは、上に選んだ項目の数量と操作、追加・最近使った項目・現在の場所を、下に項目の一覧を表示します。表示の設定と図面番号の読み直しは「表示の設定・図面番号」を開いて使います。
- 「右欄では選んだ経路を置き換え、左の数量タブの「拾う」では新しい経路の雛形にします」の「拾う」は「数量タブ」に直す。
- ほかの文は変えない。

## 変えないこと

- 部品の種類・名前・働き（追加・編集・削除・並べ替え・表示切替・見本・集計・CSV・検索・場所・チェック）。
- 拾いバー（`PickupBar.tsx`）。
- 保存データ。数量の計算。

## 試験

**画面の試験の直し**（Claude Code が行う）：既存の試験が「管理」「拾う」のボタンを押している箇所（20 ファイル、64 か所）は、Claude Code がまとめて消す。Codex は直さなくてよい。

**新しい画面の試験**（新規 `e2e/fixture-panel-layout.annotate.spec.ts`）：
- 数量タブに「拾う」「管理」のボタンが無い。
- 次の部品が同時に見える（折りたたみを開いた状態を含む）：集計表、数量をCSVに書き出す、項目を追加、標準マスタから追加、他のPDFから読み込む、編集、複製、削除、上へ、下へ、現在の階・部屋、名称・略号で検索、一覧の見出し（表示・印・見本・略号・名称・この図面・全図面）。
- 「表示の設定・図面番号」は初めは閉じ、開くと 4 つのチェックと「すべて表示」「図面番号・図面名称を読み直す」が出る。開閉はページを読み直しても覚えている。
- 一覧の高さ：画面 1440×900 で、一覧（`.fixture-groups`）の高さがパネルの高さの 50% 以上。
- 項目を 30 個ほど足しても、一覧の中で縦にスクロールでき、パネル全体ははみ出さない。
