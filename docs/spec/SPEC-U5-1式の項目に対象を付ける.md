# SPEC-U5: 1式の項目に、何の1式かを名称と摘要で示す

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol`
- reasoning effort: `high`
- 選定理由: 標準マスタから作る項目の名称・摘要の作り方を変え、規格・内訳書の両タブと既存の試験に波及するため既定の sol-high。

---

## 背景

利用者の意見（2026-10-14、試用版 第5版）:

> 据付が一式形状になるのは構わないが、何の据付が入っているのか分からない。エクセルで出力すれば分かるが、集計表でも分かるようにしたい。

U2 で、品目の無い1式の行（据付費・試験調整費・諸経費 等）を「1式の項目」にした。

- 規格タブでは同じ名称の行を1品目にまとめた（分類 `LUMP_SUM_CATEGORY` 等）。
- 作った項目は名称が「据付費」だけ。
- 集計表は分類「1式（経費・工事）」の下に出るので、どの設備の据付費か分からない。

## 変更内容（`src/core/catalog.ts` の `catalogPresets`）

**対象:** 次のすべてに当たる品目から作る項目。

- 品目の編が電気設備・機械設備
- 鍵が `row:`
- 単位が `式`
- 内訳書の位置（`position`）がある

**名称:** `{細目名}（{対象}）`

- 対象は `position.middle` があればそれ、無ければ `position.subject`。
- 例「据付費（自家発電（原動機））」「試験調整費（監視カメラ設備）」「諸経費（ガス設備）」。

**摘要:** 区分 `対象` を先頭に足す。

- 値は `[position.subject, position.middle].filter(Boolean).join(' ')`。例「発電設備 自家発電（原動機）」。
- 既に `対象` の区分があれば置き換える。

**その他:**

- 内訳書の位置が無いとき（「付けない」）は今のまま（名称「据付費」）。
- `fixtureIdentity` は名称・摘要を含むので、位置ごとに別の項目になる（同じ位置で2回追加しても1つ）。
- 既に PDF にある項目は変えない。

## 試験

- **単体（`tests/catalog.mergedRows.test.ts` に追加）:**
  - 電気設備の「据付費」に 発電設備 › 自家発電（原動機） の位置を渡すと、名称「据付費（自家発電（原動機））」、摘要の先頭が `{ label: '対象', value: '発電設備 自家発電（原動機）' }`。
  - 中科目の無い位置（電気自動車用充電設備）では名称「据付費（電気自動車用充電設備）」。
  - 位置が無いと名称は「据付費」、摘要に対象が無い。
  - 単位が式でない品目（開閉器箱）は名称が変わらない。
- **e2e:** `e2e/catalog-merged-rows.annotate.spec.ts` の据付費の試験の期待を新しい名称・摘要に直す。
  - 数量パネルの集計表（「集計表」ボタン）に「据付費（自家発電（原動機））」の行が出ることを足す。
- 既存の試験で、1式の行の項目の名称を前提にしている所があれば直す。
