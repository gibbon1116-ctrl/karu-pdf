# SPEC-T8: 「項目を編集」の画面を、初めての人が戸惑わない構成にする

## 実行モデル指定（必須）

- モデル: `gpt-6.1-sol` / reasoning effort: `high`
- 選定理由: 既存の中核画面（src/app/FixtureDialog.tsx、約2,200行）の構成を、保存データを壊さずに作り直す判断を伴うため。

## 利用者の指示（2026-10-18）

- 「項目を編集」も、感覚的に使え、使用者が戸惑わない構成にする。
- 入力は原則として選択式。選択では表せず正しく拾うために欠かせない最低限の情報だけを自由記入にする。不要な記入欄は削除する。

## 現状の欄（ラベルの棚卸し）

種別・拾い方・名称・略号・規格・集計方式・分類（新しい分類の名前）・透明度・メモ・内訳書（単位・編・種目・科目・中科目・細目＋各候補）・摘要（区分名・値）・備考・質量・寸法（発生材の種類）・連動（標準の規則・連動の種類・RC/形/交差/鉄骨からの計算・元の項目の検索・係数・施工条件・切り上げ・見かけ比重・数量の上書きと理由）・数量の換算（単位・係数・根拠）・RC 部材・鉄骨の部材・開口寸法（幅・高さ）・立上り・その他の加算 ほか。

## 方針

1. **3段の構成**にする。
   - 「基本」（いつも見える）: 名称（標準マスタの候補から選ぶ。候補に無いときだけ自由記入）、規格（候補から選ぶ。無いときだけ自由記入）、拾い方（個数・長さ・面積・体積の選択）、印の色・形（見本から選ぶ）。
   - 「この項目に必要な設定」（項目の種類で自動的に出し分ける）: 面積・長さの項目なら高さ・幅・深さの数値、開口がある壁なら開口寸法、RC 部材・鉄骨の項目なら部材の選択、連動している項目なら連動の内容（元の項目と計算の説明を文で表示し、変更は選択で）。関係しない区画は出さない。
   - 「詳しい設定」（折りたたみ。既定は閉じる）: 内訳書の位置（標準マスタから自動で入るので通常は触らない）、集計方式、略号、透明度、数量の換算、数量の上書き。
2. **自由記入を減らす**。
   - 削除: メモ（備考と重複）、新しい分類の名前（分類は候補から選ぶ。必要なら「その他」で1欄）。
   - 選択式へ: 摘要の区分名（候補から）、内訳書の種目・科目・中科目・細目（候補の選択を主にし、自由記入は「候補に無い」を選んだときだけ）、発生材の種類、施工条件、上書きの理由（「図面と現場の差」「特記による」「その他」＋その他のときだけ短文）、換算の根拠（同様）。
   - 残す自由記入: 名称・規格（候補に無いときだけ）、備考（特殊な仕様を採用する場合の1欄）、数値（高さ・幅・深さ・係数・上書きの数量など）。
3. **初めての人向けの文**: 各区画の見出しの下に1行の説明（例「連動: ほかの項目の数量から自動で計算します」）。専門用語には括弧で平易な言い換えを付ける。英語・内部の名前を出さない。
4. **保存データを壊さない**: 欄を画面から消しても、既に保存されている値は消さずに保持する（例: メモに値がある項目は「詳しい設定」に読取専用で表示し、空にできるボタンだけ出す）。保存形式は変えない。

## 試験

- 既存の FixtureDialog・項目の登録・連動・内訳書の位置の試験（vitest・e2e）がすべて通ること（ラベルが変わる箇所は試験側を合わせる）。
- 新しい e2e: 新しい項目を作るとき、初期表示で見える入力欄が「基本」の欄だけであること（`textarea` と文字の `input` の数を数える）。面積の項目では高さ等の数値欄が出て、個数の項目では出ないこと。メモに値がある旧データの項目を開いても値が消えないこと。

## 守ること

- 既存の機能（連動・RC・鉄骨・換算・上書き・内訳書）を削除しない。見せ方と入力の方法だけを変える。
- 既存の保存データ・出力（集計表・内訳書・Excel）を変えない。
