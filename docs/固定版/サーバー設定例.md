# 内部 Web サーバーの設定例

ZIP の中身を `/karu-pdf/` に展開する。以下は固定版専用の HTTPS origin を想定した例であり、管理者が実際の設定の継承・重複・MIME・ヘッダーを確認する。`file://` で開かない。試験用 `serve-fixed.mjs` は localhost の検証専用で、本番の TLS やアクセス制御を提供しない。

配布パスを変える場合は、ビルド前に `VITE_BASE_PATH=/別のパス/` を設定する。先頭と末尾の `/` が必要で、クエリ・フラグメント・二重スラッシュ・正規化で変わるパスは拒否する。配布後の文字列置換では変更しない。

## IIS: 配布ディレクトリの web.config

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <staticContent>
      <remove fileExtension=".wasm" />
      <mimeMap fileExtension=".wasm" mimeType="application/wasm" />
      <remove fileExtension=".webmanifest" />
      <mimeMap fileExtension=".webmanifest" mimeType="application/manifest+json" />
      <remove fileExtension=".ttf" />
      <mimeMap fileExtension=".ttf" mimeType="font/ttf" />
      <clientCache cacheControlMode="DisableCache" />
    </staticContent>
    <httpProtocol>
      <customHeaders>
        <remove name="Content-Security-Policy" />
        <add name="Content-Security-Policy" value="default-src 'self'; connect-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; manifest-src 'self'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'" />
        <remove name="X-Content-Type-Options" />
        <add name="X-Content-Type-Options" value="nosniff" />
        <remove name="Referrer-Policy" />
        <add name="Referrer-Policy" value="no-referrer" />
        <remove name="Permissions-Policy" />
        <add name="Permissions-Policy" value="camera=(), microphone=(), geolocation=()" />
      </customHeaders>
    </httpProtocol>
  </system.webServer>
</configuration>
```

`clientCache DisableCache` により静的ファイルへ `Cache-Control: no-cache` を付ける。上位設定やプロキシがヘッダーを置き換えていないことを確認する。静的コンテンツ機能と必要なセクションの委任を有効にし、同じヘッダーが二重に出る設定は取り除く。

## Apache: 配布ディレクトリの .htaccess

mod_headers、mod_mime と必要な AllowOverride を有効にする。

```apache
AddType application/wasm .wasm
AddType application/manifest+json .webmanifest
AddType font/ttf .ttf
Header always set Content-Security-Policy "default-src 'self'; connect-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; manifest-src 'self'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'"
Header always set X-Content-Type-Options "nosniff"
Header always set Referrer-Policy "no-referrer"
Header always set Permissions-Policy "camera=(), microphone=(), geolocation=()"
Header always set Cache-Control "no-cache"
```

## nginx: HTTPS server ブロック内

この例では ZIP を `/srv/www/karu-pdf/` に展開する。証明書とアクセス制御は管理者が別途設定する。配布パスの外は配信しない。

```nginx
root /srv/www;
location / { return 404; }
location /karu-pdf/ {
    index index.html;
    try_files $uri $uri/ =404;
    types {
        text/html html;
        text/javascript js;
        text/css css;
        application/wasm wasm;
        application/manifest+json webmanifest;
        font/ttf ttf;
        image/png png;
        application/json json;
    }
    default_type application/octet-stream;
    add_header Content-Security-Policy "default-src 'self'; connect-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; manifest-src 'self'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
    add_header Cache-Control "no-cache" always;
}
```

## 配布後の実測

ブラウザの Network または `curl -I` で、HTML と JS、WASM、フォント、`manifest.webmanifest`、`sw.js` の実際のレスポンスを確認する。WASM は `application/wasm`、マニフェストは `application/manifest+json`、JS と SW は JavaScript の MIME で返す。SW や WASM の 404 に HTML を返す SPA のフォールバック設定は使わない。

`sw.js` とマニフェストの `Cache-Control` は必ず `no-cache` にする。すべての実行ファイルに同じ CSP と追加の 3 ヘッダーを付ける。Worker のレスポンスにも CSP が必要である。SW のスコープを配布パスより広げる `Service-Worker-Allowed: /` は付けない。プロキシや IIS の設定で MIME やヘッダーが変更される可能性があるため、設定ファイルだけで完了と判断しない。

初回オンライン起動でキャッシュ完了を確認した後、通常の再起動とオフライン再読み込みで編集・保存を確認する。管理者は承認済み ZIP とハッシュ、VERSION と SBOM、実測したヘッダーを記録する。このリポジトリのテストサーバーでの結果は、IIS / Apache / nginx の本番設定を検証した結果ではない。
