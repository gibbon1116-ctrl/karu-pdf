# 固定・閉域版のセキュリティ設計

固定版は、管理者が承認した生成物を HTTPS の内部サーバーから配信する形を想定する。ブラウザ内で PDF を処理し、PDF 本体・ファイル名・検索語・書き込み・比較内容をサーバーへ送る機能を持たない。ソース監査、生成物監査、ブラウザの通信記録を組み合わせて検証する。PC 全体の通信を止める機能ではない。

## 防御と配布パス

アプリの取得先を同じ origin の配布パスに限定し、サーバーの CSP でも外部への取得を禁止する。`src/fixed/security.ts` でフォント URL の origin、正規化後のパス境界、クエリ、フラグメント、危険なエンコードを検査する。WASM、Worker、PWA のファイルは Vite が同じ配布パス内の URL に組み立てる。固定版を GitHub Pages で開いた場合は、App のモジュールを評価する前に起動を止めて案内を表示する。

通常版のファイル名・内容を維持するため、`vite.config.ts` の pre-transform で `@fixed` / `@pages` の領域を選ぶ。Worker のビルドにも同じ処理を適用する。通常版では元のソースだけをコンパイルする。新たなメタデータと CSP は固定版だけに入る。通常版の「版 1.0」の表示も維持する。

`connect-src 'self'` は、同梱のフォントと WASM を fetch で読むために必要である。`'none'` にするには約 15MB のフォントなどをプログラムへ埋め込む変更が必要になる。CSP の self は origin の境界であり、配布パスの境界まで保証する指示ではない。アプリの URL 検査・静的生成物の監査・内部サーバーの配信範囲を合わせて管理する。

サーバーで使う CSP:

```text
default-src 'self'; connect-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; manifest-src 'self'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'
```

WASM の実行に `wasm-unsafe-eval`、React の要素スタイルに `unsafe-inline` が必要になる。一般の JavaScript の eval は許可しない。meta CSP は補助で、meta では効かない `frame-ancestors` を省く。ヘッダーが主となる。CSP の値は `scripts/fixed-policy.mjs` を参照する。IIS / Apache / nginx の設定例は [サーバー設定例](サーバー設定例.md) に記載する。

## PWA と版の固定

PWA のインストールとオフライン利用を維持する。Service Worker は同じ内部サーバーの `sw.js` と同梱 Workbox を取得し、HTML・JS・CSS・WASM・フォント・アイコン・マニフェストを静的キャッシュへ入れる。外部 CDN、版確認 API、外部の更新 API は使わない。

`registerType: 'prompt'` を維持する。`autoUpdate`、常時の `skipWaiting`、`clientsClaim` を使わない。利用者が更新操作を選んだ場合だけ、既存の SKIP_WAITING メッセージで切り替える。管理者が内部サーバーの生成物を置き換えなければ、外部から新しい版へ変わることはない。ブラウザが行う SW の確認や precache の取得は、同じ内部サーバーへの GET であり、PDF のアップロードではない。`sw.js` と `.webmanifest` は `Cache-Control: no-cache` とし、毎回再確認できるようにする。

オフライン動作には、オンラインで初回の静的キャッシュが完了していることが必要である。キャッシュを消した PC の初回起動には内部サーバーへの接続が必要になる。PWA と File System Access API を使う本番環境は HTTPS を使う。試験用の localhost HTTP はブラウザの例外である。

## 保存と記憶

上書き保存は利用者が許可した File System Access API のファイルハンドルへ書く。別名保存のフォールバックはブラウザ内で作った Blob URL をダウンロードする。これらの処理では PDF を HTTP リクエストへ入れない。試験用の保存窓口も、メモリー上の PDF バイト列を返すだけである。

IndexedDB に保存するのはファイルハンドル、ファイル名、最近使ったファイルの情報であり、PDF の本体は入れない。ページ・倍率や書式などの設定は localStorage に記録する。ファイル名やハンドルは機密になり得るため、共有 PC のブラウザプロファイルも管理する。Service Worker のキャッシュに入るのはアプリの静的ファイルである。

## 監査・配布物

`audit:network` はソース、`audit:network -- --dist` は固定版の実行ファイルを調べる。許可はファイルパターン・一致する文字列・理由・最大出現数の組に限定する。ライセンス文、README、開発文書、試験コードの URL は実行先ではないため対象外である。許可したものは SVG/XML の名前空間、React のエラー説明 URL、Workbox の警告説明 URL、起動禁止ホストの比較、同梱ファイルの取得処理である。監査は文字列検査であり、実行時の完全な形式的保証ではない。

ZIP は Node 標準の deflate、CRC32、SHA-256 で生成し、中央ディレクトリから展開して全ファイルとハッシュを検証する。`SHA256SUMS.txt` は自己参照になるため自分自身のハッシュを含めず、それ以外をすべて含める。checksum ファイルを含む ZIP 全体は外側の `.zip.sha256` で確認する。これは通常の `sha256sum -c SHA256SUMS.txt` と互換の形式である。

SBOM は lockfile の全パッケージの固定された版・ライセンス・依存関係を記録する。dependencies の木と実際に同梱する Workbox の実行部品を required、開発だけの部品を excluded とする。`karu:bundled-runtime` が実際に同梱する部品を示す。フォントは元データの SHA-256 を固定版の識別子にする。第三者ライセンス集は、ビルド中に記録したバンドルの部品と生成された Workbox ランタイム、同梱フォントのライセンス文から作る。新しい依存は加えない。

## 残るリスク

ブラウザ拡張、ブラウザ自体の通信や脆弱性、OS・PC の管理、マルウェア、内部サーバーの設定や侵害、同一 origin に置かれた別のアプリ、PDF エンジンの未知の脆弱性はこの実装の保証範囲外である。CSP は同一 origin 全体を許可するため、固定版専用の origin を推奨する。HTTPS 証明書、アクセス制御、ネットワーク側の制限、脆弱性対応、承認と配布の管理も必要になる。ハッシュは一致の検査であり、承認者の署名ではない。ZIP とハッシュを同じ攻撃者が置き換えた場合の真正性は保証しない。既存キャッシュのある利用者は承認版への再読み込みを確認する。古い版へ戻す場合も同じ確認が必要になる。

## HTML ファイル1つの版

HTML 版はサーバーなしで Edge・Chrome の `file://` から起動する。CSS、画面プログラム、PDF・画像 Worker、MuPDF WASM、BIZ UD ゴシック・明朝、アイコンをすべて埋め込む。別のファイルを取得せず、Service Worker・PWA・更新の案内を登録しない。更新は HTML ファイルの差し替えのみである。通常版・内部サーバー版の出力には `@single` の領域を残さない。

```text
default-src 'none'; script-src 'sha256-<実行スクリプトのSHA-256をbase64化>' 'wasm-unsafe-eval'; worker-src blob:; connect-src 'none'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; object-src 'none'; base-uri 'none'; form-action 'none'
```

CSP は最初の資産・実行コードより前の meta に置く。組み立て時に最終的なインラインスクリプトの UTF-8 バイト列を SHA-256 で計算し、そのハッシュだけを許可する。配布物作成時にも実際の HTML から再計算して一致を検査する。`unsafe-inline` をスクリプトには使わず、JavaScript の eval、外部 URL、同じフォルダのファイルの fetch も許可しない。meta では `frame-ancestors` が効かないため含めない。file の HTML には HTTP レスポンスヘッダーはない。

WASM の base64 を起動時に1回だけ戻し、1回だけ `WebAssembly.compile` する。`Uint8Array.fromBase64` がなければ、確保済み配列に `charCodeAt` で書き込む。画面側でも MuPDF を参照する既存機能があるため、主スレッドではこの Module を非同期でインスタンス化する（8MB を超える同期インスタンス化のブラウザ制限を避ける）。各 Worker に同じ Module を構造化複製で渡す。

Worker は Rolldown で import・export のない ESM にまとめ、全体を async 関数で包む。最初のメッセージを受けて `$libmupdf_wasm_Module.instantiateWasm` を設定してから実行し、準備中の後続メッセージは順序を保って渡す。構文上の `import.meta.url` はビルド時に `self.location.href` へ変換し、従来形式の Blob Worker とする。Worker の CSP は生成元のページから継承する。フォントの応答は PDF の通常メッセージ処理へ渡さない。Blob URL は Worker の作成直後に解放する。

フォントは Worker が要求したとき、または入力欄・注釈・計測・プレビューが表示するときに初めて戻す。画面に1つずつキャッシュして各 Worker に複製し、表示には同じバイト列を `new FontFace` で登録する。起動時のフォント復号と、CSS への二重の埋め込みは行わない。未使用の MuPDF/Emscripten の取得分岐は依存ライブラリ内に残るが、Module の注入で実行せず、CSP でも遮断する。監査ではこれらの文字列と名前空間・例外メッセージ用 URL のみを回数制限付きで許可する。base64 の除外は決められた要素・属性・文字種の範囲に限定し、実行スクリプトと Worker は監査する。

IndexedDB に PDF 本体は保存しない。ファイルハンドルと名前、最近使ったファイルの情報は従来どおり保存する。`file://` では他のローカル HTML と保存場所を共有しうるため、同じブラウザで信頼できないローカル HTML を実行しない。ファイルハンドルの権限、ブラウザプロファイル、拡張機能、PC 管理と組織のポリシーは運用側で管理する。`file://`、Blob Worker、WASM が禁止された環境は対象外である。印刷は生成した PDF を Blob タブに表示し、表示できない環境では保存後に Edge で開いて印刷する。
