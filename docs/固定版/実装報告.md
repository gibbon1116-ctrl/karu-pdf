## CSP・ヘッダー

```text
default-src 'self'; connect-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; manifest-src 'self'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'
```

フォントと WASM の同一オリジン fetch のため connect-src self を使う。none にするには約 15MB のフォントなどを埋め込む必要がある。指定された CSP から実機で緩和した項目はない。HTML の meta は補助とし、meta で効かない frame-ancestors は入れない。Worker のレスポンスも同じヘッダーを付ける。

実際の応答で nosniff、no-referrer、Permissions-Policy の camera=(), microphone=(), geolocation=() を確認。WASM は application/wasm、マニフェストは application/manifest+json、SW は JavaScript の MIME。sw.js とマニフェストは Cache-Control: no-cache。試験サーバーでは全静的ファイルを no-cache にした。[サーバー設定例](サーバー設定例.md) に IIS、Apache、nginx の設定を記載した。

## 残るリスク

CSP の self は origin 全体を許可する。ブラウザ拡張、ブラウザ自体の通信・脆弱性、PC / OS の管理、同一 origin の別アプリ、内部サーバーの設定・侵害、PDF エンジンの未知の脆弱性は保証範囲外。専用 origin、HTTPS、アクセス制御、ネットワーク制限、承認と更新の運用が必要になる。ファイル名とハンドルがブラウザの記憶に残る点、ハッシュが署名ではない点も [セキュリティ設計](セキュリティ設計.md) に記載した。
