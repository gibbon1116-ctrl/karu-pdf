# 指摘入力の欄外クリック修正（2026-10-15）

指摘の内容を入力中にPDF上の入力欄外をクリックすると、そのクリックで内容を確定して入力欄を閉じる。指摘ツールの選択は保ち、もう一度クリックした位置に次の番号を置く。別ページをクリックした場合も同じ。

`IssueEditor` の document capture の `pointerdown` で、PDFの注釈レイヤーへのクリックに `preventDefault()` を設定する。`AnnotationLayer` の既存の `defaultPrevented` 判定により、同じイベントでの指摘作成を防ぐ。入力欄内と定型文・記号挿入は編集を継続し、ツールバーの操作では従来どおり入力を確定する。

## 確認

- `npm run build`：型検査と通常版ビルド成功。
- `npm test -- tests/issues.test.ts tests/cloudIssues.test.ts tests/cloudIssues.integration.test.ts tests/issueOverlay.test.ts`：48件成功。
- Chromiumの画面テスト：同一ページ・別ページの欄外クリック、次番号が2であること、入力欄内クリック、保存・再読込を追加して確認。
- 既存の画面テスト：指摘の連番・削除後の番号、Esc確定・再編集、文字・吹き出しの外側クリック、空文字の削除を確認。

画面テストの条件はLinux、Playwright Chromium、1440×900、生成した5ページの `sample-small.pdf`。Windows上のEdge・Chromeでの操作確認は未実施。

## 性能と復元

追加処理は指摘入力中の欄外クリックでのDOM祖先判定とイベントの既定動作の抑止。通常閲覧時の読込・描画処理や文字解析の経路は変更していない。通常操作の絶対ms・相対%の比較、大規模PDFの遅延・メモリ計測は今回未実施であり、性能の合否は判定していない。
