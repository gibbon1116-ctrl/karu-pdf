## 設計の要点

### タブと Worker（01a）

- 表示用の Worker は、開いているタブの文書だけを持つ。タブを切り替えたら、Worker 1 と 2 は文書を読み込み直す。MuPDF は開く処理が軽いので、100MB でも 0.1〜0.2 秒程度で済む。
- Worker 0 は、開いているすべての文書を持つ（書き込みの反映と保存を受け持つため）。
- メッセージに `docId` を付け、どの文書への要求かを区別する。
- 同時に開ける文書の数は、上限を 8 とする。

### 元に戻す／やり直し（01b）

- 書き込みは、保存するまで Worker の文書に反映しない（試作と同じ）。そのため、元に戻す操作は画面側のストアの中だけで行える。
- 保存した後に元に戻した場合も、ストアが「保存済みの状態との差」を `update` や `delete` として次の保存で送る。

### ページ整理（01c）

- 整理の画面では、縮小表示のカードを並べ替えるだけの「下書き」として操作する。
- 「適用」を押したときに、Worker 0 が次の順で処理する。
  1. 未反映の書き込みを反映する。
  2. ページの操作（`rearrangePages`、`deletePage`、`graftPage`、回転、白紙の挿入）を行う。
  3. 結果をバイト列にする。
  4. 表示用の Worker を、そのバイト列で開き直す。
- 適用の直前のバイト列を1つだけ手元に残し、「元に戻す（直前のページ整理）」ができるようにする。
- 分割と抽出は、保存先のフォルダを選んでもらい（`showDirectoryPicker`）、複数のファイルとして書き出す。

### ファイルが大きくなることへの対策（01d）

- 普段は増分保存にする。
- 開いてから増分保存が 5 回を超えるか、増えた量が 2MB を超えたら、次の保存を全体の書き直し（不要なオブジェクトの除去つき）にする。

## 試作から持ち越した課題

- 速いスクロールで、灰色の仮表示が 0.1〜0.2 秒出る（01a で、ページ一覧の縮小表示を先読みの下地として使い、改善する）。
- 描画の部分を PDFium に差し替える案は、利用者のPCで拡大が遅いと分かった場合にだけ検討する。
