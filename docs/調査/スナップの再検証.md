# SPEC-05f スナップの再検証

実測日: 2026-10-06〜2026-10-07（JST）。対象: quantity-pickup-expansion-ea43cf。

## 結論

**A（既存の頂点）だけを採用。B（図面の端点）・C（図面の線上）・D（交点）は不採用。** 抽出と索引作成の500ms基準を満たせず、Dは探索p95の1ms基準も満たさない。小さなPDFだけB/Cを使う限定採用は「迷うときは不採用」に従って行わない。

最終ソースと配布物から、図面用Device・線抽出・線分索引・交点計算・試作用Worker通信・5方式の試作切替を削除した。図面解析は通常読込でもスナップがオンでも実行しない。

## 測定条件

- Windows / Edge 154.0.0.0（msedge、headless）/ 1440×900 / hardwareConcurrency=12 / Worker=3。設定は変更せず、`npm run build` の dist を Vite preview で測定した。
- 実図面は `test-data/real/七ヶ浜町_実施設計図.pdf` の1階・2階・屋根に相当する冒頭3ページ。約5.8万〜11.7万本の線を含むページを使った。全30ページの本数順位から選んだ3枚ではない。A1は `test-data/heavy-300p.pdf` の6ページ目。
- 性能測定中はビルド・単体試験・別の画面試験を並行実行していない。
- Workerの `page.toDisplayList(false)` を独自Deviceで歩き、strokePathからページ座標の線分を抽出。注釈を除外。曲線は平坦度0.25pt・長さ8ptを目安に最大12段分割。Float32Arrayで x1,y1,x2,y2。200,000本で打切り。
- 8/16/32pt格子を比較。線分の外接矩形に交わる格子へIDを登録し、Uint32Arrayのoffsets/idsをWorkerで作成。格子100万・参照400万の上限。配列は画面側へ転送して探索。Dは近傍だけの線分組合せ。停止を避ける試作用5ms打切りを設けたが、これ自体が1ms条件を超える。
- 探索は各方式1,000回。B/C/Dは線分配列全体から均等に選んだ中点に0.3ptずらした位置、半径1.5pt（400%で8px）。Aは1,000個の模擬既存頂点。表示値0は約0.1msの時計分解能未満であり、処理時間ゼロではない。
- 面積操作は既存 measure.perf と同じ400%・円周20点・mouse.move(steps:3)・click・30ms間隔。requestAnimationFrameの全間隔からp95を求め、Enter後に20頂点の面積ができたことを確認。
- 5方式の比較では未採用方式を試すため、500msを超えた索引も作業用に使用。この例外は製品から削除済み。
- 3ページ目で解析待ちの間に対象ページが画面外へ移動した試行を除外し、その未成立の2条件とA1だけを再測定。解析後に対象ページへ再移動し、20点が載る表示範囲を確認した。不成立の操作数値は採用していない。
- フレーム操作は既存注釈を大量に追加しない既存 measure.perf 相当。Aの探索は別途1,000頂点で測定。実際の計測・数量拾いの頂点への吸着は画面試験で確認。

## 採否

|方式|採否|理由|
|---|---|---|
|A 既存頂点|採用|PDF解析不要。1,000頂点の探索p95は試作で0.1ms未満。全4枚の操作p95が20ms以下、オフとの差2ms以下。最終値は下記。|
|B 図面の端点|不採用|探索p95約0.1msだが、抽出+索引が500ms超（16pt案で4枚すべて）。|
|C 図面の線上|不採用|Bと同じ抽出費用が必要。探索が速くても500ms条件が不成立。|
|D 交点|不採用|共通の抽出費用に加え、実図面3枚の探索p95が2.7〜5.2ms。|

## 最終実装・変更ファイル

- `src/core/snap.ts`: 既存頂点だけの純粋な索引と探索。16pt格子、Float64Array座標、Uint32Arrayのoffsets/ids。最も近い頂点を採用。既存頂点との完全一致のためFloat64を使用。
- `src/editor/MeasurementOverlay.tsx`: オンで対象操作のときだけ表示中ページの既存注釈から索引を作り、注釈変更時に再作成。移動時は既存索引の探索だけ。描画フィルタで非表示の注釈・個数印は候補から除外。計測/拾い/多角形の頂点、線の両端、手書きの開始/終了点、四角/文字等の枠の頂点、吹き出しの先端を対象とする。曲線には数学的頂点がないため候補を作らない。
- `src/editor/AnnotationLayer.tsx`: 倍率と既存のstore更新番号を渡す。ページを離れたら印を消す。
- `src/App.tsx`: 入切の管理・対象道具の判定・Context・試験モードのみのA診断。localStorageの読書きはtry/catch。既定オフ。
- `src/app/ToolRow.tsx`: ズーム横のスナップボタン。対象操作でのみ押せる。
- `src/app/HelpDialog.tsx`: 採用範囲とAlt/Shiftの説明。
- `tests/snap.test.ts`: 距離境界、最も近い頂点、精度保持、格子境界、Shift、上限・過密時の打切り。
- `e2e/snap.annotate.spec.ts` / `e2e/snapFixtures.ts`: 決まった線を持つPDFをメモリ内で作成。既存頂点への吸着、オフ、Alt、Shift、拾いの頂点、縮尺のなぞり、状態保存、PDF線が候補でないことを検証。試験からwork等へファイルを保存しない。
- `e2e/snap.perf.spec.ts`: 最終Aとオフを1回ずつ測定。Aの1,000頂点索引の追加計測と、CDPで保持メモリ差を確認。最終確認では、オフ/オン両方に同じ1,000頂点の既存折れ線を置き、空でない索引で操作する。

半径は `8 / (zoom × 96/72)` pt。対象は距離・連続長さ・面積、長さ/面積/体積の拾い、縮尺のなぞり。個数印・普通の図形・選択時の頂点編集では働かない。Altで一時解除し、静止中にも印・プレビューを更新。四角1つのSVG pathをrefで更新し、移動ごとのReact state更新・Worker問い合わせ・PDF解析はない。

Shiftは先に水平/垂直/45度にそろえ、その直線上の頂点だけを使う。オフの既存計測の5度刻みは維持。索引はオフ時や対象外道具で捨て、文書を閉じるとページのrefも破棄される。

実用上限は1ページ200,000頂点、格子100万。近傍候補合計4,096点を超えたら吸い付かない（部分的な探索結果を採用しない）。保持配列の理論上限は約7.63MiB。すべての文書の性能を保証するものではない。

Worker側・PdfWorkerPoolは元の内容に戻した。保存形式・設定ファイル・public・scripts・その他docsは変更なし。Gitの変更操作なし。

|オフ|111|16.8|17.2|—|
|A|107|16.8|17.2|0.0|

Aの診断索引1,000頂点: 作成2.4ms、保持配列83,180B（0.079MiB）、探索p50は0.001ms未満、p95は0.001ms、最大0.008ms。時計分解能を考慮して100回の探索を1束として1,000束測定し、1探索相当に換算した値。単独の1,000回では0.1ms未満だった。

CDPでGC前後をそろえ、診断索引を強参照で保持した比較: backingStorageSize差+83,172B、JS heap差−11,736B。負のheap差は他のGC/測定ノイズを含むためゼロ使用量と解釈しない。配列の保持量はbyteLengthの83,180Bを採用する。文書全体やWorkerメモリの数値と混ぜていない。

改修前の既存 measure.perf はp95 17.1ms。改修後は16.8ms、差−0.3ms（−1.75%）、最大17.1ms。索引用の既存折れ線を追加しない最終snap試験でも、オフとAのp95は両方16.8ms。この差を高速化の証明とは扱わず、今回の測定ではオフ時のフレーム退行は観測されなかったとする。オフ時は頂点の収集・索引作成をしないことをコードでも確認した。通常読込/表示時間の追加の全体ベンチマークはしていない。

## SPECとの差・残課題

B/C/Dが不採用なので、図面端点の吸着試験、三角/交点印、Workerキャッシュ、未採用方式の単体・画面試験は製品に残さない。既存頂点と完全一致すること、PDFの線には吸い付かないことを検証する。採否によって試作を消す指示を優先。

試作のWorkerネイティブメモリのピークは未測定。Edgeのheadless測定であり利用者の実操作試用は未実施。B/Cは抽出のボトルネックを別の手法で改善した場合に再検証できるが、現行Device方式で採用範囲を広げない。

実測の元ログは作業用の work/spec05f-prototype-final.log、work/spec05f-prototype-remaining.log、work/spec05f-final-perf.log、work/spec05f-seeded-perf.log。試験自身が書いたファイルではなく、試験の外側のコマンドで標準出力を保存したもの。最終試験の実行にこれらのログやworkディレクトリは必要ない。
