# 営繕改修 試用版 1.1.0（2026-10-04）

営繕レビュー向けの改修を実装し、ローカル試用版を作成した。性能差の採否は利用者の操作確認を残す。2026-10-04の指示に従い、数十ms程度の差だけで工程を停止しない。この方針は今後の改修にも適用する。[復元と性能判定](../営繕改修_復元と性能判定.md) に保存済み。

## 試す方法と戻す方法

- `release/karu-pdf-v1.1.0-single.zip` を試用用の別フォルダーへ展開し、`karu-pdf-v1.1.0.html` をEdgeで直接開く。ブラウザだけで使える。ショートカット作成は試用後に行える。
- 配布用の固定版は `release/karu-pdf-fixed-v1.1.0.zip`。内部HTTPサーバーが必要。
- 既存の配布・公開サイトは差し替えていない。旧版と新しい試用版を並行して確認できる。保存するPDFも別名を使う。
- 導入前の固定タグは `karu-pdf-before-eizen-20261003`（`130166f6049938814c1f1b7db124790593444f5a`）。完全履歴の `work/rollback/karu-pdf-before-eizen.bundle` も検証済み。旧版を別フォルダーに復元する手順は上記文書を参照。アプリの復元と、保存したPDFの復元は別である。

## 実装した内容

| 内容 | 操作・範囲 |
|---|---|
| PDF読込の反応 | 読込直後から「PDFを開いています」。初表示で消し、失敗・中止で解除。根拠のない進捗率は表示しない |
| 図面内文字の抽出 | ファイル→図面内文字を抽出。現在ページ／範囲／全ページを明示実行しCSV/TXTへ。ページ、利用者指定の図面番号、位置mm、方向、抽出状況を含む。OCRなし |
| 既存文字の限定修正 | 文字選択→文字を修正。横書き1行全体に限定し、対象の本文文字を除去して日本語の本文文字を挿入する。修正したコピーを別タブへ開き、原文を保持。対象外は訂正注釈で記録 |
| 指摘管理 | 番号・位置・内容に分野、回答、修正確認、図面番号、IDを追加。未回答→回答済→修正済→確認済。旧版の対応済は確認待ちとして区別。詳細とCSVをPDF内に保存 |
| 個数カウント | 計測→個数カウント。種類を指定してクリック、種類・ページ別集計、CSV、Undo、削除、保存再読込。多数の丸印の描画をまとめる |
| 比較・重ね合わせ | 既存の差分・左右表示・同期拡大／移動に透過率と2組の基準点による平行移動／倍率／回転補正を追加。建築・電気・機械など任意の2PDFに使用可能 |
| ページ対応 | 旧新版のページと位置補正、利用者指定の図面番号を記録。JSONで書出し／再読込。通常読込では図面番号を自動解析しない |
| 前回指摘の引継ぎ | 比較中の現在の対応ページから未確認指摘を候補表示。位置補正を適用し、利用者が内容・対応・位置を確認したものを追加。範囲外・重複を除外し、元の指摘を保持 |
| 変更記録 | 文字→変更記録。内容・理由・位置・関連指摘ID・状態を入力し、PDFへ保存。関連指摘への移動と変更一覧CSV |

通常読込への全文字解析・全ページ差分・OCRは追加していない。抽出、比較、引継ぎ、本文修正は明示操作で開始する。指摘一覧は100行、引継ぎ候補は50行ずつ。文字抽出は上限付きキャッシュ、ページ単位処理、表示を優先する待機、中止・遅い応答の破棄を行う。MuPDFの同期呼出し自体は途中で中断できない。

## 見送った内容と制約

- 3画面表示、OCR、全ページの自動差分、自動図面番号認識、自動ページ対応・修正済判定は追加していない。既存の最大8タブと2画面を活用する。
- 本文修正は万能な編集ではない。回転ページ、Formを含むページ、複雑なクリッピング、位置・文字を安全に確認できない選択、他の行との重なり、範囲に収まらない修正文などは拒否する。フォントと文字色の完全な再現は行わず、BIZ UDゴシックの黒文字を使う。200文字まで。署名等の編集制限は維持する。
- 本文修正はコピー生成と全体保存を伴うため待ち時間がある。処理中表示を出す。日本語フォントを埋め込むため出力サイズは増えうる。原文のタブは変更しない。
- 引継ぎは手動で確認した現在のページ対応が対象。旧形式のIDなし指摘は文書名とオブジェクト番号で識別するため、旧PDFを別のソフトで書き換えた後の同一性までは保証しない。
- 図面文字の抽出結果はPDFの文字・構造に依存する。スキャンだけのPDFは対象外。文字変更の一覧化はCSVによる確認までで、自動意味比較は実装していない。

**発見した課題：** 最初の小型PDFの初表示に573.3ms（全操作試験）、635.6ms（5回試験）が観測された。全操作2回の初表示中央値は改修前203.2→改修後386.15ms（+182.95ms）である。5回試験の後続4回は184.8〜208.7ms、5回中央値は207.4msだった。内部の文書登録と描画Worker処理を確認したが、最初の表示が遅れる原因は確定していない。外れ値として除外しておらず、中央値だけで初回の性能維持を保証しない。利用者の初回操作確認を残す。

全操作の小型PDF保存は95.0→104.0ms（+9.0ms、+9.47%）。数十msの差は利用者の試用で判断する方針に従い、これだけを理由に試用版作成を止めていない。大容量PDFの未使用時ズーム・パン・入力・保存の値は上表のとおり。全項目を一括で「5%以内合格」とは判定していない。

抽出を開始した状態も同じ最終版で各1回測定した。300ページのパンは375.4→394.4ms（+19.0ms）、スクロール3000のp95は17.0→17.1ms、操作・保存後private bytesは+0.095%、GC後メインJS保持ヒープは+2.50%。小型のprivate bytesは操作・保存後+107,008,000bytes（+11.01%）だった。1回のみで有意な増加とは断定できず、文書終了後は+1.57%だった。

この抽出試験では小型5ページは完了したが、300ページは連続操作を優先して0/300ページで待機した後、保存で中止された。したがって大容量PDFの**解析実働中**の速度・メモリはこの試験で確認できていない。抽出開始・待機中の値と区別する。
