## 分かった制約

- 他のPDFから追加したページと、ページの抽出・分割で作るPDFには、書き込み（指摘・個数の印など）が付いてこない。MuPDF のページの取り込み（`graftPage`）が書き込みを写さないためで、以前から同じ。必要なら、書き込みも写す機能を別に作る。
- 外部への送信の見張りは、アプリ自身の通信の呼出しを対象にしている。通常版（GitHub Pages）では、画像・CSS・iframe からの読込、内部のURLからの外部への転送、Service Worker の中の通信は見張りの対象外（閉域版は CSP が止める）。アプリにはこれらで外部へ送る処理はない。
- 警告に出す通信の種類は「fetch」「XHR」などの技術的な名前のまま（管理者が確かめるときに役立つため）。

## 公開サイトへの反映

利用者の指示（「作成した版を https://gibbon1116-ctrl.github.io/karu-pdf/ にも反映させてください。外部への送信の警告機能も必ずつけてください」）で、改修ブランチを  へ fast-forward し、GitHub Actions の「GitHub Pages へ公開」で公開した（ = 。1.2.1 のソースに、試験の設定の変更2件を加えたもの）。

- 1回目（）は画面試験の段階で失敗し、公開されなかった（公開サイトは前の版のまま）。実行記録はリポジトリの管理者としてログインしないと読めないため、失敗した試験は特定できていない。同じ内容の2回目で全件が通ったので、GitHub の実行環境での時間の揺れとみている。以後、画面試験の失敗は注記（公開の API で読める）にも出す（ の  報告）。
- 2回目（）: 単体試験・ビルド・通常版の画面試験（183件成功・1件スキップ、5.4分）が通り、公開された。
- 公開サイトで、外部（example.com）への fetch が送られずに止まり、「外部への送信を止めました」（データは送信していません。fetch：example.com（1件））が出ること、ブラウザーの外へ出た通信が0件であることを確かめた（、）。
- 公開サイトは PWA なので、以前に開いたことのある端末では古い版が残っていることがある。「新しい版があります」の表示から切り替えるか、ページを再読み込みする。
