## 調べてわかったこと

### 保存後の未保存警告

次の流れを Edge で再現しようとしたが、どれも保存後は「未保存でない」になった（`e2e` の使い捨ての試験で確認）。

- 白紙2ページ: 長さの項目2つ、縮尺、経路、立上り・余長、条数、「この経路に足す」、範囲 → Ctrl+S
- 実図面（七ヶ浜町 30ページ）: 数量タブを開いて図面番号の読み取り中に項目を追加して Ctrl+S、読み取り後の再保存、図面番号の手動変更と「自動に戻す」、読み直し中の保存、ページ整理の後の保存、閉じて開き直し

その中で見つけた不具合と、警告が出たように見える原因の候補:

1. **入力欄の未確定の値が失われる**: 書式欄の「余長・その他」などに値を打って Enter を押さずに Ctrl+S を押すと、その値は保存されず、保存後に選択が外れて欄が消えるので、値はそのまま捨てられる（確認済み）。保存ボタンを押した場合は、押す前に欄からフォーカスが外れて値が確定する。
2. **別のタブの未保存**: アプリの終了（`beforeunload`）は、開いているすべての PDF のどれかが未保存なら警告する。どの PDF が未保存かは表示していない。
3. **比較が JSON の文字列**: 未保存の判定は、図面情報・縮尺・項目・注釈の状態を `JSON.stringify` で比べている。値が同じでもキーの順番が変わると「変更あり」になる（例: 余長を 1 → 0 → 1 と戻すと、`slackM` がいったん消えて末尾に付き直る）。
4. **保存後の後処理の失敗**: ファイルへの書き込みが終わった後の「最近使ったファイル」の記録などが失敗すると、保存済みの印が付かない。

### 選択の表示

保存済みの線・図形は PDF の画像の中に描かれ、数量拾い・指摘・編集中の書き込みは画像の上の SVG に描かれる。最前面の表示は、SVG の中の描く順番を変えることと、画像の中にある選択中の図形を SVG に重ねて描くことでできる（PDF の再描画は要らない）。

### 画面

右の書式欄は幅が約 210px で、経路の項目を縦に1つずつ積んでいる。左の数量タブは、操作のボタン・場所・検索・設定・7列の一覧を常に出している。

## 方針

- 新しい機能を使わない通常の閲覧に処理を足さない（AGENTS.md）。標準マスタ・Visual Search のコードは使うときだけ読み込む。
- 保存の形は欄を足すだけにし、`version` を変えない。古い PDF はそのまま読める。
- 経路の「よく使う構成」は、別の PDF でも使えるようにブラウザーに保存する（項目は略号・規格・名称で照合し、無ければその PDF に足す）。
