## 設計の要点

- **別の仕組みを作らない**: 項目は今の `CountFixture`（カタログの `KaruCountFixtures`）に `spec`・`aggregation` を足す。拾いは今の `CountMark`（`/KaruCount`）・`QuantityMark`（`/KaruQuantity`）に `floor`・`room`（と長さの `count`・`extra`）を足す。どれも欄を足すだけで `version` は変えず、古い PDF も、古い版のかるPDF も読める。
- **場所は拾いの側**、**集計方式は項目の側**（名前で判定しない。省略時は種別から: 個数→場所別、それ以外→全図面）。
- **集計の索引**（`QuantityIndex`）を1つ作り、数量タブ・内訳・CSV のすべてで使う。注釈・項目・縮尺が変わったときだけ作り直す。ページを削除すれば、その注釈が消えるので合計も減る。
- **図面情報はページの属性**: ページの辞書に付けるので、ページと一緒に動く。開くときは辞書のキーを見るだけで、文字は読まない（縮尺の `/VP` と同じ）。
- **性能**: 改修前のビルドを `bench-results/eizen/base-e1394e0-dist` に保存した。段階ごとに `scripts/eizen-bench.mjs` で比べる。
