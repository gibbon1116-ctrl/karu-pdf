## 3. 実図面での MuPDF 単体の測定（Node、AC 電源）

描画の条件は2つ。

- 「全体」: 幅 1408px に合わせてページ全体を描く
- 「400%」: 400% に拡大して、1536×1024px の範囲を描く

| 資料 | 下準備（DisplayList）平均／最大 | 全体 平均／最大 | 400% 平均／最大 |
|---|---|---|---|
| 標準仕様書（330 ページ） | 13／60ms | 26／67ms | 22／67ms |
| 設備標準図・電気（254 ページ） | 5／75ms | 13／178ms | 12／98ms |
| 設備標準図・機械（174 ページ） | 6／47ms | 15／66ms | 13／52ms |
| UR 詳細設計図集（149 ページ） | 25／325ms | 28／130ms | 28／142ms |
| **七ヶ浜町 実施設計図（30 ページ）** | **556／2227ms** | 217／639ms | **128／437ms** |

- 実物の図面では、400% の描画は最大でも 0.44 秒で、合格基準の 0.5 秒以内だった。
- 下準備は、重いページで最大 2.2 秒かかる。重いページを初めて表示するときは、2〜3 秒ほど灰色の仮表示が出る。
- 利用者のPCでは、最も重いページの 400% 表示が 0.5 秒を少し超える可能性がある。

## 4. MuPDF と PDFium（@embedpdf/pdfium 2.15.1）の比較

同じページを、同じ条件で描いた。単位は ms。

| ページ | 下準備 MuPDF／PDFium | 全体 MuPDF／PDFium | 400% MuPDF／PDFium |
|---|---|---|---|
| 七ヶ浜 p12（最も重い） | 2399／1362 | 865／585 | **431／64** |
| 七ヶ浜 p13 | 1089／847 | 721／834 | 280／40 |
| 七ヶ浜 p9 | 860／674 | 428／368 | 226／26 |
| 試験用 A1 | 481／217 | 1326／986 | 245／59 |

- **400% の描画は、PDFium が 5〜10 倍速い。** PDFium は、画面の外にある図形を素早く読み飛ばす。MuPDF にも同じ仕組み（`fz_run_display_list` の scissor 引数）はあるが、MuPDF.js の `DisplayList.run` はこの引数を公開していないため、毎回すべての図形を処理している。
- **PDFium は、埋め込まれていない日本語フォントを表示できなかった。** UR 詳細設計図集の p4（MS ゴシックを埋め込んでいない）では、日本語がすべて消えた。
  - MuPDF は、内蔵の代替フォントで正しく表示した。
  - PDFium で直すには、代替フォント（BIZ UD や Noto Sans JP）を渡す仕組みを別に作る必要がある。
- 細い線の見え方が違う。
  - PDFium は、細い線を1画素以上の太さで描く（Acrobat の「細い線を強調」や Edge の表示に近い）。
  - MuPDF は、細い線を細いまま、薄く描く。

比較の画像は、作業用フォルダ（scratchpad の `pdfium-cmp/png/`）で確認した。

## 5. 判断

- **中心部品は MuPDF のまま進める。**
  - 実図面では、合格基準を満たすか、ぎりぎりである。
  - 日本語の代替フォントがそのまま使える。
  - 1つのエンジンで作れるので単純である。
- 描画の部分（`src/core/render.ts` と Worker の `render`）は、後から PDFium に差し替えられる形にしておく。
- 利用者のPCで試して、拡大や重いページが遅いと感じた場合は、次のいずれかを検討する。
  - 表示だけを PDFium にする（日本語の代替フォントの対応が必須）
  - MuPDF の WASM を scissor 付きで自前ビルドする
